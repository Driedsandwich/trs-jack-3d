Apple M5 では低負荷モードに効果がありません。 画素数を 4 分の 1 にしても描画コストが変わらないためです。 つまりこの GPU では塗り面積が律速になっておらず、コマンド送出側で既に頭打ちになっています。

一方、ソフトウェアラスタでは 2〜2.9 倍速くなりました（倍率は CPU の混み具合で動きます）。 低負荷モードは「フィルレートが足りない環境で効く機能」であり、その環境では実際に効くことを確認しました。 高速な GPU で差が出ないのは、そもそも削る必要が無いからです。

測定はディスプレイ 60 Hz の環境です。120 Hz（ProMotion）環境では上限が 8.3 ms になりますが、

実コストが 0.1 ms 未満なので余裕は十分あると考えられます。ただし 120 Hz 環境では未測定です。

6-3. この検証で見つけて直した不具合

ピンチの 1 本目の指がプラグに乗ると、ズームがまったく効かなかった。

原因は、プラグのドラッグを開始したときに OrbitControls.enabled = false にしていたことです。 これだと OrbitControls が 1 本目の指を登録しないため、あとから 2 本目が触れても 「2 本指ジェスチャ」として認識されず、ピンチが成立しませんでした。 プラグの上でピンチしようとすると、ズームせずにプラグが動くという挙動になります。

修正: enabled ではなく enableRotate と enablePan だけを止めるようにしました。 OrbitControls は指を数え続けるので、2 本目が触れた瞬間にズームへ移れます。 あわせて、2 本目の指が触れたらプラグのドラッグは中止してカメラ操作に譲るようにしました。

修正前後で、上表の「プラグの上から始める 2 本指ピンチ」が FAIL → PASS に変わっています。 マウス操作側（デスクトップ 27 件）に退行がないことも再実行で確認済みです。
