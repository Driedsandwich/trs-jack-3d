# v0.6.1 — **schema は 1 本も上げていません。下流はどこでも止まりません**

## ⚠ 先に読むところ

### 1. **契約は変わっていません**

```
v0.6.0 の schema 22 本 → v0.6.1
  HOLD 22 / HOLD_RECORD 0 / **BUMP 0**
新設 0 本
```

**profile も感度も頑健性も `schemaVersion` はそのままです。**配布ファイル名も変わりません。
判定は条文（`docs/SCHEMA_VERSIONING_POLICY.md`）の判定器で実測しました
（対照: `required` を 1 つ外すと `BUMP` になるので、判定器は黙っていません）。

**`source-verification-result.v1` は据え置きです。**`ARCHIVE_INVALID` を enum へ足すと
言語が広がって v2 になり下流の lock が止まるので、**足していません**（→ 4 節）。

### 2. `profileId` が変わりました。**lock を作り直してください**

```
v0.6.0  trs-jack-3d:TRS|JACK-TRS:480daac80519
v0.6.1  trs-jack-3d:TRS|JACK-TRS:38b692a12af6

v0.6.0  trs-jack-3d:TRS|JACK-TRRS:b5b1e5ff2dba
v0.6.1  trs-jack-3d:TRS|JACK-TRRS:eaccc9119c92
```

**報告文から転記せず、同梱の `trs-jack-3d-release-index.v1.json` から引いてください。**

動いた理由は 2 つで、**どちらもモデルの数値とは無関係です。**

| 動いたもの | なぜ |
|---|---|
| `physicalVerificationRef` | 判定の条文が v1 → v2 になり、書き出す項目が増えた（→ 3 節） |
| 版数 | `package.json` が 0.6.0 → 0.6.1 |

**区間・event の数は変わっていません。**接点位置も走査結果も同じ値です。

### 3. **`verifiedPhysical` の判定に穴が 3 つありました**（条文 v1 → v2・値は `false` のまま）

外部監査（2026-08-06）が反例を出し、**こちらで再現してから**直しました。
**記録が 0 件のうちに直したので、`true` になった実績はまだ 1 件もありません。**

```
v1 で実際に起きていたこと（実測）

  [一致する記録, 矛盾する記録] → verified=true  rejected 0 件
  [矛盾する記録, 一致する記録] → verified=true  rejected 1 件
  分解能 1.0 mm / 生値 2.0×3    → 許容 0.29 mm の判定を通る
```

一致する記録を 1 件見つけた時点で止めていたため、**矛盾する記録が同じ台帳にあっても `true`** で、
しかも**並び順で出力が変わって**いました。

v2 で直したこと。

| | v2 |
|---|---|
| 相反する記録 | 全候補を評価し `recordId` で並べ直す。一致と矛盾が併存したら `AMBIGUOUS`（= `false`） |
| 分解能 | 観測点ごとに要求分解能を**許容の 1/3** から導く（`L` は 0.05 mm 以下）。生値が目盛に乗っているかも見る |
| 主張の範囲 | `claimScope: geometry-only` を出す（→ 下） |
| 台帳の重複 | `recordId` が重複したら判定ごと拒む（`INVALID_LEDGER`） |

**`physicalVerificationRef` の中身が増えています。**型は `string` のままです。

```
v0.6.0  …@sha256:… gate=…@v1 records=0 required=… satisfied=- missing=… rejected=0
v0.6.1  …@sha256:… gate=…@v2 scope=geometry-only verdict=UNVERIFIED records=0
        required=… satisfied=- missing=… ambiguous=- conflicting=0 notCertified=0
        retracted=0 dupIds=0 decidedBy=- rejected=0
```

**`scope=geometry-only` を読んでください。**`verifiedPhysical: true` が言うのは
「条文が名指しした**幾何量**が、モデルの予測と許容の内側で合った」までです。

```
言わないこと
  target-topology  どの端子がどの導体と繋がるか・GND が開放か・短絡が無いか
  acoustic         音がどうなるか
  lot-variation    別個体・別ロットでも同じか
```

`TRS|JACK-TRRS` の必須観測点は 1 点だけで、しかも**別 variant（`TRRS-CTIA|JACK-TRRS`）の量**です。
これが合っても `IV028`（左右が別導体・共通帰線だけ開放）は**確かめたことになりません。**

### 4. **検算ツールが `toolVersion` 6 になりました**

v5（v0.6.0）で塞いだつもりだった穴が 3 つ残っていました。**同じ外部監査の指摘です。**

```
v5 で実際に起きていたこと（実測）

  root/dup.txt を 2 回  → エラーなし・dup.txt = "SECOND"（後の中身が黙って勝つ）
  loop -> . が 1 本     → exit 1 / stdout 0 行 / stderr に ELOOP のスタック
  120 MB の入力         → 最大 RSS 165.0 MB（1 MB のときは 45.0 MB）
```

| 直したこと | v6 |
|---|---|
| 同名 entry | `ARCHIVE_INVALID` で止める。**中身が同一でも拒む** |
| symlink | `lstat` で見て追わない。fs エラーは構造化 status へ（**JSON が出る**） |
| 圧縮入力の上限 | `maxCompressedBytes` 64 MB。**最大 RSS 165.0 MB → 43.6 MB** |

**`status` の種類は増えていません。**`ARCHIVE_INVALID` は v5 のままです。

> **`ARCHIVE_INVALID` は、同梱の `source-verification-result.v1` では表現できません。**
> これは v0.6.0 からの既知の欠けで、**v0.6.1 でも直していません**——
> enum へ足すと言語が広がって v2 になり、下流の lock が止まるためです（判定器で実測）。
>
> 代わりに 3 つ入れました。
>
> 1. schema 自身が「この v1 では表現できない」と名指しで書く
> 2. こちらの生成器が、表現できない status を**近い値へ丸めずに止まる**
> 3. ずれが `ARCHIVE_INVALID` 1 個だけであることをテストで固定（7 個目が増えたら落ちる）
>
> **受け手が道具を直接回したときの stdout は、この schema の対象ではありません。**
> `ARCHIVE_INVALID` はそのまま出ます（`exitCode` 2）。`status` を allowlist で持っている場合は、
> **`SOURCE_UNAVAILABLE` とも `MISMATCH` とも別のもの**として足してください。

### こちらで見つけた 3 件

- `check:doc-numbers` が**公開済みの release notes を作業ツリーの artifact と照合していた**。
  release 後に profile を作り直すと ID が変わるので、この検査は**公開済み文書を書き換えろと言い続けます。**
  公開本文は編集しない方針なので、手元の控えを凍結しました。
  **凍結できるのは tag が実在する release notes だけ**です。
- **CHANGELOG に v0.6.0 の節がありませんでした。**公開したのに記録が無い状態でした。
- テストが 1 件、**負荷時にだけ** 30 秒を超えて落ちていました（6 回中 2 回）。
  単独では 2.4〜5.6 秒で、修正前とも同じ範囲です。判定条件は変えず時間枠だけ 120 秒にしました。

### `supersedes` を入れなかった

新しい記録が古い記録を**黙って上書きできる仕組み**を作らないためです。
矛盾したときの決着は 2 つだけで、どちらも書いた人の判断が残ります。

1. **モデルのほうが間違っている** → モデルを直す
2. **その記録が間違っていた** → `retracted: true` と理由を付ける（**記録は消さない**）

`retracted` は既に台帳 schema にあるので、`measurement-record.v1` の版も上がりません。

- **実測が 1 件も来ていません。**ジャック内部の接点位置は全部仮定のままです。

  profile への `evidenceSources` 出力。**どちらも「最初の実測記録が入る前に」という条件つきで、

  **実際に自己申告が必要になった日に判断します。**

  **すべての細工に耐えることは示していません**——現に v5 で 3 つ見落としていました。
