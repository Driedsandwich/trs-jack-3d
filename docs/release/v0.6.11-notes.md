# v0.6.11 — **schema を 1 本足しました（22 → 23）。既存の 22 本は 1 行も動いていません**

## ⚠ 先に読むところ

### 1. **`OK` の意味を狭めました。古い tag では `OK` が出なくなります**

**受け手に直接影響するのはこちらです。**

v0.6.10 まで、`status` は**不一致が無いこと**しか見ていませんでした。
そのため、**記録漏れの探索をしていなくても `OK`** になりました。
受け手には「探して見つからなかった」と読めます。**やらなかったことは、合格ではありません。**

```
できていない工程がある  → VERIFICATION_INCOMPLETE（exit 1）
```

**v0.3.0 より前の tag を検算すると、これに当たります。**その tag には範囲定義が無く、
manifest も範囲を記録していないので、記録漏れの探索ができません。
**sha256 の突き合わせは今までどおり実施していて、そちらの結果は有効です。**

`OK` を期待している自動処理があれば、**そこは直す必要があります。**

### 2. **範囲定義が manifest に縛られていませんでした**

`--scope` を**中身も確かめずに**受け取っていました。

```
--scope /nonexistent/s.json     status OK / exit 0（探索していないのに）
src/model を除いた scope        status OK / 未記録候補 0 件
```

manifest は `inputScope.sha256` を持っているのに照合していませんでした。
**範囲を差し替えられるなら、「範囲の中に記録漏れは無い」は何も言っていません。**

### 3. **名前が空の member と、切れている archive を受理していました**

```
名前が空（生ヘッダ / GNU L）  検算 v15 OK 32/32 ／ bsdtar は skip・python は落ちる
本体の詰め物が欠けている      検算 v15 OK 32/32 ／ 2 実装とも `Truncated` で拒む
終端の印を見ないまま尽きる    検算 v15 READ    ／ bsdtar だけが拒む
directory 内の FIFO           検算 v15 OK / 候補 0 件（名前が一度も出てこない）
```

**下 2 つはこちらで見つけました。**

### **お願い: v0.6.10 以前で出た `OK` は取り直してください**

**`v0.6.11` 同梱の `verifyReleaseSourceInputs.mjs`（`toolVersion` 16）で取り直してください。**

### 4. **受け手向けの契約を新設しました**

`source-verifier-cli-result.v1.schema.json` を同梱しました（**asset 28 → 29 件**）。

v0.6.10 まで、受け手はこの出力を読むのに
`source-verification-result.v1`（**こちらが回した記録**）の説明を使うしかありませんでした。
その 2 つは**出る status が違います**——記録側は作業ツリーを読む経路なので
`ARCHIVE_INVALID` も `ARCHIVE_UNSUPPORTED` も `VERIFICATION_INCOMPLETE` も出ません。

status 8 種類・`stableReasonCode`・`archivePolicy`・`incompletePhases`・
`rootTransform` を含みます。**`archivePolicy` は「この道具が何を通すか」**
（受け入れる形式・typeflag の許可表・終端の約束・上限）で、受け手が機械で読めます。

**既存の schema 22 本は 1 行も動いていません**（判定器の記録も `BUMP 0`）。
**下流はどこでも止まりません。**

### 5. `profileId` が変わりました。**lock を作り直してください**

```
v0.6.10  trs-jack-3d:TRS|JACK-TRS:e3a230f2c600
v0.6.11  trs-jack-3d:TRS|JACK-TRS:54261c562e54

v0.6.10  trs-jack-3d:TRS|JACK-TRRS:8d64e23c190d
v0.6.11  trs-jack-3d:TRS|JACK-TRRS:f1daad3f053c
```

**この文書から転記せず、同梱の `trs-jack-3d-release-index.v1.json` から引いてください。**

**動いた原因は版数上げ（`package-lock.json`）です。**検算ツールは配布物ですが
**入力ではない**ので、v15 → v16 にしても digest を動かしません。

**モデルの数値は変わっていません。**葉ノードまで平坦化した実測です。

```
TRS   葉 2267 件 → 由来まわりの差 8 件 / モデル数値の差 0 件
TRRS  葉 3130 件 → 由来まわりの差 8 件 / モデル数値の差 0 件
```

`jack.fullInsertionDepth` を 14.0 → 14.001 に変えると
**モデル数値の差が TRS 80 件**になります。

## 止める理由が、どちらの実装で裏を取れるか

```
GNU tar 側でだけ根拠が取れる   15 件
bsdtar 側でだけ根拠が取れる    10 件
どちらでも取れていない          5 件
```

**残る 5 件のうち 3 件は、実装が割れているのではなく方針で止めています**
（見え方を変える鍵・通常ファイルの重複）。そう書き分けてあります。

> この版では**CI の ubuntu 側に 3 回落とされました。**
> 切れ方の根拠が platform で割れること、権限の無いディレクトリで木を歩けず
> 落ちていたこと、そして**測れていなかったものを「根拠が取れない」と書いていた**ことです。
> **道具が落ちているときと、根拠が無いときは、出力が同じに見えます。**

## 変わっていないもの

- **モデルの数値**。接点位置も走査結果も同じです。
- **`verifiedPhysical` は `false`**。実測記録は依然 **0 件**です。
- 過去 release の asset。**v0.1.0 以降の 489 件すべて byte 一致**であることを、
  再生成の段ごとに対照つきで実測しています。

## まだやっていないこと

- **実測が 1 件も来ていません。**ジャック内部の接点位置は全部仮定のままです。

- annotated tag への署名。
- 検算ツールの強化は **試験した範囲まで**です。**すべての細工に耐えることは示していません**

  v12 で 2 つ、v13 で 3 つ、v14 で 2 つ、v15 で 3 つ見落とし、
