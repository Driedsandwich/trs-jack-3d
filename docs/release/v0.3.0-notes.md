> # ⚠ 破壊的変更です
>
> **`topology-robustness` の `schemaVersion` を 1 → 2 に上げました。**
> 窓の端点を読んでいる実装はそのままでは動きません。
>
> | 旧（v1） | 新（v2） |
> |---|---|
> | `fromMm` | **`startMm`** |
> | `toMm` | **`lastSampleMm`** |
> | （無し） | **`endExclusiveMm`** |
>
> **旧 `toMm` は「最後に当たった標本の位置」で、区間の終端ではありませんでした。**
> profile の `nominalEndMm`（13.52 mm）と 1 刻みずれて見えます。
> **同じ「終わり」という語で、2 つの違う量を指していました。**
>
> `profile` の `schemaVersion` は **2 のまま**で、v0.2.0 から変わっていません。
> 対応表は `topology-robustness` の `contractMigration` にあります。
>
> **v0.1.0 / v0.1.1 / v0.2.0 の asset は上書きしていません**（byte 一致を確認済み）。

## 版数について

**v0.2.1 ではなく v0.3.0 にしました。**パッチ番号だと変更の重さを実際より小さく見せます。
この一連の作業で扱ってきたのが「版を据え置いたまま非互換にすると下流が沈黙して壊れる」
という問題そのものなので、番号でも同じ姿勢を通しました。

v0.2.1 として staging した記録は `docs/release/v0.2.1-SHA256SUMS.txt` に、
未使用である理由とともに残してあります（消すと何をなぜ変えたか分からなくなるため）。

## 追加したもの

### `trs-jack-3d-release-index.v1.json`

**報告文から値を手で転記しなくて済むようにするための索引です。**
v0.2.0 では下流が lock を手入力で作っており、転記ミスの余地がありました。

| 項目 | 意味 |
|---|---|
| `releaseTag` / `releaseCommit` | tag と、それが指す commit |
| `evidenceBuiltAtCommit` | 索引を作った時点の HEAD |
| `artifactGenerationCommit` | **profile の**生成 commit。`releaseCommit` とは違う |
| `artifactGenerationCommits[]` | **生成 commit は 1 つではない。**この版では 3 種 |
| `profiles[variantId]` | `filename` / `profileId` / `inputDigest` / `sha256` / `generatedFromCommit` / `sensitivityAsset` |
| `assets[]` | 配布物と sha256。**索引自身は含みません**（自己参照になるため） |

> **`generatedFromCommit` と `releaseCommit` の一致を要求しないでください。**
> artifact をコミットしてから tag を打つので、artifact は必ず tag より前の commit から作られます。
> release 工程が 2 段階（感度を確定 → profile を生成）なので、生成 commit も 1 つになりません。

### evidence 3 種の schema

`validation-results` / `source-input-manifest` / `release index` に Draft-07 schema を付け、
配布物へ入れました。**形の検証が bundle だけで閉じます。**

### 検証対象の配布区分

`validation-results.json` の各対象へ `distribution` を付けました。

```
RELEASE_ASSET   bundle に入っている（7 件）
SOURCE_ONLY     入っていない（2 件）
```

**9 対象すべてを bundle だけで独立再検証できるわけではありません。**
`topology_search_difference_signal.json` と `real_jack_comparison.json` は runtime 入力ではないため配布していません。

### `npm run verify:release-source-inputs`

**こちらの自己申告を信じずに確かめるための道具です。**
`source-input-manifest.json` の記録を tag の source と突き合わせ、sha256 を計算し直します。

```
--source <dir>   展開済みの source        （通信しない）
--tag <tag>      手元の git object から    （通信しない）
--fetch github   **明示したときだけ**取りに行く
```

**「取れなかった」と「合わなかった」を潰しません。**

| status | exit |
|---|---:|
| `OK` | 0 |
| `MISMATCH` | 1 |
| `SOURCE_UNAVAILABLE` | 2 |
| `MANIFEST_UNAVAILABLE` | 2 |
| `NOTHING_TO_VERIFY` | 2 |

入力 0 件を `NOTHING_TO_VERIFY` にしたのは、**0 件でも「全件一致」が真になる**ためです。

**read-only です。**書き込み API を 1 つも使わず、tar は展開せずメモリ上で読みます。

> v0.2.0 tag に対して実行し、**28/28 一致**しました（手元の git 経由と GitHub tarball 経由の両方）。
