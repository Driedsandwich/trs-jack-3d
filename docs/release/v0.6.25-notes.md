# v0.6.25 — **BusyBox を初めて走らせたら、受理している 3 形を BusyBox だけが拒みました**

## ⚠ 先に読むところ

### 1. **BusyBox を、引用ではなく実測にしました**

v0.6.24 までの試験は「GNU tar 1.35 / **BusyBox 1.37** の実測にもとづく」と書いていましたが、
BusyBox の側は**外部監査の報告の引用**でした。開発機にも CI にも BusyBox が無く、
こちらでは一度も走らせていなかったからです。

この版から、**CI の ubuntu run が BusyBox を入れ、tar 展開 oracle の 3 つ目として照合に混ぜます。**

```
ubuntu   BusyBox v1.36.1（Ubuntu の apt）        照合: 実走 / スキップ 0 件
macOS    入れていない（Homebrew に formula が無い）  照合: スキップ / 76 件
```

**必須にはしていません。**受け手の環境に BusyBox を要求する筋合いが無いからです。
無い run は照合をスキップし、**スキップした件数を出します**（黙って緑にはなりません）。
在る run では、**木が割れたら止めます**——表示するだけにすると門になりません。

### 2. **受理している 3 形を、BusyBox だけが拒みました**

最初の run で、検算器が受理し、tar と python が**同じ木を作る**材料のうち
**3 個を BusyBox が拒みました**（exit 1）。

```
raw-cksum-signed                 tar: invalid tar header checksum
format-v7-no-prefix              tar: invalid tar magic
format-unknown-magic-no-prefix   tar: invalid tar magic
```

3 個とも、過去の外部監査で**受理すると決めた形**です。
signed checksum は v0.6.8 の P1-C で「bsdtar も python も展開する＝過剰拒否」として受理へ直し、
V7 と未知 magic は v0.6.9 の P0-A で「形式そのものは拒まない」と決めて通す側の対照に置きました。

**違う木を作った材料は 0 個でした。**

**検算器は変えていません。**試験の側で「拒む」と「違う木を作る」を分けました。

| BusyBox が | 扱い |
|---|---|
| 違う木を作る | **止める** |
| 展開を拒む・表に無い | **止める** |
| 展開を拒む・表（`BUSYBOX_REFUSES`）に載っていて理由の文も合う | 通す（3 件） |
| 表に載っているのに展開した | **止める**（表が古い） |

件数 3 も試験で固定しました。増えたら気づきます。

> **受け手への意味。**BusyBox で展開する受け手は、この 3 形の archive を展開できません
> （exit 1 とエラーが出ます。黙って違う木ができるわけではありません）。
> v0.6.24 の tag の source archive（GitHub が作る物・ヘッダ 431 件）は、
> **3 形のどれも含んでいません**（全件が POSIX ustar・unsigned の checksum。2026-10-18 実測）。

**受理の範囲を BusyBox に合わせて狭める道は採りませんでした。**
それは検算器の判定を変え、過去 2 回の外部監査の結論を戻すことになります。
採るなら版を上げ、別の版で扱います。

### 3. **nanoid の更新を、この版で閉じました**

v0.6.24 の後（2026-09-14）に `nanoid` を **3.3.16 → 3.3.19** へ上げました
（dev のみの推移依存・[GHSA-2v37-7h3g-55p8](https://github.com/advisories/GHSA-2v37-7h3g-55p8)）。

`package-lock.json` は**記録された入力**なので、上げた時点で記録と食い違い、
source-input 検算系の **7 ファイル 20 件**が落ちていました。
lockfile の中身だけを戻すと同じ 164 件が全部通ることを、対照として測ってあります。

この版の staging で、記録を使う 5 件を作り直し、記録を取り直しました。

```
作り直した artifact   感度 2・頑健性 1・profile 2
葉の増減              0 件
変わった葉            由来だけ（生成元 commit・入力の指紋・lockfile の sha256・日付）
モデル数値            0 件が変化
```

**出荷物は 1 バイトも変わっていません。**ビューアの build を nanoid 3.3.16 と 3.3.19 で作り直し、
7 ファイルとも sha256 が一致しました（2026-10-09 に測り直し）。

## 版数を上げていない根拠（すべて実測）

**`toolVersion` 20 / CLI 結果契約 `schemaVersion` 2 / profile `schemaVersion` 3のままです。**

```
配る検算ツール          v0.6.24 と **byte 一致**（scripts/verifyReleaseSourceInputs.mjs）
配る asset の一覧        scripts/releaseAssets.mjs が v0.6.24 と同じ
schema                 26件とも v0.6.24 と同じ
CLI 出力の 10 経路    基準と byte 一致
profile のモデル数値     **0 件が変化**
```

この版で変わったのは、**依存の lockfile・試験・CI・文書**です。検算器の判定は変わっていません。

## まだやっていないこと

- **実測が 1 件も来ていません。**接点位置は全部仮定のままで、
  導通測定も音響測定もしていません（`verifiedPhysical` は `false`）。
- **annotated tag への署名**（v0.6.25 も**署名なし**です）。
- **`main` の branch protection / ruleset**。リポジトリ設定の変更なので手を付けていません。
- **Half-Plug 下流の `release-lock v7` / `mechanism-binding v7`**（別 repo）。
- **残り 3 件の advisory**（`@vitest/mocker` / `fast-uri` / `vitest`・いずれも dev のみ）の切り分け。
- **BusyBox で根拠が取れる拒否を `EVIDENCE_ELSEWHERE` へ入れること。**
  `on` は `bsdtar` / `gnu-tar` / `none` の 3 値のままです（BusyBox が走った run の出力はこの版で初めて取れました）。
- **macOS の run で BusyBox を走らせること**（Homebrew に formula がありません）。
