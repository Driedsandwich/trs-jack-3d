# v0.6.10 — **schema は 1 本も上げていません。下流はどこでも止まりません**

## ⚠ 先に読むところ

### 1. **v0.6.9 は、長さ 0 の PAX 鍵で鍵の検査を丸ごと飛ばせました**

**受け手に直接影響するのはこちらです。そして、これは v0.6.9 でこちらが開けた穴です。**

v0.6.9 で「長さ 0 の値を早く返す」ようにしたとき、
`path`/`linkpath` と数値鍵しか記録しなくなりました。ところが
**そのあとの allowlist と known-dangerous 検査は、記録された鍵しか見ません。**
つまり**値を空にするだけで、その 2 つを飛ばせました。**

```
同じ鍵で、値の長さだけを変える
  size=12            ARCHIVE_INVALID   ／ size=（長さ 0）      READ  ← 素通り
  SUN.holesdata=X    ARCHIVE_INVALID   ／ SUN.holesdata=      READ  ← 素通り
  ACME.weird=X       ARCHIVE_UNSUPPORTED ／ ACME.weird=        READ  ← 素通り
```

`SUN.holesdata=` は **bsdtar が exit 1 で拒む**のに受理していました。
32 入力の source に混ぜると **`status OK / 32 of 32`** になります。

### 2. **終端 zero block のあとを、一度も見ていませんでした**

```
32 入力の source + zero block 1 個 + root/src/model/sneaky.ts
  検算 v14  status OK ／ 32 of 32 ／ 未記録候補 0 件
  GNU tar   tar: A lone zero block at 3 と警告する
```

zero block を 1 個置いた後ろに member を隠せました。
**GNU tar はこの形をちょうど名指しで警告します。**

### **お願い: v0.6.9 以前で出た `OK` は、この 2 つを見ていません**

**そちらが v0.6.9 以前の道具で別の archive を検算していた場合、
`OK` が出ていても「長さ 0 の鍵が混じっていないこと」も
「終端のあとに中身が続いていないこと」も確かめていません。**
`v0.6.10` の道具（`toolVersion` 15）で取り直してください。

### 3. **こちらの過剰拒否が 6 版続けてです**

```
正当な old GNU sparse   typeflag S・345..499 は sparse map。2 実装とも読めるのに
                        「壊れている」と言っていた（型より先に形式を見ていた）
mtime=1.                小数点のあとに数字が無い形。2 実装とも受理するのに拒んでいた
冪等な directory の重複  同じ root/dir/ を 2 回。2 実装とも同じ木を作るのに拒んでいた
```

sparse は「壊れている」ではなく「**こちらが扱わない**」ので `ARCHIVE_UNSUPPORTED` です。

### 4. 止めた理由すべてに、変わらない名前が付きました

止め方 **65 か所すべて**に `stableReasonCode` を付け、
**corpus の材料が `*_OTHER` を返したら試験が落ちる**ようにしました
（止まる材料 105 件・`*_OTHER` は 0 件）。受け手が機械で分岐できます。

### 5. **こちらが「根拠が無い」と書いて、それも間違えました**

止める理由のうち根拠が取れないものを一度 **8 件**と書いたのですが、
**CI の ubuntu 側が落として、3 件は GNU tar が警告を出していると分かりました。**

```
eoa-lone-zero-then-member   tar: A lone zero block at 3
zero-hdrcharset             tar: Ignoring unknown extended header keyword 'hdrcharset'
```

**開発機の 2 実装だけを見て「根拠が無い」と書くと、根拠を過小に報告します。**
過大に報告するのと同じくらい、受け手の判断を誤らせます。

```
GNU tar 側でだけ根拠が取れる   15 件（v0.6.9 は 11 件）
bsdtar 側でだけ根拠が取れる     9 件
どちらでも取れていない          5 件（v0.6.9 は 2 件）
```

残る 5 件のうち 3 件は**実装が割れているのではなく、方針で止めている**ものです
（見え方を変える鍵・通常ファイルの重複）。そう書き分けました。

### 6. `profileId` が変わりました。**lock を作り直してください**

```
v0.6.9   trs-jack-3d:TRS|JACK-TRS:6209fa3bd888
v0.6.10  trs-jack-3d:TRS|JACK-TRS:e3a230f2c600

v0.6.9   trs-jack-3d:TRS|JACK-TRRS:76904bf4730a
v0.6.10  trs-jack-3d:TRS|JACK-TRRS:8d64e23c190d
```

**この文書から転記せず、同梱の `trs-jack-3d-release-index.v1.json` から引いてください。**

**動いた原因は版数上げ（`package-lock.json`）です。**検算ツールは配布物ですが
**入力ではない**ので、v14 → v15 にしても digest を動かしません。

**モデルの数値は変わっていません。**葉ノードまで平坦化した実測です。

```
TRS   葉 2267 件 → 由来まわりの差 8 件 / モデル数値の差 0 件
TRRS  葉 3130 件 → 由来まわりの差 8 件 / モデル数値の差 0 件
```

`jack.fullInsertionDepth` を 14.0 → 14.001 に変えると
**モデル数値の差が TRS 80 件**になります。
