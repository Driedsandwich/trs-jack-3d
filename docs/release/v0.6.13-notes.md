# v0.6.13 — **検算ツールが「無言で合格に見える」状態を塞ぎました**

## ⚠ 先に読むところ

### **v0.6.12 までの道具は、別名で走らせると何も出さずに `exit 0` で終わります**

入口の判定が**ファイル名の正規表現**（`/verifyReleaseSourceInputs\.mjs$/`）でした。
受け手がコピーの名前を変えたり symlink を張ったりすると、**検算せずに終了コード 0** を返します。

```
実測（2026-08-12・v0.6.12 の道具）
  verifyReleaseSourceInputs.mjs   exit 0 / 出力 4,318 バイト
  renamed.mjs                     exit 0 / 出力     0 バイト   ← 無言
  link.mjs（symlink）             exit 0 / 出力     0 バイト   ← 無言
```

**終了コードだけを見る受け手には、合格と区別が付きません。**
`if verify.mjs ...; then echo OK; fi` のような書き方をしていると、**検算していないのに OK になります。**

**同梱の手順どおり（名前を変えずに）回していれば起きません。**
黙る経路は JSON を 1 バイトも出さないので、**出力を読んでいたなら気づけています。**

v0.6.13 は、名前ではなく「**起動された本体か**」で判定します。

```
v0.6.13 の道具
  verifyReleaseSourceInputs.mjs   出力 4,318 バイト
  renamed.mjs                     出力 4,318 バイト
  link.mjs（symlink）             出力 4,318 バイト
```

### **`toolVersion` は 16 のままです**

判定は 1 バイトも変わっていません。**正規の名前での出力は v0.6.12 と byte 一致**です
（対照: 引数を変えると 83 行差）。

同梱 schema は `toolVersion` を「**判定の意味を変えたら上げる**ので、受け手はこれで
挙動を見分けられる」と定義しています。ここで変わったのは**走るかどうか**であって、
走ったときの判定ではありません。

さらに、**黙っていた経路は JSON を 1 バイトも出しません**（実測: v0.6.12 の道具を
別名で走らせると `toolVersion` の出現 0 件）。つまり
**`toolVersion` を読める受け手が「16 なのに挙動が違う」に出会う場面がありません。**
版で見分ける必要が生じないので、上げません。

道具そのものを突き合わせたいときは、`source-verification-result.json` の
`tool.sha256` を見てください。

> **v0.6.12 と v0.6.13 の道具は、どちらも `toolVersion` 16 を名乗ります。**
> 「別名で走らせたときに黙るかどうか」で見分けたい場合、**版数では見分けられません。**
> これは承知のうえの判断です。

### 試験で固定したこと

新設した `test/verifierEntryPoint.test.ts`（6 件）が、**実際に別名でコピーし symlink を張って走らせます。**
ソースに `realpathSync` という語が在ることを確かめても、**走らせなければ「走る」ことは分かりません。**

```
(1) 別名・symlink でも JSON を出す
(2) 正規の名前での出力が別名での出力と同じ（引数を変えれば変わることも見る）
(3) module として import しても CLI は走らない
```

**空振り防止**として、入口を v0.6.12 の書き方へ差し戻した版を試験の中で組み立て、
**そちらでは無言になる**ことを確かめています（差し戻しが実際に入ったことも先に検査します）。
変異対照: 入口を名前判定へ戻すと **4 件が落ちます**（修正前は 0 件でした）。
