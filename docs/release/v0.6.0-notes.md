# v0.6.0 — **schema は 1 本も上げていません。下流はどこでも止まりません**

## ⚠ 先に読むところ

### 1. **契約は変わっていません**

```
v0.5.2 の schema 21 本 → v0.6.0
  HOLD 21 / HOLD_RECORD 0 / **BUMP 0**
新設 1 本  measurement-record.v1.schema.json（比較対象なし）
```

**profile も感度も頑健性も schemaVersion はそのままです。**配布ファイル名も変わりません。
判定は条文（`docs/SCHEMA_VERSIONING_POLICY.md`）の判定器で実測しました
（対照: `required` を 1 つ外すと `BUMP` になるので、判定器は黙っていません）。

### 2. `profileId` が変わりました。**lock を作り直してください**

```
v0.5.2  trs-jack-3d:TRS|JACK-TRS:0a6070eed88f
v0.6.0  trs-jack-3d:TRS|JACK-TRS:480daac80519

v0.5.2  trs-jack-3d:TRS|JACK-TRRS:ba8261c707ff
v0.6.0  trs-jack-3d:TRS|JACK-TRRS:b5b1e5ff2dba
```

**報告文から転記せず、同梱の `trs-jack-3d-release-index.v1.json` から引いてください。**

動いた理由は 3 つで、**どれもモデルの数値とは無関係です。**

- 生成器 `exportHalfPlugProfile.ts` を直した（`verifiedPhysical` の決め方・後述）
- profile の schema の `description` を直した（`evidenceGrade` の定義・後述）
- `package-lock.json` の版数を 0.6.0 へ上げた（全生成物の共通入力）

**区間・event・接点状態・数値は 1 つも変わっていません**（TRS 23/32・TRRS 30/36）。
再生成のたびに**葉ノードまで展開して差分を数え**、provenance 以外が 0 件であることを実測しました。

| | 葉ノード | 差分 | うち provenance 以外 |

| `sensitivity.trs_jack_trs.json` | 204 | 6 | **0** |
| `sensitivity.trs_jack_trrs.json` | 200 | 6 | **0** |

対照として `configurationsTotal` を 5,184 → 5,185 に変えた写しを同じ検出器へ通すと、
「provenance 以外 1 件」で落ちます。**検出器は黙っていません。**

### 3. **`verifiedPhysical` の意味が変わりました。値は `false` のままです**

v0.5.2 まで、この 1 行は**生成器のリテラル `false`** でした。
schema には「`true` にできるのは実測記録が伴う場合のみ」としか書いておらず、
**何を何点測れば足りるのかがどこにもありませんでした。**
つまり実態は「**誰かがリテラルを書き換えたら `true`**」で、検証ではありませんでした。

v0.6.0 で、**記録から機械で決まる値**にしました。

```
条文    docs/VERIFIED_PHYSICAL_GATE.md（全8条）
台帳    docs/measurements/measurement-records.v1.json（**記録 0 件**）
判定器  scripts/measurementGate.mjs
```

**記録が 0 件なので `false` です。それが正しい状態です。**
実測は募集していますが必須にしていません（`docs/VERIFICATION_PLAN.md` 冒頭の方針）。

**受け手から見て変わるのは `physicalVerificationRef` です。**
`null` だったところに、判定の根拠が文字列で入ります。

```
docs/measurements/measurement-records.v1.json@sha256:dfe5020f9198
gate=docs/VERIFIED_PHYSICAL_GATE.md@v1 records=0
required=L_FIRST_CONTACT_SHOULDER_GAP_MM satisfied=- missing=L_FIRST_CONTACT_SHOULDER_GAP_MM rejected=0
```

**`null` を期待して分岐している実装があれば、そこだけ直してください。**
schema は `["string","null"]` のままなので、**型としては壊れていません。**

### 4. **検算ツールの `status` が 1 つ増えました**（`toolVersion` 4 → 5）

同梱の `verifyReleaseSourceInputs.mjs` で、
「取れなかった」と「取れたが archive が壊れている」を分けました。

```
v4  どちらも SOURCE_UNAVAILABLE
v5  SOURCE_UNAVAILABLE … 取れなかった（無い・繋がらない・timeout）
    ARCHIVE_INVALID    … 取れたが安全に読めない。**中身を見ていない**
```

**`exit code` は 2 のままです。**exit code で見ている実装は影響を受けません。
**`status` で分岐している実装だけ**、`ARCHIVE_INVALID` を足してください。
`SOURCE_UNAVAILABLE` だけ見ていると、壊れた archive を素通りします。

詳しくは [verify-tool-v5-notes.md](verify-tool-v5-notes.md)。

## 直したもの

### `verifiedPhysical` の合格条件を条文にした

`docs/VERIFIED_PHYSICAL_GATE.md`。要点だけ。

| 条 | |
|---|---|
| 第1条 | `true` は**必須観測点が裏付けられた**ことだけを言う。全値が実測とは言わない |
| 第2条 | **必須観測点が定義されていない profile は必ず `false`**（空集合を合格にしない） |
| 第4条 | 予測は artifact から引かず、**生成器がその場で計算した値**と照合する |
| 第5条 | 許容は「見分けたい差の 1/5」 |
| 第6条 | 台帳を `inputDigest` に入れない理由と、代わりの縛り方 |
| 第8条 | **実測値も `FACT` に置く。区分は増やさない**（後述） |

判定器は**合成の記録**で試験しています（記録 0 件で `true` にできない／1 件消すと `false` へ落ちる／
揃えば `true`／変異 9 種が 1 件ずつ鳴る）。**実測が来なくても、ここは全部確かめられます。**

### `evidenceGrade` に区分を足さなかった

`MEASURED` を足す案と、`FACT` の定義を「一次情報」へ広げる案を、
条文の判定器に当てて実測してから決めました。

```
案A  enum へ MEASURED を足す          → BUMP（profile v4・下流が止まる）
案B  description を広げる（採用）      → HOLD（差分 0 件・版据え置き）
```

**A を見送った理由は「いま入れる値が無い」ことです。**
`FACT` **53 件はすべて記載寸法で、実測由来は 0 件**（実測）。
中身が空のうちに下流を止めると、**止める理由を実物で説明できません。**

**記載寸法と実測は `sources` で分けます**（記載寸法は資料 ID、実測は記録 ID `MR####`）。

### 信頼できない archive に対して安全にした（外部監査 P1）

`verifyReleaseSourceInputs.mjs` の tar parser。**26 個・6 種類の壊れた tar で実測**しました。

| 何 | v4 | v5 |
|---|---|---|
| header checksum | 見ていなかった | 検算する |
| PAX（`x` / `g`） | **中身をファイルとして拾っていた** | 拾わない。上書き指示にも従わない |
| `..` / 絶対パス / `\` | そのまま登録していた | 止まる |
| symlink / hardlink | ファイルとして扱っていた | 読み飛ばす |
| entry 数・サイズ・パス長・総量 | 上限が無かった | 上限を超えたら止まる |
| `fetch` | timeout が無かった | 60 秒 |

上限は v0.5.2 の実物を測ってから決めました（実測の 6〜20 倍）。
**塞ぎすぎていないことも同じテストで見ています**（正常な tar・実物の tarball・上限のすぐ内側）。

### read-only の CI を入れた（外部監査 P2）

`.github/workflows/ci.yml`。

```
permissions: contents: read だけ（job 側でも足さない）
action は full commit SHA で固定（tag 参照は書き換えられる）
persist-credentials: false
重い成果物（search:topology / sensitivity / search:robustness）は回さない
```

**この 3 つはテストで固定しています**（`test/ciWorkflow.test.ts`）。
tag 参照を混ぜたり `contents: write` を足したりすると落ちます。

「このプロジェクトが保証しないこと」を独立した節にしてあります。
