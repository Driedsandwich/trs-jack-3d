# v0.6.26 — **絶対パスを指す hardlink を受理していました（検算ツール v21 で拒みます）**

## ⚠ 先に読むところ

### 1. **検算ツールの判定が変わります（`toolVersion` 20 → 21）**

v0.6.25 の notes の 4（「前の版から残る穴」）に書いた穴を塞ぎました。
経緯は [`docs/ERRATA.md`](https://github.com/Driedsandwich/trs-jack-3d/blob/v0.6.26/docs/ERRATA.md) の 33 にあります。

**hardlink の指す先が `/` で始まる archive を、v20 までは受理していました。**
指す先を畳むときに先頭の空の要素を捨てていたので、`/root/a.txt` が
先行する `root/a.txt` と同じ物と見なされ、絶対パスの検査に届いていませんでした。
**entry の名前の絶対パスは前から拒んでいたのに、指す先だけこの扱いでした。**

```
root/a.txt（通常ファイル）の後に、指す先が /root/a.txt の hardlink（2026-11-08・macOS）

v20 の検算ツール   OK（root/a.txt と同じ物と見なす）
v21 の検算ツール   ARCHIVE_INVALID / LINK_TARGET_NOT_CANONICAL
python 3.15.2     exit 1（tarfile・filter='tar'・KeyError）
bsdtar 3.5.3      exit 0（先頭の / を外し、中の a.txt と同じ inode に張る）

対照: 指す先が root/a.txt（相対）なら、4 つとも通る
```

「検算ツールが受理した archive は、tar と python が同じ木を作る」という、
この repo が試験で守っている約束から外れる形でした。

- **理由の札は `LINK_TARGET_NOT_CANONICAL` です。**v0.6.25 の notes で予告したとおりです。
  指す先の綴りの問題はすべてこの family（`link`）で返していて、
  指す先が名前の規則に落ちたときもこの札へ言い換えています。
  entry の名前の絶対パスは今までどおり `PATH_ABSOLUTE` です。状態はどちらも `ARCHIVE_INVALID` です。
- **畳む前の生の値で拒みます。**直接の指す先・PAX の `linkpath`・GNU long link（`K`）の
  3 経路を試験に足しました（`test/tarHardening.test.ts` の ⑦・9 本）。
  直しを外した写しでは、絶対パスの 4 本が落ちます。
- **GitHub が作る source archive は当たりません。**git の archive はハードリンクを作らないので、
  前の版の検算ツールでも結果は変わりません。当たるのは、手を加えた archive を通した場合です。
- **v0.6.25 の notes に書いた tar の注意は、検算ツールとは別に今も有効です。**
  GNU tar は `-P`（`--absolute-names`）を付けると先頭の `/` を外しません。
  よそから来た archive を展開するときに `-P` を付けないでください。

### 2. **CLI の出力は `toolVersion` の 1 か所だけ変わります**

CLI の出力は経路ごとに byte で固定しています（`test/fixtures/cli-output-baseline.v1.json`・10 経路）。
`toolVersion` が出力に入るので、**この版で基準を取り直しました。**

取り直す前に、v20 と v21 で 10 経路の出力を実際に出して比べました。

```
10 経路とも   違いは "toolVersion": 20 → 21 の 1 行だけ
終了コード     10 経路とも同じ
stderr        10 経路とも同じ
比べ方の対照   v20 側の出力は、取り直す前の基準と 10/10 一致
```

基準はもともと core / CLI 分離（v0.6.18）の前に取った物で、試験はその時の道具の digest を
「分離で道具が変わっている」の比べる相手にしていました。取り直しで上書きすると、
その比べる相手と、分離の後に足した経路の来歴が消えます。
**分離前の基準の要約は `preSeparation` の欄に残し、試験はそこから読みます。**

**CLI 結果契約は `schemaVersion` 2 のままです。**v2 の schema は `toolVersion` を「20 以上」と定めていて、
v21 の出力もそのまま適合します（この床は道具の版に連動させない決まりです）。

### 3. **開発用の依存の 6 件を、踏む経路ごとに切り分けました（上げてはいません）**

v0.6.25 の notes で「まだやっていない」と書いた切り分けです。
表と根拠は [`docs/maintenance/DEP_TRIAGE_v0626.md`](https://github.com/Driedsandwich/trs-jack-3d/blob/v0.6.26/docs/maintenance/DEP_TRIAGE_v0626.md) にあります。

```
npm audit（2026-11-08）    6 package（high 4・moderate 2）・advisory は足すと 37（重なりを除くと 36）
npm audit --omit=dev       0 件＝6 件とも dev の依存
配る物に入るか              6 件とも入らない（検算ツールは node: の組み込みだけを読む）
条件付きで踏む              vite だけ（開発機で npm run dev を開いている間・待ち受けは localhost）
踏む経路が無い              vitest / @vitest/mocker / fast-uri / source-map-js / undici
```

**lock はこの版では上げていません。**5 つとも `package.json` の範囲の中で lock だけを上げれば直りますが、
lock は記録された入力なので、上げると profile などの由来の作り直しが要ります。
判定を変えたこの版に重ねると、何で記録が変わったのかを分けて追えなくなるので、**次の版の頭で上げます。**

  導通測定も音響測定もしていません（`verifiedPhysical` は `false`）。

- **Dependabot の知らせ。**この repo では有効にしていません（2026-11-08 に API で確かめました）。
  これもリポジトリ設定の変更です。
- **Half-Plug 下流の `release-lock v7` / `mechanism-binding v7`**（別 repo）。
