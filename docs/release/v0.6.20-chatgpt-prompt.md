## 1. **`SOURCE_FETCH_*` の 4 経路を、global を差し替えずに踏めるようにしました**

**実質の差分は 2 行です。**`v0.6.19` と `v0.6.20` の tag 間で道具を diff した実測値:

```
変更ブロック 2 個 / 削除 1 行 / 追加 12 行（うち 10 行はコメント）

  > 　fetch: (url, init) => fetch(url, init),      ← io へ足した 1 行
  < 　res = await fetch(url, {
  > 　res = await io.fetch(url, {                  ← 呼び出しを io 経由へ

判定ロジック  **差分 0 行**
```

そちらでも同じものが取れます。

```
diff <(git show v0.6.19:scripts/verifyReleaseSourceInputs.mjs) \
     <(git show v0.6.20:scripts/verifyReleaseSourceInputs.mjs)
```

踏めるようになった 4 つ:

```
SOURCE_FETCH_FAILED      fetch が throw
SOURCE_FETCH_TIMEOUT     name = 'TimeoutError' で throw
SOURCE_HTTP_ERROR        503 を返す
SOURCE_BODY_UNREADABLE   本文の reader が失敗する
```

`AbortSignal.timeout` が `TimeoutError` を投げる約束はそのままで、
差し替える側が同じ約束を守ればよい形です。

**`globalThis.fetch` を触っていないこと**も試験で確かめています
——触っていたら、その試験は「global の差し替えが効いた」ことしか示しません。
`io.fetch` が呼ばれた回数も数えます（各 1 回）。呼ばれていなければ別の経路で止まっています。

## 2. **`toolVersion` も `schemaVersion` も上げていません**

**受け手の分岐は 1 つも変わりません。**添付の道具から直接読めます。

```

export const CLI_RESULT_SCHEMA_VERSION = 2

**上げていない根拠（すべて実測）:**

```

              stdout / stderr / 終了コードの sha256 で比べる
出しうる code  **82 種類のまま**（corpus 45 / cli-route 34 / defensive-invariant 3。合計 82）
io は出力に出るか  **0 件**
```

catalog の数はそちらでも数えられます（`REASON_CODES` は export されています）。

```js
const m = await import('./verifyReleaseSourceInputs.mjs')
Object.keys(m.REASON_CODES).length                      // 82
Object.keys(m.defaultIo()).length                       // 11
```

`io` に注入できるのは **11 種類**です。

```
cwd / argv / stdout / stderr / exit                              v0.6.18
existsSync / readFileSync / statSync / lstatSync / readdirSync   v0.6.18
fetch                                                            **v0.6.20**
```

`io` は道具の内側の仕組みで、**受け手が読む値には現れません。**

基準は repo に入っています（`test/fixtures/cli-output-baseline.v1.json`）。
`npm run check:cli-output` で**そちらでも同じものを回せます。**CI にも段として入っています。
**`JSON.parse` して比べていません。byte で比べます**——キーの順序が変われば受け手の差分も変わるためです。

## 3. **既存の検査が 1 件、正しく鳴りました**

「`gh` に依存していない」の検査が、`io.fetch` へ寄せた瞬間に落ちました。
**性質（外部コマンドに頼っていない）を、書き方で確かめていた**わけです。

**検査を緩める前に、性質が保たれているかを実測しました。**
`io` の既定は組み込みの `fetch` そのものなので、性質は変わっていません。
そのうえで実態へ合わせましたが、**両方の書き方を許すだけにはしていません。**

`test/verifyReleaseSourceInputs.test.ts` の実物（行番号は現在の repo のもの）:

```
82:  it('**`gh` に依存していない**（受け手の環境に無くても使える）', () => {
83:    expect(SRC).not.toMatch(/execFileSync\(\s*'gh'/)
84:    expect(SRC).not.toMatch(/'gh api'/)
94:    expect(SRC, '取得の経路が見当たらない').toMatch(/await (io\.)?fetch\(/)
96:    expect(SRC, 'io の既定が組み込みの fetch でない').toMatch(/fetch: \(url, init\) => fetch\(url, init\)/)
```

**96 行目が新しく足したほうです。**差し替え先が別物になったら、94 行目の検査は意味を失います。
対照として、取得の経路を消すと落ちることを確かめています。

**落ちたのは検査が正しく鳴ったから**でもあります——「取得の経路がソースに見当たらない」
という状態は、本当に外部コマンドへ逃げたときにも起きます。**区別がつきません。**

## 5. **「過去 N 件が byte 一致」の検算を、repo へ入れました**

v0.6.16 からの release notes に毎版こう書いてきました。

> 過去 release の asset は **v0.1.0〜v0.6.19 の 753 件すべて byte 一致**を、
> 再生成の段ごとに対照つきで実測しています

**この数字を出す道具は repo の外にありました**（作業機の `~/.trs_v0615/` と `~/.trs_v0616_audit/`）。
つまり **5 版ぶん報告して、そちらでは一度も再現できませんでした。**
結果だけ配って手段を配らないのは、この repo が他の場所でやっていることと矛盾します。

```
npm run check:published-assets       scripts/publishedAssetBaseline.mjs
基準  test/fixtures/published-assets-baseline.v1.json
      783 件 / 30 tag（v0.1.0〜v0.6.20）/ schemaId trs-jack-3d-published-assets-baseline.v1
終了  0 無傷 / 1 要確認 / 2 **測れていない**
```

**そちらでも回せます**（`gh` が要ります）。出力はこの形です。

```
公開中 783 件 / 基準 783 件と一致 783 件 / 対照 782 件
→ 過去の asset はすべて無傷（対照も効いている）
```

移すときに、外に置いていたから許されていた 2 つを直しました。

**件数を直書きしない。** 旧版は `base_753.tsv` と「753」という数の**両方**を持ち、
版が上がるたび人が書き換えていました（663 → 693 → 723 → 753）。
書き換え忘れれば、**検査は緑のまま守る範囲だけが古くなります。**
いまは件数も対象 tag も基準ファイルから数えるので、版が上がっても直す所はありません。

**対照を別ファイルで持たない。** 旧版は `base_753_broken.tsv`（1 文字だけ違う写し）を
並べて置いていました。**同じ境界を 2 つの一覧で持つ**形です。
いまは対照をその場で基準から作り、**変異が入ったことを毎回確かめてから**当てます。

> **移す前と移した後で同じ答えが出ることを先に確かめました。**
> 旧基準 753 件を新しい形へ載せ替えて（往復して原本と byte 一致）、両方を回しています。
>
> ```
> 移す前   公開中 783 件 / 基準 753 件と一致 753 件 / 対照 752 件   exit 0
> 移した後  公開中 783 件 / 基準 753 件と一致 753 件 / 対照 752 件   exit 0
> ```
>
> そのうえで基準を v0.6.20 まで広げました。旧 753 件は全件そのまま含まれ、増えたのは 30 件です。

## 6. **その検算に欠陥がありました。「取れなかった」を「0 件」と報告していました**

v0.6.20 を公開する直前、この検査がこう出しました。

```
Post "https://api.github.com/graphql": dial tcp 20.27.177.116:443: i/o timeout
  公開中 0 件 / 基準 753 件と一致 0 件 / 対照 0 件
  → **要確認**            ← 終了コードは 0
```

**asset は 1 件も欠けていませんでした。**GitHub API のタイムアウトです。
原因は道具の側にありました（`~/.trs_v0615/assets.sh` の控え、行番号つき）。

```
 4  set -e
 5  out="$1"
 6  : > "$out"
 7  for t in $(gh release list --repo Driedsandwich/trs-jack-3d --limit 100 --json tagName --jq '.[].tagName' | sort -V); do
 8    gh release view "$t" --repo Driedsandwich/trs-jack-3d --json assets \
 9      --jq ".assets[] | \"$t\t\(.name)\t\(.digest)\"" >> "$out"
10  done
11  wc -l < "$out"
```

**`gh` が失敗すると 7 行目の語リストが空になり、loop が一度も回りません。**
`set -e` も効きません。出力は「asset が全部消えた」ときと**同じ形**になります。

**ここが一番効くところです——対照も一緒に 0 になります。**
この検査の対照は「基準を 1 件壊すと一致が 1 件減る」ですが、
取得に失敗すると壊した側も壊していない側も 0 件になり、**対照は何も守りません。**
対照は「基準を壊したら気づくか」を見ているだけで、「測れたか」は見ていませんでした。

いまはこうです。

```
export const EXIT_OK = 0                  // 48 行
export const EXIT_MISMATCH = 1            // 49 行
export const EXIT_MEASUREMENT_FAILED = 2  // 50 行
```

`measurePublished()` は**どこで失敗しても `MeasurementFailure` を投げます**（空配列を返しません）。
偽の `gh` を PATH の先頭に置いて 3 通り実測しました。

```
通信断（exit 1 を返す）  → 件数を出さず exit 2
gh が存在しない          → 件数を出さず exit 2
release を 0 本返す      → 件数を出さず exit 2
対照（直す前の道具）      → 「公開中 0 件 / 一致 0 件 / 対照 0 件・要確認」で exit 0
```

判定に変異を 4 通り入れ、落ちる試験を数えています。

```
空の tag 一覧を投げずに通す   → 2 件
対照の関門を外す             → 1 件
digest を鍵から外す          → 8 件
取得失敗でも件数を出す        → 5 件
```

## 7. **CI へは入れていません。その除外を宣言して固定しました**

**測っている対象が push では変わらない**ためです。公開済み asset が変わるのは
誰かが release を編集・削除したときで、commit とは無関係に起きます。
それを毎 push の関門に置くと、**通信の揺らぎがその commit の欠陥のような顔で
release の関門を赤くします。**道具は「測れなかった」を終了コード 2 で分けていますが、
CI は緑か赤しか持てません。API も 1 回の push で 62 回叩くことになります（31 × 2 環境）。

**判定の中身は CI で守っています。** `test/publishedAssetBaseline.test.ts`（**18 件**）が
`io` を注入して `main()` を回すので、**GitHub を 1 回も叩かずに**規則が固定されます。

除外は黙って外さず、`test/ciWorkflow.test.ts` の `NEVER` 一覧へ理由つきで入れました。

```
112:  const NEVER = ['npm run search:topology', 'npm run sensitivity', 'npm run search:robustness',
127:    'npm run check:published-assets']
```

**後から CI へ足すとテストが落ちて、理由を読むことになります。**
実際に CI の workflow へ足して落ちること、戻すと通ることを確かめています（36 件 → 1 件 failed → 36 件)。
