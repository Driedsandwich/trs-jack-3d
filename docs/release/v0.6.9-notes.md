# v0.6.9 — **schema は 1 本も上げていません。下流はどこでも止まりません**

## ⚠ 先に読むところ

### 1. **v0.6.8 は、ヘッダ形式を確かめずに tar のパスを組み立てていました**

**受け手に直接影響するのはこちらです。**

```
magic が old GNU（ustar␠␠\0）／ V7（全 NUL）／ 未知 で、345..499 が非空
  検算 v13  status OK ／ 32 of 32（src/model/types.ts が「ある」と言う）
  bsdtar    exit 0 — types.ts を root に作る       ← prefix を使わない
  python    exit 0 — src/model/types.ts を作る     ← prefix を使う
```

**同じ archive から別の木ができます。**受け手が macOS の `tar` で展開すると、
検算器が「あった」と言ったファイルが手元にありません。

345..499 が prefix なのは **POSIX ustar のときだけ**です。
old GNU ではそこは atime / ctime / offset / sparse の領域でした。

### 2. **知らない entry 型が素通りしていました**

```
typeflag Z ／ 空白（本体 5 バイト）を、範囲の外（docs/ の下）に置く
  検算 v13  status OK ／ 32 of 32 ／ files 85・inventory 86
  bsdtar    exit 0 — 5 バイトの通常ファイルを作る
  python    同じ
```

v13 の検査は**除外表**でした。**除外表は、知らない物を通す側へ倒れます。**
許可表にして、載っていない型は止めます。

### **お願い: v0.6.8 以前で出た `OK` は、この 2 つを見ていません**

**そちらが v0.6.8 以前の道具で別の archive を検算していた場合、
`OK` が出ていても「そのヘッダ形式が正しい」ことも
「知らない型が混じっていない」ことも確かめていません。**
`v0.6.9` の道具で取り直してください。

### 3. **こちらの過剰拒否が 5 版続けてです**

```
同一 PAX ヘッダ内の重複鍵            6 鍵とも 2 実装が一致して後の値を採るのに拒んでいた
symlink / hardlink の末尾スラッシュ  2 実装とも同じ木を作るのに拒んでいた
頭 1 個しかない archive              2 実装とも同じ木を作るのに「壊れている」と言っていた
```

最後の 1 件は監査の指摘になく、**こちらの根拠検査そのものが見つけました。**

### 4. **こちらが 1 つ間違え、CI が落として分かりました**

長さ 0 の `mtime=` / `uid=` も「過剰拒否」と判断して**通すように直したのですが、誤りでした。**

```
GNU tar 1.35  Malformed extended header: invalid mtime= — **archive ごと拒む**
bsdtar        exit 0 — 削除として無視して展開する
python        同じ
```

**開発機に GNU tar が無く、手元の 2 実装がそろって通したのを「割れていない」と読みました。**
割れていたのは**3 つ目の実装**です。**v0.6.8 の拒否が正しかった。**

**2 実装で足りるかどうかは、2 実装では決められません。**

### 5. **監査の勧告のうち 3 点は採っていません**

前回、**監査の勧めた正規表現がそのまま過剰拒否になりました。**
今回は勧告どおりに書いたものを corpus の「通す」側へ当ててから決めています。

| 勧告 | 採らなかった理由（実測） |
|---|---|
| V7・old GNU は `ArchiveUnsupported` | 345..499 が空なら 2 実装とも同じ木。**old GNU は GNU tar 自身の既定の出力形式**で、拒むと実物が読めなくなる |
| prefix は `ustar\0` + `00` のときだけ | version が `00` / NUL NUL / 空白 2 個のどれでも 2 実装とも prefix を使う。version まで見ると通る形を落とす |
| 長さ 0 の `path=` は POSIX の削除意味を実装 | 実装すると bsdtar とは一致するが python とは一致しない |

### 6. 確かめる側の欠陥も直しました

木を歩く試験の道具が、**FIFO を読もうとして書き手を待ち、永久に止まる**状態でした。
例外ではなく停止なので `try` では捕まりません。**CI ごと止まります。**
実測で **typeflag 6 は 2 実装とも実際に FIFO を作る**と分かったので、
材料を corpus へ入れる**前に**直しました。

### 7. `profileId` が変わりました。**lock を作り直してください**

**この文書から転記せず、同梱の `trs-jack-3d-release-index.v1.json` から引いてください。**

**入力ではない**ので、v13 → v14 にしても digest を動かしません。

**モデルの数値は変わっていません。**葉ノードまで平坦化した実測です。


## 止める理由が、どちらの実装で裏を取れるか

```
GNU tar 側でだけ根拠が取れる   11 件（v0.6.8 は 9 件）
bsdtar 側でだけ根拠が取れる     9 件
どちらでも取れていない          2 件（v0.6.8 は 3 件）
```

増えた 2 件が**長さ 0 の `mtime=` / `uid=`**（上の §4）、
減った 1 件が `pax-symlink-trailing-slash` で、**過剰拒否だったので受理側へ直しました。**
`none` の 2 件は、名前・指す先の上書きが 2 つ効く形の**片方の順序**です。
