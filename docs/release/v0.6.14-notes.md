# v0.6.14 — **`stableReasonCode` が全経路を覆っていませんでした。`toolVersion` を 17 へ上げます**

## ⚠ 先に読むところ

### 1. **`toolVersion` が 16 → 17 になります。判定の出力が変わります**

v0.6.13 までの道具は、いくつかの経路で**止めた理由の名前を付けていませんでした。**
受け手が機械で分岐する値が変わるので、版を上げます。

```
                        v0.6.13                    v0.6.14
壊れた gzip              ARCHIVE_INVALID_OTHER  →   GZIP_DECODE_FAILED
source root が symlink   ARCHIVE_INVALID_OTHER  →   SOURCE_ROOT_SYMLINK
圧縮サイズ上限            （名前なし）            →   LIMIT_COMPRESSED_BYTES_UNSUPPORTED
```

**`*_OTHER` で分岐している自動処理があれば、そこは直す必要があります。**

> **v0.6.13 では 16 に据え置きました。**あのときは入口の判定を直しただけで
> 正規の名前での出力が byte 一致だったためで、その判断自体は今も誤りだと思っていません。
> **今回は判定の出力そのものが変わる**ので、規則どおり上げます。
> なお **v0.6.12 と v0.6.13 の道具は、どちらも 16 を名乗ります**——`tool.sha256` で見分けてください。

### 2. **こちらが公開した文書が虚偽でした**

```
verify-tool-v16-notes.md:「gzip の失敗に GZIP_DECODE_FAILED を付けました」
実測: その名前は source 全体で 1 件、しかも**コメントの中だけ**（実装されていない）
```

**実装していない機能を「付けた」と書いて配布していました。**

「corpus で止まる材料 110 件・`*_OTHER` は 0 件」は真でしたが、
**それは corpus が踏んだ経路についてだけ**です。走らせて集めた実測では、
catalog の 55 種類のうち **corpus が踏むのは 37 種類**でした。

### 3. **配布物に古い一覧と誤った境界が残っていました**

```
配布ソースの冒頭 28〜32 行   status を 5 種類だけ並べたコメント（道具は 8 種類を返す）
配布 schema の description   「v0.3.0 より前の tag」（正しくは v0.4.0 より前・v0.3.0 自身も対象）
```

**どちらも、こちらが v0.6.11〜v0.6.12 で同じ誤りを直した「もう 1 か所」です。**
artifact の手順書を直したときに配布ソース側を、
ERRATA で notes を訂正したときに schema 側を、それぞれ見落としました。

訂正は
[`docs/ERRATA.md`](https://github.com/Driedsandwich/trs-jack-3d/blob/v0.6.14/docs/ERRATA.md)
に**気づいた方法と再現手順つき**で積んでいます（今回で 7 件目まで）。

## 直し方 — 止め方の名前を 1 か所で持つ

`REASON_CODES` を新設しました（`code → status / family / summary`・**55 種類**）。
**配布物 1 ファイルに同梱**しています。

```
ArchiveInvalid / ArchiveUnsupported
  catalog に無い名前   → その場で投げる
  名前を付けない       → その場で投げる
  status が食い違う    → その場で投げる（受け手が「壊れている」と「範囲の外」を読み分けるため）
{ kind: 'ARCHIVE_*' } の直書き 3 か所 → archiveError() へ集約し、kind は catalog から引く
```

**変異対照**: 修正前は「catalog に無い code を使う」で落ちる試験が **0 件**でした。
修正後は **4 件**落ちます。

### `KNOWN_LOAD_KINDS` と `NOTE` も 1 つにしました

status に紐づくもの（終了コード・loader が返してよいか・受け手向け注記）を
`CLI_STATUS_META` へ統合しました。手書きの 2 要素配列だったときは、
status を足すと**黙って `SOURCE_UNAVAILABLE` へ丸められる**経路が残っていました。
——「取れなかった」と「壊れていた」が入れ替わる、いちばん避けたい丸め方です。

### `archivePolicy` が覆っていない範囲を、自分で言うようにしました

名前は「受け入れる範囲の全部」と読めますが、機械で読める形にしてあるのは
形式・prefix・typeflag・終端・上限の 5 つだけです。
PAX の鍵・パスの綴り・リンクの指す先・checksum・重複は**止め方の名前でしか表に出ていません。**

**改名は schema を狭めて下流を止める**ので、`notMachineReadableHere` と
`reasonCodeFamilies` を足す形にしました（言語部分集合の判定器で `HOLD` を実測済み）。

## `profileId` が変わりました。**lock を作り直してください**

```
v0.6.13  trs-jack-3d:TRS|JACK-TRS:e4c3e9916a50
v0.6.14  trs-jack-3d:TRS|JACK-TRS:864677448069

```

**この文書から転記せず、同梱の `trs-jack-3d-release-index.v1.json` から引いてください。**

**動いた原因は版数上げ（`package-lock.json`）です。モデルの数値は変わっていません。**

```
TRS   葉 2267 件 → 由来まわりの差 8 件 / モデル数値の差 0 件

```

対照として `entries["jack.fullInsertionDepth"].value` を 14 → 14.001 に変えると
**モデル数値の差が TRS 80 件**になります。

## まだやっていないこと

- **実測が 1 件も来ていません。**ジャック内部の接点位置は全部仮定のままで、
  導通測定も音響測定もしていません（`verifiedPhysical` は `false`）。
- **corpus は catalog の 55 種類のうち 37 種類しか踏みません。**
  残り 18 種類のうち 3 種類（gzip・root symlink・圧縮サイズ上限）は
  CLI の経路として試験に足しましたが、**15 種類はまだ材料がありません。**
  試験がこの数を毎 run 出すので、増減したら気づきます。
- BusyBox を oracle に足すこと。**開発機にも CI にもありません。**
  監査から BusyBox 1.37.0 の実測（`pax-path-then-gnu-longname` などで分岐が割れる）を
  もらいましたが、**こちらでは再現していません。**bsdtar と python の列は一致しました。
- annotated tag への署名。
- 検算ツールの強化は**試験した範囲まで**です。**すべての細工に耐えることは示していません**
  ——v5 から v16 までに計 33 件見落とし、**v9〜v15 では正当な archive を拒みもしていました。**
