## 1. 何で固定するか — `sourceRevision` では固定しないでください

次の 2 通りのどちらかにしてください。`main` は追わないでください。

| | 固定するもの |
|---|---|
| **A** | release tag `v0.1.0` ＋ asset の SHA-256（`SHA256SUMS` に同梱） |
| **B** | commit `84c39753f70ff49baf3dfd445315d4c4316b0791` ＋ `provenance.inputDigest` |

```
provenance.inputDigest = bba0e6dc73a4273c7178ede2eaeb40cb518fcf6c9c0c7679d24f15a9a6d821a0
profileId              = trs-jack-3d:<variant>:bba0e6dc73a4
```

**理由**: `sourceRevision === HEAD` を要求できない、というオーダーの指摘はそのとおりでした。artifact を含めてコミットすると HEAD が変わるため、生成時点で正しかった値があとから「古い」ように見えます。

そこで **`inputDigest`（入力ファイルの中身だけから作った sha256。生成物自身は含まない）** を導入しました。入力が同じなら、生成し直しても変わりません。`provenance.inputFiles[]` に path と sha256 が入っているので、**そちらで再計算して検算できます**（作り方は `inputDigestScope` に記載）。

`profileId` も `<revision>` 由来から `<inputDigest>` 由来へ変えました（**破壊的変更**）。

## 2. `events[].spreadMm` の意味が変わりました — 旧版の値は読み捨ててください

P0-3 の指摘はそのとおりで、**下流を誤誘導する状態でした。**

旧版は感度解析の **`kind` 単位の集計を各事象へ複製**していました。`STATE_CHANGE` は 1 回の挿入で何度も起きます（**TRS×TRRS で 29 件 / TRS×TRS で 24 件**）。その全部に同じ `−0.88〜14 mm`（挿入ストローク全域）が付いており、Ring のブレーク接点にも帰線接点用の幅が付いていました。

現在は `spreadStatus` で 3 つを区別します。

| `spreadStatus` | `spreadMm` | 意味 |
|---|---|---|
| `MEASURED` | 値あり | その事象そのものを測った幅 |
| `NOT_EVENT_SPECIFIC` | `null` | `kind` 単位の集計しか無く、この事象へは配れない |
| `NOT_MEASURED` | `null` | 測っていない |

**どれも「動かない」の意味ではありません。**`kind` 単位の集計は捨てておらず `sensitivitySummary.aggregateSpreadByKind` にあります。**そちらを個々の事象へ当てはめないでください。**

## 3. `intervalId` と `eventId` は `profileId` とセットで保存してください

どちらも**位置に依存します。**

- `intervalId`（`IV028` など）は区間の並び順から振った番号
- `eventId`（`STATE_CHANGE:JC_RING:BREAK_CLOSED->BREAK_OPEN#1`）の末尾 `#n` は、同じ遷移が挿入中に複数回起きるための連番

実際、4極ジャックの組み直しで TRS×TRRS profile の本命区間は `IV019`（12.90〜13.12 mm）から `IV028`（13.30〜13.52 mm）へ移り、区間総数も 21 → 30 になりました。

`profileId` が違ったら、**`electricalTopology.topologyClass` と `normalizedStart/End` で引き直してください。**

> `topologyClass` は `acousticAnnotation` から **`electricalTopology`** へ移しました（P0-4。電気的な事実と聴感の仮説を別層にするため）。**破壊的変更**です。

## 4. 実測していないことの確認

| | |
|---|---|
| `verifiedPhysical` | **`false`** |
| 導通の実測 | **未実施** |
| 音響の実測 | **未実施** |
| 4極ジャックの接点の軸方向オフセット | **ASSUMPTION**（一次資料なし） |

**実在資料 2 件が逆を指しています。** pro-SIGNAL PS000001 の断面図（Tip 接点 12.75 mm）を入れると左右差分の区間は **1 件も出ません**。Lumberg 1503 28 の端子位置（11.30 mm）では出ます。結論は Tip 接点が 12.6 mm より浅いことを必要条件にしており、**PS000001 はその外側**です。どちらが実物に近いかは決着していません。

`realizability.passesPadWidthHeuristic` は**製造可能性の判定ではありません**（P0-5 で改名）。0.3 mm という閾値には出典がなく、`manufacturingVerified: false` と記録しています。
