# 検算ツール `verifyReleaseSourceInputs.mjs` を v14 にしました（受け手向け）

対象: 配布物に同梱している `verifyReleaseSourceInputs.mjs`
出力の `toolVersion` が **13 → 14** になります。

v13（v0.6.8）の続きです。外部監査（2026-08-11）が **P0 3 件と P1 3 件**の反例を出しました。
**6 群すべてを、こちらで組み立て直して再現できました。**
**そのうえで、勧告のうち 3 点は採らず、理由を実測で示しています**（後述 §6）。

> **今回の監査パケットも checksum が合いました**（`shasum -a 256 -c` が exit 0）。

## 手元で確かめられた範囲

開発機（macOS）は **bsdtar 3.5.3 / libarchive 3.7.4 と Python 3.14.6** の 2 実装。
CI は **ubuntu（GNU tar 1.35）と macOS** の matrix です。
**BusyBox と GNU tar は開発機にありません**——GNU tar の結果は
**CI へ材料を通して取っています**（§4 の訂正は、その CI が落として分かりました）。
監査が BusyBox で取ったと書いている結果は、**こちらでは追試していません。**

## 1. **ヘッダ形式を確かめずに 345..499 を prefix として読んでいました**（P0-A）

```
magic が old GNU（ustar␠␠\0）／ V7（全 NUL）／ 未知 で、345..499 が非空
  検算 v13  status OK ／ 32 of 32（src/model/types.ts が「ある」と言う）
  bsdtar    exit 0 — types.ts を root に作る       ← prefix を使わない
  python    exit 0 — src/model/types.ts を作る     ← prefix を使う
```

**同じ archive から別の木ができます。**受け手が macOS の `tar` で展開すると、
検算器が「あった」と言ったファイルが手元にありません。

345..499 が prefix なのは **POSIX ustar のときだけ**で、
old GNU ではそこは atime / ctime / offset / sparse の領域です。
v14 は magic を形式判別子として読み、**prefix を使うのは POSIX ustar のときだけ**にしました。

> **監査は「GNU tar だけが違う」と書いていましたが、実測ではもっと広いです。**
> **bsdtar でも同じ差が出ます**（つまり手元の 2 実装だけで根拠が取れます）。

## 2. **知らない entry 型が素通りしていました**（P0-B）

```
typeflag Z ／ 空白（本体 5 バイト）を、範囲の外（docs/ の下）に置く
  検算 v13  status OK ／ 32 of 32 ／ files 85・inventory 86
  bsdtar    exit 0 — 5 バイトの通常ファイルを作る
  python    同じ
```

v13 の検査は `7`/`S`/`D`/`M`/`N` を並べた**除外表**でした。
**除外表は、知らない物を通す側へ倒れます。**許可表にして、載っていない型は止めます。

支援するのは `NUL`/`0`・`1`・`2`・`5`・`x`・`g`・`L`・`K` だけです。

## 3. 長さ 0 の PAX 値（P0-C）

```
x: path=（長さ 0）＋ 生ヘッダ root/raw.txt
  検算 v13  READ — files 0 件（**member が丸ごと消える**）
  bsdtar    exit 0 — root/raw.txt を作る（POSIX の削除意味）
  python    exit 2 — IsADirectoryError（空の名前として扱う）
```

v13 は空文字を名前として採り、**その member を落としたまま `OK` と言っていました。**

## 4. **こちらの過剰拒否が 5 版続けてです**（P1）

```
同一 PAX ヘッダ内の重複鍵        6 鍵とも 2 実装が一致して後の値を採るのに拒んでいた
symlink / hardlink の末尾スラッシュ  2 実装とも同じ木を作るのに拒んでいた
頭 1 個しかない archive            2 実装とも同じ木を作るのに「壊れている」と言っていた
```

**最後の 1 件は監査の指摘にありません。**材料を足したとき、
**こちらの根拠検査そのものが落として**教えてくれました。

### **ここで 1 つ間違えました（CI が落として分かりました）**

長さ 0 の `mtime=` と `uid=` も「過剰拒否」と判断して**通すように直したのですが、誤りでした。**

```
x: mtime=（長さ 0）
  GNU tar 1.35  Malformed extended header: invalid mtime= — **archive ごと拒む**
  bsdtar        exit 0 — 削除として無視して展開する
  python        同じ
```

**開発機に GNU tar が無く、手元の 2 実装がそろって通したのを「割れていない」と読みました。**
割れていたのは**3 つ目の実装**です。受理すると、GNU tar の受け手は何も手に入らないのに
検算器だけが「そのファイルはある」と言うことになります。**v13 の拒否が正しかった。**

**2 実装で足りるかどうかは、2 実装では決められません。**
これが v12 で CI を 2 platform の matrix にした理由そのもので、
今回はその matrix が実際に働きました。

`pax-symlink-trailing-slash` は、v13 の時点で
**「2 実装が同じ木を作るのに止めている」と自分で書いてあった行**でした。
**根拠が無いと書いた行は、次に直す候補の一覧でもあります。**

## 5. 確かめる側の欠陥も 1 つ見つけました

木を歩く試験の道具が、**FIFO を `readFileSync` して書き手を待ち、永久に止まる**状態でした。
例外ではなく停止なので `try` では捕まりません。**CI ごと止まります。**

実測で **typeflag 6 は bsdtar・python とも実際に FIFO を作る**と分かったので、
typeflag の材料を corpus へ入れる**前に**直しました。
今の corpus には FIFO を作る材料がなかったので、**この欠陥はまだ一度も踏んでいません。**

## 6. **勧告のうち 3 点は採りませんでした**

前回、**監査の勧めた正規表現をそのまま採ったことが過剰拒否になりました。**
今回は勧告どおりに書いたものを corpus の「通す」側へ当ててから決めています。

### (a)「V7・old GNU を実装しないなら `ArchiveUnsupported`」→ 採らない

実測で、**345..499 が空なら old GNU も V7 も未知 magic も 2 実装が同じ木**を作ります。
そして **old GNU は GNU tar 自身の既定の出力形式**です。
形式で拒むと、**ふつうに GNU tar で作った tar.gz が読めなくなります。**

止めるのは「**形式が POSIX ustar でないのに 345..499 が非空**」——実装が割れる形だけです。

### (b)「POSIX ustar は `ustar\0` + `00` でのみ prefix を使う」→ version を見ない

実測で、magic が `ustar\0` なら version が **`00` / NUL NUL / 空白 2 個**のどれでも
2 実装とも prefix を使います。version まで見ると、この 2 つを落とします。

### (c)「長さ 0 の `path=` は POSIX の削除意味を実装する」→ 止める

削除意味を実装すると **bsdtar とは一致しますが python とは一致しません**（上の §3）。
この道具の約束は「ここに挙げた物が、展開して出てくる物と同じ」なので、
**読み手によって出てくる物が違う archive では、その約束を果たせません。**
v0.6.6 以来の「割れるものは受理しない」と同じ規則を当てます。

長さ 0 の扱いは、**解釈する鍵かどうかで分けます。**`path`・`linkpath` は上のとおり止め、
`mtime`・`uid` など値を読む鍵も **GNU tar が拒むので止めます**（§4 の訂正）。
見え方を変えない鍵（xattr・comment 等）だけ、何もしません。

## 7. 止める理由が、どちらの実装で裏を取れるか

```
GNU tar 側でだけ根拠が取れる   11 件（v13 は 9 件）
bsdtar 側でだけ根拠が取れる     9 件
どちらでも取れていない          2 件（v13 は 3 件）
```

増えた 2 件が、上で書いた**長さ 0 の `mtime=` / `uid=`** です。
減った 1 件が `pax-symlink-trailing-slash` で、**過剰拒否だったので受理側へ直しました。**
残る 2 件は、名前・指す先の上書きが 2 つ効く形の**片方の順序**です
（監査は BusyBox で裏を取ったと報告していますが、こちらには BusyBox がありません）。

## 8. `stableReasonCode` を付けました

止めた理由に、文章とは別の**変わらない名前**を付けました。文章は版ごとに書き換わります。
欄名・型・パスの具体値は `detail` に入れ、**欄ごとの code は作りません**（監査 §6）。

受け手向けの `source-verifier-cli-result.v1` schema（監査 §7）は**まだ作っていません。**
新しい公開契約なので、release の判断と一緒に決めます。

## 塞ぎすぎていないこと

```
GitHub の実 tarball（v0.6.7）   entry 330
git archive HEAD                entry 331（typeflag 0/5/g）
macOS tar が作ったもの           通る（typeflag 0/x）
npm の実 tarball 600 本          51,802 entry・magic はすべて ustar\0+00
                                 うち 632 entry が prefix を実際に使っている
```

壊れた tar の corpus は **119 個 12 種類 → 146 個 13 種類**、
うち「通す」材料が **34 → 49 件**です。

新しい検査が本当に効いていることは、**変異を 12 通り入れて確かめました（10 件を検出）。**
残る 2 件は、**単体では落とせない控えの行**だと分かったので、
そう分かるようにコードへ書いてあります——
効いている検査は別の場所（形式の `throw` と、祖先の型の検査）にあります。

## 変わらないこと

- **read-only** です。書き込み API を使わず、tar は展開せずメモリ上で読みます
- モデルの数値は 1 つも動いていません
- **実測記録は 0 件のまま**で、`verifiedPhysical` は `false` です

## 戻し方

変更は検算ツールと試験だけです。`profileId`・区間・event・`verifiedPhysical` は動きません。
受け手は v13 の道具を使い続けられます（出力の `toolVersion` で見分けられます）。
判定が変わるのは、**上の 1〜4 に当たる archive を検算したときだけ**です。
