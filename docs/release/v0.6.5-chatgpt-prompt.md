### P0-2 — 受理するのに、誰も展開できない archive があった

**そちらの「展開失敗を利用して見えない file を混ぜられるか」は、そのとおり再現しました。**

### P0-3 — PAX の `path` に入れた NUL を切り捨てていた

```
再現（v0.6.4 実測）

```

固定長ヘッダ欄用（NUL は詰め物）と PAX テキスト用（NUL は値の一部）で読み方を分けました。

### P0-4 — PAX の denylist が閉じていなかった → allowlist へ

```
再現（v0.6.4 実測）
  PAX x: SUN.holesdata=0 4 4 4
    検算 v9  status OK（未知の鍵として無視）
    bsdtar   exit 1 — Parse error: SUN.holesdata で archive ごと拒否

```

**こちらの実測は、そちらの説明とは少し違いました。**
そちらは「libarchive が sparse metadata として解釈するので view が変わる」でしたが、
こちらで見えたのは **bsdtar が archive ごと拒否する**という形です。
どちらにせよ **3 者で結末が割れる**ので、結論（accepted subset へ入れない）は同じです。

**そちらの提案どおり allowlist へ変えました。**通す鍵は実物を数えてから決めています。

```
通す   path（解釈する）／ mtime・atime・ctime ／ uid・gid・uname・gname ／ comment
       LIBARCHIVE.xattr.* ／ SCHILY.xattr.*（値は読まない不透明な metadata）
拒む   上記以外すべて（未知の vendor 鍵を含む）

実物の PAX 鍵（実測）
  GitHub の tarball   g:comment だけ
  macOS の tar        x:mtime / x:LIBARCHIVE.xattr.* / x:SCHILY.xattr.*
```

## 3. **v0.6.4 の `ARCHIVE_INVALID` は、archive の問題でなかった可能性があります**

上の P1 は **false-reject**（正当な archive を拒む）です。

**この repo の実物では踏みません**——最長パスが 95 文字で、long name 機構を使わないためです。
**「実物が通る」確認では過剰拒否は見つかりません。**

**そちらが v0.6.4 の道具で別の archive を検算していた場合**、
`ARCHIVE_INVALID` が出ていても、それは archive の欠陥ではなく**こちらの誤検知**だった
可能性があります。**v0.6.5 で取り直してください。**

該当しうるのは、**同じ archive の中に長いパスのファイルが 2 つ以上ある**場合です
（GNU tar の `L` ヘッダ、または per-file の PAX `path` を 2 回以上使う archive）。

## 4. 差分試験の必須 oracle を 2 実装にしました

**そちらの §10（2 実装では足りない／1 実装では話にならない）は、実測で正しさが出ました。**

```
PAX path の NUL 切り捨てを v0.6.4 の形へ戻す変異
  差分試験（bsdtar のみ）  0 件が落ちる  ← bsdtar も同じく切り捨てるため
  期待値の表              1 件が落ちる
  差分試験（+ python）     1 件が落ちる  ← 2 実装目で初めて割れる
```

**oracle が持つ癖と同じ癖を検算器が持っていると、差分は出ません。**
v0.6.5 からは bsdtar と python tarfile の**両方**を必須にし、
**2 つが違う木を作る archive は受理しません。**

そちらが挙げた差分試験の弱点も 3 つ直しました。

```
展開失敗を「比べようがない＝合格」と数えていた → 受理したのに展開できないなら食い違い
中身を UTF-8 文字列で比べていた              → 生バイトで比べる
剥がした頭を endsWith で推測していた          → 検算器が記録した値で戻す
逆向きの母集団が通常ファイルだけだった          → dir 以外を全部見る
```

**強化した試験が、指摘外でもう 1 件見つけました。**
GNU long name のあとに entry が無いまま終わる archive を v0.6.4 は受理していましたが、
`tar` は `Damaged tar archive` で拒みます。

**GNU tar と BusyBox はまだ入れていません。**そちらの推奨（GNU tar と bsdtar を必須、
python を diagnostic、BusyBox は任意）には届いていません。
