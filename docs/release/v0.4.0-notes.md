## `profileId` は local ビルドから予測できません

この版の作業中に実証しました。**`--release` を付けて作り直すまで確定しません。**

profile の入力には**感度 artifact が含まれます**。感度を `--release` で作り直すと
`artifactKind` が `local` → `release` に変わって bytes が動くので、profile の digest も動きます。

```
入力 24 件のうち変わったもの        2 件
  package-lock.json                 （採番による）
  artifacts/sensitivity.*.json      （local → release）
残り                                22 件は不変
```

感度と頑健性は入力に他の artifact を含まないので、こちらは予測できます。
**profile だけが予測できません。**下流は index から引いてください。

## 窓の端点の test vector（P1-4）

`test/fixtures/topology-robustness/` に 3 件。**どの層が弾くかまで実走で確かめてあります。**

| fixture | schema | 意味検査 | 捕まえた層 |
|---|---|---|---|
| `valid-exclusive-window.json` | PASS | PASS | （通す） |
| `invalid-legacy-toMm.json` | **FAIL** | — | **schema** |
| `invalid-lastSample-equals-endExclusive.json` | **PASS** | **FAIL** | **意味検査** |

**3 番目は schema を通ります。**draft-07 に項目どうしの大小を書く方法が無いので、

窓の規則は `scripts/robustnessWindows.mjs` に切り出し、
**本番の検証と fixture のテストが同じ関数を呼びます**（二重に書くと片方だけ直ります）。

## `package.json` / `package-lock.json` の version 一致（P1-1）

**v0.2.0 から 2 版にわたってずれていました**（`package.json` 0.3.0 / lockfile 0.1.0）。
`npm ci` は止まらないので実害は出ませんでしたが、SBOM・provenance 表示・release tooling が
食い違う版数を見ることになります。

**判定は `check:stale` ではなく `validate:profiles` に入れました。実測して決めています。**

複製したリポジトリで `package.json` の version だけを変えて両方を回すと、

```
check:stale        「重い成果物は現在のモデルと整合しています。再実行は不要です。」 rc=0
validate:profiles  すべて適合 → parity を入れれば鳴る
```

`check:stale` が見るのは `inputDigest` で、**`package.json` は入力ではありません。**
だから version だけ上げても構造的に鳴きません。不一致が 2 版続いたのは、まさにこの経路です。

`package.json` を入力に加える案は採っていません。scripts や依存の範囲指定を直すたびに
全 artifact の digest が動き、**「中身が変わっていないのに ID が変わる」**を自分から作ることになります。

## 検証を回した記録（P1-3）

`source-verification-result.json` を追加しました。**これは自己申告です。**

```
isSelfReport                       true    ← schema で const 固定
replacesRecipientVerification      false   ← 同上
sourceOrigin                       作業ツリー（**tag の source ではない**）
releaseCommit                      null
```

tag は evidence をコミットしてから打つので、生成時点では存在せず、**原理的にここでは検証できません。**
`howToVerifyYourself` に、受け手が自分で回すコマンドを入れました。

### 「自分で検算せよ」と書いたのに、道具を配っていませんでした

v0.3.0 では入力 28 件の独立検算を依頼しながら、**その script も tag source も bundle に
入れていませんでした。**返ってきた `SOURCE_UNAVAILABLE` は正しい報告で、欠陥は指示側にありました。

- `scripts/verifyReleaseSourceInputs.mjs` を**同梱しました**（node 標準のみで単体動作）
- tag source は**この release ページの "Source code (tar.gz)" がそのまま使えます**
- 展開すると `<repo>-<sha>/` が 1 枚かぶります。**剥がし忘れると全件 `MISSING_IN_SOURCE` になり
  「壊れている」と読めてしまう**ので、`--source` がその 1 階層を剥がすようにしました

```bash
node verifyReleaseSourceInputs.mjs \
  --manifest source-input-manifest.json \
  --source <展開した Source code> \
  --scope source-input-scope.v1.json
```

| status | exit | 意味 |
|---|---:|---|
| `OK` | 0 | 全件一致 |
| `MISMATCH` | 1 | 不一致・欠落・**記録漏れの入力** |
| `SOURCE_UNAVAILABLE` | 2 | source を取れなかった。**検証していないだけで、不一致ではない** |
| `MANIFEST_UNAVAILABLE` | 2 | manifest を読めなかった |
| `NOTHING_TO_VERIFY` | 2 | 入力 0 件。**何も見ていないのに OK と言わない** |
