# trs-jack-3d v0.6.2 — 前回の指摘 4 件を直した版の確認

前回の監査（v0.6.1・2026-08-06）で出た **P0 3 件 / P1 1 件を、こちらで反例を再現してから直した**版です。
添付は公開した release asset **28 ファイル**そのものです。

## 0. 添付をどう扱うか

```
28 ファイル / 2.7 MB
SHA256SUMS      27 件ぶんの checksum（自分自身は含まない）
```

**まず `shasum -a 256 -c SHA256SUMS` を通してください。**
こちらでは公開物を取り直して 27/27 OK でした。合わなければ、そこから先は読まなくて構いません。

## 1. 前回の指摘 4 件をどう直したか

**捏造・誤検知は 0 件でした。指摘は全件実在しました。**

### P0-1 — 生成器の依存が `inputDigest` の外にあった

```
再現（v0.6.1 実測）
  scripts/measurementGate.mjs の CLAIM_SCOPE を書き換える
    → profile の中身は変わる（physicalVerificationRef に scope=MUTATED-SCOPE が出る）
    → profileId    38b692a12af6 のまま
    → inputDigest  変わらない
    → 受け手の検算 status=OK / 30 of 30 / 未記録 0 件

直したあと（実測）
    → profileId 6df4546829d9 → aec8c7ea85c5 ／ 検算 MISMATCH 31/32
```

`scripts/contractMigration.mjs`（3 生成器すべてが import）と
`scripts/measurementGate.mjs` を入力へ入れました。入力は **30 → 32 件**です。

**個別のファイル名を並べるだけだと、次に足した `import` で同じ穴が空きます。**
`import` を実際に辿って宣言と突き合わせるテストを入れてあります
（母集団を宣言の外から作るので、直し忘れたらそこで落ちます）。

> **`measurementGate.mjs` を import しているのは profile 生成器だけです。**
> 生成器ごとの依存欄を作ると `source-input-scope.v1` が **`BUMP`**（下流の lock が止まる）に
> なることを判定器で実測したので、`commonInputs` に置きました。
> **入れすぎ（関係ない生成器の ID まで動く）と入れ忘れ（変えても ID が動かない）なら、
> 入れすぎのほうが安全側**です。指摘の「generator 別 dependency set」は採っていません。

### P0-2 — tar の綴り違い・リンク衝突で誤った `OK`

```
再現（v0.6.1 実測）
  root/file.txt = FIRST / root/./file.txt = SECOND   → 両方受理・status OK
  regular root/file.txt + symlink root/file.txt      → リンクを無視して status OK

直したあと
  どちらも ARCHIVE_INVALID（中身は返さない）
```

**正規化して受け入れるのではなく拒みます。**畳んだ先が衝突したときに
どちらを採るかを新たに決めることになるためで、正しい source archive にこの綴りは出てきません。
`.` を含むパス・空のパス要素（`//`・末尾 `/`）・制御文字・
**読み飛ばす entry と同名のファイル**を拒みます。

**塞ぎすぎていないこと**も同じテストで見ています。実物の GitHub tarball は
**246 ファイルのまま**通り、26 個・6 種類の壊れた tar は v6 と同じ結末です。

### P0-3 — validator が現行モデルの予測を再計算しなかった

```
再現（v0.6.1 実測）
  モデルの予測 2.14 mm と 1.45 mm 食い違う記録が台帳にあっても
  couldBeVerified = true（predictions: {} で呼び、「予測が無い」を「true でよい」と読み替え）

直したあと（実測）
  conflicting = 1 / couldBeVerified 相当 = false
  対照: 一致する記録なら verified = true / verdict = VERIFIED のまま
```

配布物だけから予測を組み直します。

| 観測点 | どこから出すか |
|---|---|
| `RING_BREAK_OPEN_DEPTH_MM` / `TIP_BREAK_OPEN_DEPTH_MM` | profile 自身の event 列 |
| `L_FIRST_CONTACT_SHOULDER_GAP_MM` | `real_jack_comparison.json` の `testerPredictions.assumed.L` |

**組み直せない観測点は満たせません**（fail closed）。空で呼ぶのと同じにはしません。
生成器は自分の計算値がこれと一致することを確かめてから書くので、2 つの経路が黙ってずれません
（ずれたら export が落ちます）。

## 2. **schema は 1 本も上げていません。下流はどこでも止まりません**

入力が 30 → 32 件になり、そのぶん ID が動きました。

再生成が provenance しか変えていないことを、葉ノードまで展開して数えてあります。

`IV028` は 13.30〜13.52 mm・`ASSUMPTION` のままです。接点位置も走査結果も同じです。

## 4. 検算ツールが `toolVersion` 7 になりました

**この版でいちばん重い修正です。受け手を直接誤らせる欠陥でした。**

v0.6.1 までは、**検算が見た中身と、ふつうに展開してできる中身が食い違う** archive が
`OK` で通っていました。「合っている」と言いながら別のものを渡せるので、
**checksum を通す意味そのものが無くなります。**

| 直したこと | v7 |
|---|---|
| `.` を含むパス・空のパス要素・制御文字 | `ARCHIVE_INVALID` |
| 読み飛ばす entry（symlink / hardlink / ディレクトリ）と同名のファイル | `ARCHIVE_INVALID` |
| ディレクトリ入力の資源上限 | archive と同じ上限を適用 |

**`status` の種類は増えていません。**`ARCHIVE_INVALID` は v5 のままで、
v1 の自己申告 schema では表現できないままです（既知・→ v0.6.1 notes）。
生成器は表現できない status を丸めずに止まります。

## 6. 次に確かめてほしいこと

### 直したはずのものが本当に直っているか

前回の反例を、**そちらで組み直して**当ててください。こちらの再現を信じないでください。

```
① measurementGate.mjs を 1 byte 変える → profileId と inputDigest が動くか・検算が MISMATCH になるか
② contractMigration.mjs でも同じか
③ root/./file.txt / root//file.txt / 末尾 `/` / 制御文字 → 止まるか
④ 通常ファイルと同名の symlink・hardlink・ディレクトリ → 止まるか
⑤ 矛盾する記録 + 手で verifiedPhysical: true → validator が拒むか
⑥ scope 外の巨大ファイルを置いたディレクトリ → 止まるか・RSS が膨らまないか
```

**⑤ は「予測を組み直せているか」まで見てください。**
`real_jack_comparison.json` を外して呼ぶと予測が組めず、fail closed になるはずです。

### 塞ぎすぎていないか

**正常な入力が弾かれるようになっていないか**を見てください。
特に tar の正規化検査（実物の tarball はディレクトリ entry を含みます）と、
ディレクトリ入力の上限です。**そちらの環境の archive で試してください。**

### 依存閉包の取り方が足りているか

`import` を静的に辿る方式です。**動的 `import()` や設定ファイル経由の依存は辿れません。**
この方式で漏れる経路が思い当たれば教えてください。
また `measurementGate.mjs` を `commonInputs` に置いた判断（入れすぎ側へ倒した）が
妥当かも見てください。

### まだやっていないこと（指摘は不要です。**分かっています**）

- **実測が 1 件も来ていません。**ジャック内部の接点位置は全部仮定です。
- **導通測定も音響測定もしていません。**
- 物理検証の evidence asset と、profile への `evidenceSources` 出力。
  **どちらも「最初の実測記録が入る前に」という条件つきで、その条件がまだ来ていません。**
- annotated tag への署名。
- `source-verification-result` の v2 化（`ARCHIVE_INVALID` を表現できるようにする）。
- 検算ツールの強化は**試験した範囲まで**です。**すべての細工に耐えることは示していません**
