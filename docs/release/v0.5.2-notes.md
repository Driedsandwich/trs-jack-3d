## 直したもの — 判定器の危険側の誤判定 3 件

外部監査（第2回）が ajv 付きの反例を出しました。**3 件とも危険側**でした。

| 反例 | v0.5.1 の判定 | 正しい判定 |
|---|---|---|
| `$ref` に sibling があると参照変更を見落とす | **`HOLD`・差分 0 件** | `BUMP` |
| schema 型 `additionalProperties` へ項目を足す | `HOLD_RECORD` | `BUMP` |
| `patternProperties` があるのに項目を消す | `HOLD_RECORD` | `BUMP` |

**live な schema で踏みます。**`$ref` sibling は profile v1/v2/v3 の `evidenceGrade` に **3 件**、
schema 型 `additionalProperties` は **43 件**。`patternProperties` は現在 0 件です。

**v0.5.1 の結論は汚染されていません。**判定器を使わない byte 比較で、
v0.5.0 → v0.5.1 の schema 20 本に **1 バイトも差が無い**ことを確認しました。

## 直し方を変えました — 個別対応から allowlist へ

`oneOf` を直した直後に同じ形が 3 つ出ました。**1 つずつ塞ぐ形では、
列挙漏れがそのまま危険側の穴になります。**

> 判定器が正しく扱えると宣言した keyword の集合（`HANDLED_KEYWORDS`）を決め、
> **宣言外の keyword が「在る」だけで**（かつその節が新旧で変わっていれば）`UNDEC` へ倒す。
> 「変わったら倒す」ではありません——**変わっていない keyword が
> 他の keyword の意味を変える**ためです（`patternProperties` がまさにこれ）。

宣言集合は**現行 schema が実際に使う keyword を機械で数えて**決めました。
`patternProperties` / `dependencies` / `if` / `not` などは**意図的に宣言外**です。
**宣言外の keyword が schema に現れたらテストが落ちます。**

## 実装中に見つけた 4 件目

**節は同じまま参照先だけ変わる**場合が、どちらの網にもかかっていませんでした。
allowlist ゲートは「その節が変わっていれば」倒すので節が同じだと鳴らず、
`deref()` は sibling があると辿りません。回帰試験に入れて直しました。

## 回帰試験

| | 内容 |
|---|---|
| ① | ajv で、新だけが通す値が実在すること（＝包含していない事実） |
| ② | **`v0.5.1` tag の実物を読み込んで** 3 件とも危険側を返すこと |
| ③ | 現在の実装が `BUMP` を返し、**差分も出す**こと（`$ref` の件は差分 0 件だった） |
| ④ | 宣言集合が現行 schema の keyword をすべて覆い、かつ**全部入りではない**こと |
