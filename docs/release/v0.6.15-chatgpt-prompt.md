## 3. **catalog が「出る」と言っているかを、両方向で照合します**

そちらの `reachability: external-fixture | cli-route | defensive-invariant |
deprecated | miswired` を採り、`corpus` を足した 4 値にしました。
**これは宣言なので、そのままでは信じません。**

```
到達すると宣言した code   → この run で**実際に出た**ことを確かめる
到達しないと宣言した code → この run で**出ていない**ことを確かめる
```

**片方向だけだと逃げ道が残ります**——宣言を `defensive-invariant` へ
書き換えるだけで、どんな未配線 code も「合格」にできてしまう。

```
catalog 80 種類 = corpus 45 / cli-route 27 / defensive-invariant 8
この run で実際に出た 72 種類
出ないと宣言した 8 種類（出ていないことも実測）:
  ROOT_STRIP_NOT_A_DIRECTORY / HEADER_NUMERIC_FIELD_RANGE / HARDLINK_CHAIN_UNRESOLVED
  SOURCE_ARCHIVE_MISSING / SOURCE_GIT_ARCHIVE_FAILED / SOURCE_FETCH_FAILED
  SOURCE_HTTP_ERROR / SOURCE_BODY_UNREADABLE
```

**fixture は corpus 本体へ入れました。**そちらが挙げた 10 種類のうち 8 種類は
壊れた tar で踏めるので、corpus を **182 個 19 種類 → 190 個 20 種類**にしています。
残り 2 種類（本文の上限・総量の上限）は CLI の経路なので、
**limit injection** で踏みました——264 MB の材料は作っていません。
圧縮サイズの上限だけは読む前の `statSync` で見ているので、
**疎ファイル**（実容量 0 バイトで 64 MB を名乗る）を渡しています。

**そちらの再分類 5 件は、4 件そのまま採り、1 件は採りませんでした。**

| code | そちらの分類 | こちらの実測と処置 |
|---|---|---|
| `ROOT_STRIP_NOT_A_DIRECTORY` | shadowed-invariant | 同じ（`ANCESTOR_TYPE_CONFLICT` が先に止める）→ defensive |
| `HEADER_NUMERIC_FIELD_RANGE` | 到達不能 | 同じ → defensive |
| `HARDLINK_CHAIN_UNRESOLVED` | 到達不能 | 同じ → defensive |
| `SOURCE_DIRECTORY_UNREADABLE` | miswired | 同じ。**status を `SOURCE_UNAVAILABLE` へ直して配線**した |
| `SOURCE_SPECIAL_NODE` | catalog-only-alias | 同じ。**削除ではなく実装を配線**した |

最後の 1 件だけ判断が違います。**archive の typeflag（決めていない型）と、
実在するノード（FIFO・socket・device）は別物**なので、名前を分けたまま配線しました。
受け手が「archive の中身の話」と「渡された directory の話」を読み分けられます。
