# trs-jack-3d v0.6.4 — 前回の指摘 3 件を直した版の確認

前回の監査（v0.6.3・2026-08-06）で出た **P0-A / P0-B / P0-C を、こちらで反例を

## 0. 添付をどう扱うか

```

```

**まず `shasum -a 256 -c SHA256SUMS` を通してください。**

## 1. 前回の指摘 3 件をどう直したか

**捏造・誤検知は 0 件でした。指摘は全件実在しました。**

GNU tar が手元に無いので、**bsdtar 3.5.3（libarchive 3.7.4）と Python 3.14 の `tarfile`**
の 2 実装を oracle にして再現しました。そちらの GNU tar 1.35 とは別の実装です。

> **どれが「正しい」かを決める必要はありません。実装間で結末が割れること自体が欠陥です。**
> 指摘のうち「参考」扱いだった `GNU L → PAX path=` も、こちらの実測では
> **検算が bsdtar と python の両方と食い違って**おり、P0 と同じ扱いにしました。

### P0-A — 同じ member に名前の上書きが 2 つ効くと、結末が割れていた

v0.6.3 は PAX の `path=` を解釈するようにしましたが、GNU long name（`L`）と
**同じ変数へ後勝ちで**置いていました。

```
再現（v0.6.3 実測・3 者で同じ archive を読む）
                            検算 v8    bsdtar     python
  PAX path= → GNU L         gnu.txt    pax.txt    pax.txt   ← 両方と食い違う
  GNU L → PAX path=         pax.txt    gnu.txt    gnu.txt   ← 両方と食い違う
  PAX path= を 2 回          two.txt    拒否       one.txt   ← 三者が全部違う
  PAX path= → PAX x(mtime)  pax.txt    拒否       pax.txt

直したあと
  4 つとも ARCHIVE_INVALID
```

上書き機構が 2 つ効いたら止めます。global header（`g`）が `path` を持つ場合も止めます。

**denylist を延ばす方向は採っていません。**「意味を変える鍵」を数え上げ続けるより、
**上書きが競合したら読まない**ほうが面積が小さいと判断しました。

### P0-B — 展開されるのに、検算の母集団から消える entry があった

v0.6.3 は通常ファイル（`typeflag 0`）だけを内部の Map に入れ、
**未記録入力の探索もその key しか見ていませんでした。**

**配布中の v0.6.3 の道具で直接確かめた実測です。**

```
scope 配下（src/model/）に symlink を仕込んだ source archive を渡す
  v0.6.3  status OK        未記録候補 []                      exit 0
  v0.6.4  status MISMATCH  未記録候補 ["src/model/sneaky.ts"]  exit 1
  対照     正常な source     未記録候補 0 件                     exit 0
```

`typeflag 7`（contiguous）も同じ形で、bsdtar と python はどちらも
**通常ファイルとして展開**します。

直し方は**全 entry の型つき一覧（inventory）**を作り、範囲の完全性検査は
そちらを母集団にする形です。指摘の 2 案のうち「typed inventory」を採りました。

```
止める    typeflag 7 / S / D / M / N（中身を持つのに扱いを決めていない）
止めない  symlink / hardlink / ディレクトリ
          → **正当な archive にも出てくる。**止める代わりに「見える」ようにした
```

### P0-C — パスの不正なバイトが U+FFFD へ置換されていた

```
再現（v0.6.3 実測）
  raw   root/file<FF>.txt
    検算 v8  root/file<FFFD>.txt を検証して status OK
    bsdtar   生バイトのまま扱う（別のファイル名）
    python   生バイトのまま扱う（別のファイル名）

直したあと
  ARCHIVE_INVALID
```

`TextDecoder('utf-8', { fatal: true })` で読み、読めなければ止めます。
USTAR の `name` / `prefix`、GNU long name、PAX の鍵、PAX の `path` に効かせています。

> **値を一律に厳密化してはいけません。**指摘のとおり全部へ適用したところ、
> **実物の macOS `tar` が作った tarball を弾きました**——
> `LIBARCHIVE.xattr.*` / `SCHILY.xattr.*` に**生バイナリ**が入るためです。
> **v8 でも同じ形の塞ぎすぎをやっており、2 回目です。**
> 解釈する値（`path`）だけ厳密にしています。

## 2. 差分試験が片方向だったので、逆向きを足しました

**これが今回いちばん重い発見です。**

v0.6.3 で入れた「実展開との差分試験」は、**検算器が返した key を展開木で探す**方式でした。
これは **「展開されるのに検算器が数えない」欠陥を見られません。**

```
実測: typeflag 7 の検査を外す変異を入れても、片方向の 48 件は 1 件も落ちなかった
```

**材料も検査もあったのに、向きが片方だったので素通りしました。**
v0.6.3 の notes では「次の見落としは人が期待値を間違える形では起きにくくなった」と
書きましたが、**期待値ではなく検査の向きに穴がありました。**

逆向きの要件を足しています。

```
展開してできた通常ファイルは、検算器の files か inventory のどちらかに
現れていなければならない。どちらにも無いなら、
**検算器から見えていないファイルが source に混じる。**
止まった（ARCHIVE_INVALID）なら合格。
```

どの検査が効いているかは、1 つずつ外して測りました。

| 外した検査 | `tarHardening` | 実展開 oracle |
|---|---:|---:|
| 名前の上書きが 2 つ効く形を止める | 3 | 2 |
| 中身を持つ未対応 type を止める | 2 | 0 |
| パスの厳密 decode | 3 | 3 |
| inventory に全 entry を載せる | 0 | 2 |

**どちらか一方の試験だけでは足りません。**上 2 つと下 2 つで、捕まえる側が入れ替わります。

壊れた tar の材料は **26 個 6 種類 → 39 個 8 種類**に増えました。
