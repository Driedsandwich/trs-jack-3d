## 2. **根は 1 つで、逃げ道が 6 本ありました。そちらが当てたのは 4 本です**

`return node` は「確かめて同じだった」ときと**まったく同じ形**なので、
**新旧そろって同じ位置で諦めると写しが一致します。**

v0.6.22 の実装（`v0.6.22 tag の scripts/schemaLanguageDiff.mjs:115`）:

if (!t || typeof t !== 'object' || '__unresolvable__' in t) return node

## 3. **一律に「変わった」へ倒すと、同一 schema 同士の比較が壊れます**

素直な直し方は「諦めたら BUMP」です。**それをやると、深いだけの schema を
自分自身と比べても落ちます**——条文が使えなくなります。

そこで**諦めが起きたときだけ、より粗い比較へ落とす**形にしました。

```
162  function sameShape(a, b, aroot, broot) {
     …写しが違えば false（変わった）
     …写しが同じで、諦めが 0 件なら true（同じ）
168    return JSON.stringify(aroot) === JSON.stringify(broot)   ← 諦めた場合だけ root を丸ごと比べる
```

まったく同じなら言語も同じなので「同じ」、違えば決められないので「違う」側へ倒します。
条文 ①-c9 ③・①-c11 ③・①-c12 ② で、**同一入力なら HOLD のまま**であることを固定しました。

**解決できるものは解決します**（E5 の復号・E4 の boolean 展開・E6 の位置ごと比較）。
**諦めを減らすほど、粗い比較へ落ちる回数が減って誤検出も減ります。**

## 4. **変異対照で 3 本が「外しても落ちない行」でした**

直した箇所を 1 つずつ戻して測ったところ、**3 本は消しても全件通りました。**

**消しても落ちない行は、入れた証拠がありません。**
そこで**その経路に実害があるかを先に測って**から試験を足しました。順序は
①ajv で実害を確かめる → ②試験を書く → ③もう一度変異で戻して落ちることを見る、です。

- **E1**：そちらの反例（55 段）は `deref` の反復上限（E3）を**先に**踏んでいました。
  `oneOf` の枝の中で 60 段ネストし、その奥に `$ref` を置くと E1 を踏みます。
  ajv で「奥が `null` の値」が旧 invalid → 新 valid になることを確かめました。
- **E2**：反例をもらっていません。**循環がある schema は保守側へ倒す**という
  振る舞いそのものを固定しました。
- **E5**：§5 のとおりです。

## 5. **E5（RFC 6901 の復号）は、安全のためでなく精度のためです**

`#/definitions/a~1b` は `definitions["a/b"]` を指します（`~1` = `/`・`~0` = `~`）。
復号していませんでした。

**復号しなくても危険側の誤りは出ません。**解決に失敗して諦めるので、
§3 の root 比較へ落ちて BUMP になります。**だから変異で消しても何も落ちませんでした。**

害は別のところに出ます。**escaped `$ref` を使う schema は、参照先が変わっていなくても、
無関係な definition が動くたびに BUMP になります。**
復号して初めて「変わっていない」と言えるようになります。

その精度を固定する試験を別に書きました（条文 ①-c8 ⑤。
escaped `$ref` があり参照先は不変・無関係な definition が増えた対で **HOLD** を要求します）。

> **安全側に倒れる修正は、変異対照では守れません。**
> 「消しても落ちない」を見たときに、**安全のためか精度のためかを分ける**必要がありました。
> これは今回いちばん学んだことです。
