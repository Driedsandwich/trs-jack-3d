## v0.4.0 の known issue を直しました

**`test_counts.json` の `allPassed` が `false` のまま公開されていました。**
実際は 467 件すべて通っており、`total` / `byFile` / `skipped` は正しい値でした。

原因は生成の順序です。テストが 2 件落ちている時点で `npm run test:count` を回し、
そのあと 2 件を直したが**件数を取り直さなかった**。件数は変わらなかったので、
`total` を突き合わせる既存の検査は通ってしまいました。

### 生成は止めず、配布を止めます

**「テストが落ちている間は件数を更新できない」という循環に戻したくない**ので、
生成側（`npm run test:count`）は今も落ちても続行します。
循環が起きるのは生成側だけなので、**止めるのは配布側**にしました。

| | |
|---|---|
| `npm run test:count` | テストが落ちても件数を書く。ただし `failed` / `exitCode` も同じ実行から記録する |
| `npm run release:evidence` | `NOT_READY` でも evidence を書く（判定を残すため）。生成は止めない |
| `npm run release:stage` | **`allPassed !== true` を拒否する。**`--allow-not-ready` で回避できるが配布してはいけない |

`test_counts.json` に足した項目:

```
failed / failedSuites / exitCode / testCommand
runner / runnerVersion / nodeVersion / generatedFromCommit
```

`validation-results.json` は判定を 2 つに分けました。

```
artifactValidationStatus   artifact の形と意味が正しいか
releaseReadinessStatus     release として配ってよいか（+ releaseReadinessReasons）
testEvidence               突き合わせた test の結果
```

**v0.4.0 は前者が PASS で後者が NOT_READY だった状態です。**両者を見ていませんでした。

## README が一度も正しくなかったので、機械照合を入れました

Half-Plug 連携の節は、**v0.1.1 から v0.4.0 まで一度も現行の配布物を案内していません**でした。

| tag | README が案内していた配布物 |
|---|---|
| v0.1.1 | v0.1.0 |
| v0.2.0 / v0.3.0 / v0.4.0 | v0.1.1 |

「release のたびに直す」手順が無いのが原因なので、文言を直すだけでは同じことが起きます。
`test/docs.test.ts` が次を突き合わせます。

- 配布物の版数とリンク先の tag が `package.json`（= `release:stage` の既定）と一致する
- profile schema 版とファイル名が artifact と一致する
- **旧版が本文に 1 箇所でも残っていたら落ちる**（`### 過去 release の known issue` の節だけ除外）
- 除外範囲が広すぎないこと自体も検査する

> 最初に書いた検査は**図の書き換えを素通り**しました。`toContain` は 1 箇所でも残れば通り、
> 除外範囲も節を越えて広がっていたためです（本文の 19% が検査の外にあった）。
> 変異 7 件すべてで落ちることを実測してから採用しています。

## 検証ツールから `gh` 依存を外しました

v0.4.0 では `--fetch github` が `gh api` を呼んでいました。
**受け手の環境に `gh` が無く、`spawnSync gh ENOENT` で `SOURCE_UNAVAILABLE` になりました。**
判定としては正しい（取れなかったことを不一致に潰していない）のですが、
**配った道具の network 経路が使えないままでした。**

Node 18 以降は `fetch` が組み込みなので、外部コマンドは要りません。

```bash
node verifyReleaseSourceInputs.mjs --manifest source-input-manifest.json \
  --tag v0.4.1 --fetch github --scope source-input-scope.v1.json
```

`gh` がある環境と無い環境の両方で実行し、**どちらも 29/29 一致・結果が同一**であることを確認しました。
使う外部コマンドは `git archive` / `git rev-parse` の 2 つだけになりました。

## `toolVersion` を全ての出口に入れました

v0.4.0 では成功・不一致の出口にしか入れておらず、
`SOURCE_UNAVAILABLE` / `MANIFEST_UNAVAILABLE` / `NOTHING_TO_VERIFY` の 3 経路には
入っていませんでした。**受け手が記録を保存しても、どの版の道具の出力か判別できません。**

各出口へ手で足すと出口が増えたときにまた忘れるので、**出力の通り道 (`done()`) で入れています。**
`TOOL_VERSION` は 2 → **3**。
