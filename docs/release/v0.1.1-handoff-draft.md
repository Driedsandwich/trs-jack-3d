## 2. 実装した内容（オーダー P0-1〜P0-4）

- **`scripts/sensitivityEvents.ts` を新設。**variant ごとに event spread を測り、
  `variantId` / `analysisScope` / `sweptParameters` / `generatedFromCommit` /
  `basis: MODEL_PARAMETER_SWEEP` を記録します
- **exporter は `variantId` が profile と一致しなければ取り込みません（fail-closed）。**
  一致しなければ `spreadMm: null` / `spreadStatus: NOT_ANALYZED` /
  `sensitivitySummary.available: false`、notes に理由を書きます
- **3極の総合解析**（プラトー間隔・Tip 橋絡しきい値・挿抜力）は 3極 variant でのみ出力します。
  TRRS では `bridgeDepthJointRangeMm` 等が `null` になります
- `sweptParameters` を直書きせず artifact の記録から取ります
- **`inputDigest` を variant 別にしました**（P1-2）

### `spreadStatus` を改名しました（**破壊的変更**・オーダー P1 を前倒し）

| 旧 | 新 |
|---|---|
| `MEASURED` | `MODEL_SWEEP_EVENT_SPECIFIC` |
| `NOT_EVENT_SPECIFIC` | `MODEL_SWEEP_NOT_EVENT_SPECIFIC` |
| `NOT_MEASURED` | `NOT_ANALYZED` |

オーダーでは schema v2 送りでしたが、**`MEASURED` を残したまま v0.1.1 を出すと
同じ誤認が続く**ため、今回入れました。schema v1 のままです（enum の値だけが変わります）。

## 4. 用語の補強（オーダー §6）

- **`fully-seated` は「肩が当たった」ではありません。**`reasonCode` のとおり
  `ALL_EXPECTED_FUNCTIONS_MATCH`（機器が期待する全機能が正しい導体に届いた）です。
  TRS×TRRS では 13.52 mm から始まりますが、機械的な完全挿入は 14 mm です。
  Schema v1 の間は名前を変えず、v2 で `electrically-normal` 等への改名を検討します
- **`normalized` の説明を弱めました。**「機種横断では normalized を使う」は強すぎました。
  profile 内の相対座標であり、**profile 横断で同じ電気状態を保証しません**。
  同一 profile 内の UI 位置と、profile 更新時の候補再探索にのみ使ってください

## 5. こちらの検査が捕まえなかった件

**指摘の価値はここにあります。**意味規則を 45 本書いていましたが、
構造（一意性・連続性・存在）ばかりで、**記録された値どうしの整合をほとんど見ていませんでした。**

同種の抜けを数えたところ、**候補 12 件のうち 11 件が素通り**していました。
今回 8 件を追加しています（すべて変異させて落ちることを確認）。

とくに **`provenance.inputFiles[].sha256` が実ファイルと一致するか**を
一度も検査していませんでした。provenance の話は全部これに乗っているので、
ここが嘘なら `inputDigest` も再計算も無意味になります。
