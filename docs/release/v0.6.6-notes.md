# v0.6.6 — **schema は 1 本も上げていません。下流はどこでも止まりません**

## ⚠ 先に読むところ

### 1. **v0.6.5 は、正当な archive を 2 種類拒んでいました**

**受け手に直接影響するのはこちらです。**

```
GNU の長い linkname（K ヘッダ）
  検算 v10  ARCHIVE_INVALID — 「. を含む entry がある」
  GNU tar / bsdtar / BusyBox / python   4 実装すべて展開できる

PAX の linkpath
  検算 v10  ARCHIVE_INVALID — 「受け入れていない鍵がある: linkpath」
  4 実装すべて展開できる
```

`K` は**分岐そのものが無く**、`K` ヘッダ自身の名前 `././@LongLink` が
正規化検査に当たって落ちていました。`linkpath` は allowlist に入れ忘れです。

**v0.6.5 で別の repo の archive を検算して `ARCHIVE_INVALID` が出ていた場合、
それは archive の欠陥ではなく、こちらの誤検知だった可能性があります。**
該当するのは、**長いシンボリックリンクの指す先を持つ archive**です。
`v0.6.6` で取り直してください。

> **正当な archive を拒む欠陥は、これで 2 版続けてです**（v0.6.4 は独立した 2 つの member が
> それぞれ長い名前を使うだけで拒んでいました）。**「実物が通る」確認では見つかりません**——
> この repo の実物は最長パス 95 文字で、これらの機構を使わないためです。

### 2. 誰も展開できない archive を、まだ受理していました

```
自分自身を指す hardlink（root/self -> root/self）
  検算 v10  status OK / 32 件中 32 件一致 / 未記録 0
  bsdtar    exit 1 — Skipping hardlink pointing to itself
  python    KeyError: linkname 'root/self' not found

ディレクトリを指す hardlink（root/hdir -> root）
  検算 v10  status OK
  bsdtar    exit 1 — Can't create 'root/hdir': Operation not permitted
```

1 つ目は **この entry の名前を先に控えていた**ため、自分を指すリンクが
「指す先が在る」と判定されていました。2 つ目は「名前が在るか」しか見ていませんでした——
**hardlink は通常ファイルにしか張れません。**

### 3. 手元では確かめられなかった 2 件も直しました

**この 2 件は、こちらの 2 実装（bsdtar 3.5.3 / python 3.14）が検算器と同じ答えを返します。**
監査は GNU tar が拒むと報告していますが、**こちらでは確かめられていません。**

```
PAX の値が読めない（uid=abc / mtime=abc / atime=nan / ctime=1e999）
  検算 v10  status OK        bsdtar exit 0    python exit 0
  （監査側の GNU tar は exit 2 — Malformed extended header）

中身を持てない型に本体がある（type 5 で size≠0）
  検算 v10  status OK        bsdtar exit 0    python exit 0
  （監査側の GNU tar は exit 2、BusyBox は exit 1）
```

**それでも直したのは、構造として理屈が立つからです。**

- 値が読めない PAX は、**「view を変えない鍵だから通す」という v0.6.5 の理屈を崩します。**
  その理屈は値が読める前提に乗っていて、読めなければ読み手の挙動は決まりません。
- 中身を持てない型に本体があると、**読み手がその本体を読み飛ばすかどうかで、
  その先の解釈が丸ごとずれます。**1 個の entry の問題では済みません。

**「監査がそう言ったから直した」ではありません。**確かめられなかったことは、
そのままここに書いてあります。

### 4. 意図して受け入れていない形（変えていません）

```

**どちらも「壊れている」とは言っていません。**理由文に何が起きたかが書いてあります。

### 5. `profileId` が変わりました。**lock を作り直してください**

```
v0.6.5  trs-jack-3d:TRS|JACK-TRS:df6244796ab5
v0.6.6  trs-jack-3d:TRS|JACK-TRS:4874b63082e9

v0.6.5  trs-jack-3d:TRS|JACK-TRRS:e5dd0a0a92a4
v0.6.6  trs-jack-3d:TRS|JACK-TRRS:4998389a40e4
```

**この文書から転記せず、同梱の `trs-jack-3d-release-index.v1.json` から引いてください。**

**動いた原因は版数上げ（`package-lock.json`）です。**検算ツールは配布物ですが
**入力ではない**ので、そちらは digest を動かしません。

**モデルの数値は変わっていません。**葉ノードまで平坦化した実測です。

```
TRS   葉 2267 件 → 由来まわりの差 10 件 / モデル数値の差 0 件
TRRS  葉 3130 件 → 由来まわりの差 10 件 / モデル数値の差 0 件

この比較が「全部を由来に寄せているだけ」ではないことも確かめてあります——
`fullInsertionDepthMm` を 14 → 14.001 に変えると **「モデル数値の差 1 件」**になります。
