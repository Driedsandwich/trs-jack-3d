## 2. **根は 1 つで、置き場所が 3 か所ありました。前の版で直したのは 1 か所目です**

判定器は「**節の文字列が変わっていない**」を「**意味が変わっていない**」の証拠にしていました。
`$ref` は参照先を指すだけなので、**指す先が変われば文字列は同じまま意味が変わります。**
v0.6.21 の `expandRefs()` は `$ref` が**唯一の key のときしか展開せず**
（`v0.6.21 tag の scripts/schemaLanguageDiff.mjs:103`
`if ('$ref' in node && Object.keys(node).length === 1) {`）、
`{ $ref: '#/definitions/d0', description: 'branch' }` は展開されないので
**参照先の変更が見えません。**その置き方が 3 か所にありました。

```
                                           直した版   見つけた人
oneOf の枝の比較                            v0.6.21   こちらの property-based 試験
同上・**枝に sibling がある形**              **この版**  **そちら**
allowlist ゲート（未対応 keyword が包む）     **この版**  **そちら**
anyOf / allOf の早期 continue               **この版**  こちら（§3）
```

**2 か所目には、条件がもう 1 つ効いていました。**未対応 keyword が在っても
**その節が新旧まったく同じなら倒しません**（同一 schema 同士の比較まで BUMP になるのを
避けるため）。反例 2 の `definitions.outer = { not: { $ref: … } }` は**新旧完全に同一**なので、
**同じ節を同じにしておけば検査を免れる**形でした。直し方は 1 つにまとめ、「変わったか」を
見る箇所を全部、参照先まで展開した写しで比べます。**片方だけ残すと、残さなかったほうの
変化が見えなくなります**（`__refTarget__` は JSON Schema の keyword ではないので衝突しません）。

```
v0.6.22 の scripts/schemaLanguageDiff.mjs

           return { ...expandRefs(rest, …), __refTarget__: target }

             JSON.stringify(expandRefs(a, aroot)) === JSON.stringify(expandRefs(b, broot))

  409      if (JSON.stringify(ol) === JSON.stringify(nl) && sameShape(ol, nl, oroot, nroot)) continue
```

——**①が通ることが大事です。**反例の前提（旧 invalid → 新 valid・枝の文字列は同一）が

## 11. 反例のもらい方について（お願い）

前回いただいた形が、こちらにとって一番効きました。

```
fixtures を最小 schema 対で         → そのまま回帰試験へ入れられる
ajv の真値（旧 invalid → 新 valid） → 前提が崩れていないか先に確かめられる
実行コマンドと期待出力              → 「再現できない」で終わらない
なぜ現行の試験が見逃すかの分析      → **直す範囲が「反例 2 件」でなく「型」になる**
```

**4 つ目がとくに効きました。**`currentFuzzCandidateCheck` で「候補値 19 件に nested null が無い」
と書いてくださったので、**判定器だけでなく試験の側も直す**判断ができました。それが無ければ、
反例 2 件を通すだけで終わっていたはずです。今回も同じ形でいただけると助かります:

- **判定器の 3 か所を直しましたが、4 か所目が無いと言い切れません。**数えて 3 つでしたが、
  数え方そのものが漏れている可能性があります。
- **`synth()` は深さ 3 で打ち切ります**（`test/_schemaFuzz.mjs:257`）。
  それより深い位置にしか作れない証人があれば、いまも見逃します。
- **`$ref` + sibling の扱いは Draft-07 の意味論とは違います。**Draft-07 は sibling を無視しますが、
  こちらは**変化検出のため両方を残して安全側へ倒しています**（`__refTarget__`）。
  この保守側の倒し方で困る場面があれば教えてください。
