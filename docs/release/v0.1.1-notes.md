**v0.1.0 の TRS×TRRS 感度情報の誤りを直した緊急修正版です。**

## 何が誤っていたか

`scripts/sensitivity.ts` は解析基準を `TRS|JACK-TRS` に固定しています。
ところが exporter は variant を問わず単一の `artifacts/sensitivity.json` を読み、
その `eventSpread.byKind` を**どの profile へも配っていました。**

```
TRS×TRS   FIRST_BREAK_OPEN  名目 8.06 mm  幅 8.06〜8.06 mm   一致
TRS×TRRS  FIRST_BREAK_OPEN  名目 8.48 mm  幅 8.06〜8.06 mm   ← 名目値が幅の外
```

**名目値が自分の幅の外にある**のは、その幅が別のモデルのものだからです。

> 2026-08-03 の修正で「`kind` 単位の集計を事象へ配るな」は直しましたが、
> **「別 variant の解析を流用するな」を見落としていました。**同じ根の、より深い層です。

## 直したこと

| | v0.1.0 | v0.1.1 |
|---|---|---|
| TRS×TRRS の `FIRST_BREAK_OPEN` の幅 | 8.06〜8.06（**3極の値**） | **7.82〜8.64**（4極を測り直した値） |
| 振った寸法 | `jack.contact.sleeve.*`（3極のキー） | **`trrs.jack.contact.*`** |
| `bridgeDepthJointRangeMm` 等 | 3極の値が入っていた | **`null`**（3極の解析なので出さない） |
| `inputDigest` | 両 variant で同一 | **variant ごとに別**（片方を測り直しても他方の ID は変わらない） |

- `scripts/sensitivityEvents.ts` を新設し、**variant ごとに**測るようにしました
- exporter は **`variantId` が profile と一致しなければ取り込みません（fail-closed）**
- 3極の総合解析（プラトー間隔・Tip 橋絡しきい値・挿抜力）は 3極 variant でのみ出力します

## ⚠ 破壊的変更 — `spreadStatus` の語を変えました

**`MEASURED` は実物の測定と誤認されます。**実際にはモデルのパラメータを振った結果です。

| 旧（v0.1.0） | 新（v0.1.1） |
|---|---|
| `MEASURED` | **`MODEL_SWEEP_EVENT_SPECIFIC`** |
| `NOT_EVENT_SPECIFIC` | **`MODEL_SWEEP_NOT_EVENT_SPECIFIC`** |
| `NOT_MEASURED` | **`NOT_ANALYZED`** |

`sensitivitySummary.basis` にも `MODEL_PARAMETER_SWEEP` と記録しています。

**`profileId` も変わります**（`inputDigest` が variant 別になったため）。
`intervalId` / `eventId` は `profileId` とセットで保存し、
`profileId` が違ったら `electricalTopology.topologyClass` と `normalizedStart/End` で
引き直してください。

## ⚠ この profile は実物を測ったものではありません

| | |
|---|---|
| `verifiedPhysical` | **`false`**（v0.1.0 から変わりません） |
| 導通の実測 | **未実施** |
| 音響の実測 | **未実施** |
| 4極ジャックの接点の軸方向オフセット | **ASSUMPTION**（一次資料なし） |

**実在資料 2 件が逆を指しています。** pro-SIGNAL PS000001 の断面図（Tip 接点 12.75 mm）を
入れると左右差分の区間は **1 件も出ません**。Lumberg 1503 28 の端子位置（11.30 mm）では出ます。
結論は Tip 接点が 12.6 mm より浅いことを必要条件にしており、**PS000001 はその外側**です。
どちらが実物に近いかは決着していません。

## 固定のしかた

**`provenance.inputDigest` を使ってください。**`sourceRevision` や `main` では固定しないでください。

```
TRS|JACK-TRS   inputDigest = ea318f0c5b6c8cc3b4d6d13f506ad7f425fc5709b4fafc537e44c976a38268c3
TRS|JACK-TRRS  inputDigest = 49b2ef8d7a13eae15a161dff1382b948cd780deee0333ab669d6e2c88a9935db
generatedFromCommit        = eeda5f1c28b9223430606de61dbbb1f9f8f19d2a
```

`provenance.inputFiles[]` から再計算して検算できます。

```bash
jq -j '.provenance.inputFiles | sort_by(.path) | map("\(.sha256)  \(.path)") | join("\n")' \
  half_plug_topology_profile.v1.trs_jack_trrs.json | shasum -a 256
```
