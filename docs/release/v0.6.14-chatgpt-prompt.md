## 2. 止め方の名前を catalog へ一本化しました

`REASON_CODES`（**55 種類**・`code → status / family / summary`）を新設し、
**配布物 1 ファイルに同梱**しています。

```
ArchiveInvalid / ArchiveUnsupported
  catalog に無い名前   → その場で投げる
  名前を付けない       → その場で投げる
  status が食い違う    → その場で投げる
{ kind: 'ARCHIVE_*' } の直書き 3 か所 → archiveError() へ集約し、kind は catalog から引く
```

**status の食い違いを止めるのは、受け手が「壊れている」と「範囲の外」を読み分けるためです。**
`ARCHIVE_UNSUPPORTED` の code を `ArchiveInvalid` で投げると、その区別が崩れます。

> **catalog を別ファイルに置いて、こちらの試験に捕まりました。**
> この道具は 1 ファイルで配るので、node 標準以外を import すると配布物が動きません
> （`検証ツールが単体で動く（リポジトリ内の他ファイルを import していない）`が捕捉）。本体へ移しました。

> **catalog の `status` 欄を名前から推測して書き、1 件間違えました。**
> `EXTENSION_HEADER_SEQUENCE_UNSUPPORTED` は名前に反して `ARCHIVE_INVALID` です。
> 突合を一時的に外して 37 種類の実際の status を集め、**実測に合わせました。**

## 3. **corpus は catalog の 55 種類のうち 37 種類しか踏みません**

これを**毎 run 出力**します。覆えていない範囲を隠さないためです。

```

corpus が踏む code    37 種類
```

**「corpus で `*_OTHER` は 0 件」は真ですが、それは corpus が踏んだ経路についてだけです。**
v0.6.13 まで、こちらはこの区別を書かずに「0 件」とだけ言っていました。

なお、v0.6.13 までの棚卸しでは `stableReasonCode:` という正規表現でソースを数えて
「49 種類」と出していましたが、**別の書き方をしている `PATH_EMPTY_NAME` などを取りこぼして**いました。
**自作の読み手が 3 度誤読したので、走らせて集める方式に変えました。**

## 4. `toolVersion` を 17 へ上げました。**v0.6.13 の判断は撤回していません**

```
v0.6.13  入口の判定をファイル名から realpathSync へ変えた
         → 正規の名前での出力は v0.6.12 と **byte 一致**
         → 黙る経路は JSON を 1 バイトも出さないので toolVersion を出さない
         → **16 に据え置いた。これは今も誤りだと思っていません**

v0.6.14  判定の出力そのものが変わる
         ARCHIVE_INVALID_OTHER → GZIP_DECODE_FAILED など
         → **受け手が機械で分岐する値が変わるので、規則どおり 17 へ**
```

そちらの推奨（「次版で 17」）と結論は同じですが、**理由は違います。**
入口の変更が observable contract だから、ではなく、**今回の P0 修正が出力を変えるから**です。

> **v0.6.12 と v0.6.13 の道具は、どちらも 16 を名乗ります。**
> その 2 つを見分けるには `tool.sha256` を使ってください
> （v0.6.13 `48e91238f483abe6…` / v0.6.14 `d56bb01ca0233490…`）。

## 7. `archivePolicy` は改名しませんでした

そちらの案は「完全な `ARCHIVE_POLICY` 正本を作る」か「`archivePolicySummary` へ改名して
coverage を明示する」でした。**改名は採りませんでした。**

```
言語部分集合の判定器で実測
  description のみの変更   → HOLD（BUMP 不要）
  対照: enum を 1 つ減らす → HOLD_RECORD + NARROW
```

改名は欄名を変える＝schema を狭めるので、**下流が止まります。**
代わりに `notMachineReadableHere`（6 件）と `reasonCodeFamilies` を足しました。

```
notMachineReadableHere:
  pax-key-handling / path-spelling / link-target-resolution /
  header-checksum / duplicate-path / root-strip
```

**「この欄は全部を書いていない」と、欄自身に言わせる形**です。
完全な正本にするほうが良いという判断であれば、次版で作ります。

## 9. 反例のいただき方と、次に見てほしいこと

**実データで再現できる形だと助かります。**今回の fixture ZIP は理想的でした
——**digest つき・両実装の exit code と結果つき・こちらで踏める形**でした。

そのうえで、次を見ていただきたいです。

1. **catalog が踏まない 15 種類。**材料を作れるものが残っていないか。
   試験がこの数を毎 run 出すので、増減したら気づきます。

   `ARCHIVE_UNSUPPORTED` の code を `ArchiveInvalid` で投げる正当な場面があるか。
3. **`archivePolicy` を完全な正本にすべきか**（§7）。改名なしで達成する方法があるか。
4. **同じ形の穴が、ほかにも無いか。**——**いちばん見てほしいのはここです。**
   同じ境界を 2 つ以上の一覧で持っていて、片方しか検査していない箇所。
   **直近 3 版で 6 つ出ました。**まだあると思っています。
5. **P2 の core / wrapper 分離。**まだ検討していません。
