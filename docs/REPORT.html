3.5 mm TRS 接合機構ビューア — 納品報告

この文書の HTML 版（同名 .html）は npm run docs:html で生成しています。HTML を直接編集しないでください。

作成 2026-07-30 ／ 最終更新 2026-08-01 ／ 状態: 完了（納品後に 3 回の見直しを反映）

実在する 3.5 mm ステレオプラグとジャックの接合機構を、ブラウザ上で自由に観察・挿抜できる 3D アプリを作りました。 一番の狙いは、プラグを途中まで挿したときに内部で何が起きているかを、見た目の色替えではなく実際の幾何計算で見せることです。

2. 何を根拠にしたか

2-1. 一次資料

メーカー公式データシート 2 点（いずれも 07/2025 改訂） を実際に取得し、図面を画像として判読しました。

  • Lumberg 1532 10 データシート — プラグの全寸法・材料・電気/機械仕様
  • Lumberg 1503 09 データシート — ジャックの外形・基板レイアウト・回路記号・材料・仕様

加えて、図面に数値記載の無い外形は自前で実測しました。 PDF を 1200 dpi にラスタライズして輪郭線を検出する方法と、ベクタ抽出という独立した 2 通りで測り、 両者が 0.05 mm 以内で一致することを確認しています。

2-2. 根拠区分の内訳

区分件数意味
FACT48データシートに数値として直接記載されている
DERIVED39記載寸法から演算、または図面を実測して導出した
ASSUMPTION41資料が無いため明示的に置いた仮定
UNKNOWN0（未確認のまま数値化した項目は無い）

アプリ内の「根拠」タブで全キーの値・区分・出典を確認できます。

2-3. 図面から分かった重要な事実

データシートの寸法 14 / 8.5 / 5 は、肩を共通の基準にして先端方向へ測られています。 したがって先端基準では 14 − 8.5 = 5.5（Ring 前端）、14 − 5 = 9.0（Sleeve 前端）になります。 この読み取りは、独立した図面実測（5.487 / 8.992）と 0.013 mm 以内で一致しました。

また実測により、Tip 導体が Ring / Sleeve より細いことが分かりました。 先端側の円錐終端で φ3.02、後端の立ち上がりでも最大 φ3.20 で、Ring / Sleeve の φ3.5 に届きません。 この 0.15 mm（半径）の段差が半挿し時の挙動を決めます —— 第1絶縁帯で橋絡が起きない理由がこれです。

ただしこの 0.15 mm は、両端とも幅を持つ量の差です。 φ3.5 は FACT ですが公差 ±0.05 を持ち、

φ3.20 は FACT ではなく DERIVED（図面実測 φ3.20〜3.22）です。両方を悪い側へ振ると段差は

0.115 まで薄くなります。それでも採用値では橋絡しませんが、余裕は 3.1 倍から 2.4 倍に落ちます

（SENSITIVITY.md §6-1、UNKNOWNS.md §4-1b）。

納品時にここを「2 つの FACT から出る幾何的な帰結」と書いていたのは誤りでした。

3. どこまでが実測・図面準拠で、どこからが推定か

実測・図面準拠（信頼できる）

  • プラグの全外形寸法と軸方向の導体境界
  • ジャックの外形寸法・挿入穴径・端子の軸位置と横位置
  • 端子どうしの関係（端子 3 と 5 が対、端子 2 と 4 が対）— データシートの回路記号そのもの
  • 材料・電気仕様・機械仕様のすべて
  • 完全挿入深度 14.0 mm — プラグ肩 φ10（図面記載）がボア φ3.6 に入らないことからの幾何的帰結

導出（根拠はあるが図面に直接は書かれていない）

  • どちらの端子が Tip 側か — 回路記号は Tip / Ring の別を書いていません。 基板レイアウト図の端子位置（端子 3 = 13.4 mm、端子 2 = 8.9 mm）と、完全挿入時の導体配置から、 端子 3 = Tip、端子 2 = Ring 以外に成立する組み合わせが無いとして導出しました。
  • 内部接点 3 本の軸方向位置 — 完全挿入時に正しく結線される必要があるという制約から絞り込み

仮定（資料が無い）

  • ジャック内部の接点ばね寸法一式 — 自由半径・板厚・梁長・ばね定数・接触パッド幅。 データシートにもメーカー CAD にも含まれていません。
  • ブレーク接点が開くたわみしきい値（0.05 mm）
  • 接触品質スコアの重み・しきい値
  • 挿抜力モデルの摩擦係数・校正係数
  • 導体と絶縁帯の境界のエッジ処理（面取り／丸み）— 図面に作図も寸法記載もありません
  • 4極ジャックの内部接点位置（4極プラグ側の導体境界は 2 社の図面記載寸法からの演算で FACT）

これらの仮定を成立範囲いっぱいに振ったらどうなるかを実測しました （SENSITIVITY.md）。結論は「仕組みは揺れない、深さの数字は揺れる」です。

4. 半挿しで何が起きるか

このアプリの中心的な発見です。物語ではなく、幾何計算の結果として出てきます。

ジャックの 3 つの接点は軸方向にばらばらの位置にあります（前面から 3.2 / 7.1 / 11.4 mm）。 プラグを挿していくと、入口に一番近い「帰線（グランド）用の接点」が、 まずプラグの Tip（左チャンネル）の上を通り、次に Ring（右チャンネル）の上を通ります。

深さごとの実際の計算結果（数字の正本は artifacts/events.json・0.02 mm 刻み）:

深度起きること
3.92 mm最初の物理接触。帰線用接点がプラグ先端の円錐に触れる
3.94 mm帰線用接点が Tip 導体に接触 — 左チャンネルがグランドに落ちる
6.32〜7.04 mm帰線用接点が第1絶縁帯を通過し、いったん回路が開く
8.02 mmRing 用接点が Tip 導体に接触 — 右チャンネルの線に左の信号が乗る
8.06 mmRing 側ブレーク接点が開く — 機器は「挿さった」と判断するが、まだ何も正しくつながっていない
8.26〜8.28 mm帰線用接点が第1絶縁帯の上を通る。ここでは橋絡しない（Tip が Ring より 0.15 mm 低いため）
9.44 mmRing 側ブレーク接点がいったん閉じ直す — ばねが先端の逆テーパを下るため
11.24 mmRing 側ブレーク接点が再び開く
11.78 mm橋絡発生 — 帰線用接点が第2絶縁帯をまたぎ、Ring と Sleeve を同時に短絡する（真値 11.760。表は 0.02 mm 刻みの走査値）
11.96 mm橋絡が解消し、帰線用接点がようやく Sleeve だけに乗る（真値 11.94）
12.34 mmようやく全接点が正しい導体に接触
14.00 mm完全挿入

つまり「半挿しでガリッとノイズが出る」「片方しか鳴らない」「機器は挿入を検知しているのに音がおかしい」 のいずれも、この 10 mm ほどの間に順番に起きています。

この表は README.md にも同じものがあります。**文言は用途に合わせて別々に

書いていますが、深さの数字は npm run test が両方とも artifacts/events.json と

突き合わせています**（test/docs.test.ts・TEST_RESULTS.md §7.5）。

橋絡が第2絶縁帯でだけ起きるのは、Ring と Sleeve がどちらも φ3.5 で高さが同じだからです。 第1絶縁帯では Tip が φ3.20 と 0.15 mm 低く、接点は Ring に押し上げられて Tip 面に届きません。 成立条件は「パッド幅 > 絶縁帯幅」ではなく「同じ高さの導体面どうしの間隔（0.700 mm）< パッド幅（0.9 mm）」です （2026-07-31 の公開前監査で判定の誤りを見つけて修正）。

この深さは単一値ではなく、幅を持ちます

上表はジャック内部の接点位置とパッド幅を現在の仮定値に固定したときの計算結果です。 それらは一次資料に無い仮定なので、深さの数字はそのぶん動きます。 成立範囲いっぱいに振って測った結果が次です（SENSITIVITY.md）。

事象上表の値仮定を振ったときの幅
Ring↔Sleeve 橋絡が始まる11.76 mm6.96〜13.14 mm
Ring 側ブレーク接点が開く8.05 mm8.00〜12.33 mm（しきい値 0.4 以上では一度も開かない）

一方、「何が起きるか」の順序は幅を持ちません。 帰線接点が Tip → Ring の順に通過すること、Ring↔Sleeve の橋絡が起きること、 Tip↔Ring の橋絡が（公称寸法では）起きないこと、ブレーク接点が正しい結線より先に開くこと —— これらはどの構成でも変わりませんでした。

「何が起きるか」はほぼ決まっていて、「何 mm で起きるか」が決まっていない、という状態です。

接点検証

完全抜去時 — 3 接点すべて非接触、ブレーク接点 2 個ともクローズ（データシートの通常状態と一致）。

完全挿入時 — Jack Tip → Plug Tip、Jack Ring → Plug Ring、Jack Sleeve → Plug Sleeve。 ブレーク接点は両方とも開き、不要な橋絡はありません。 押付力は 1.085 / 1.085 / 1.016 N で、参考値 0.8〜1.3 N/接点の範囲に収まっています。

挿入途中 — 誤セグメント接触・絶縁帯上での開放・橋絡・ブレーク接点の先行開放を、 いずれも具体的な深度で再現できることを確認しました。

決定性 — 0.05 mm 以下のステップで全域を走査でき、同一条件では常に同一結果になります。 接点が存在しない位置に架空の接触を生成しないこと、絶縁帯を無視して常時接続しないことも確認済みです。

挿抜力

推定挿入ピーク 5.27 N、抜去ピーク 5.28 N。 Lumberg 1503 09 の公称 3–20 N（gauge plug 測定）の範囲内です。 ただしこれは校正係数をこのレンジに合わせて置いた結果であり、検証ではなく設計です。

この数字を有効数字 3 桁の量として読まないでください。

力のモデルの係数 9 件はすべて ASSUMPTION です。感度解析で振ったところ:

| | 値 |

|---|---|

| 校正係数（純粋な倍率・独立した根拠なし） | 1.0 → 3.64 N ／ 1.45 → 5.27 N ／ 2.0 → 7.27 N |

| 校正係数を固定し、物理 8 件を同時に振る（256 通り） | 1.5 〜 11.2 N |

| そのうち公称 3–20 N を外れた構成 | 32 / 256（いずれも下側） |

5.27 N は幅 7.3 倍の中の 1 点で、その中心を決めているのは根拠を持たない校正係数です。

意味があるのは曲線の形（入口摩擦・段の乗り越え・完全挿入位置の保持・抜去時の

ヒステリシス）で、こちらは幾何から出ており係数を振っても変わりません。

詳細は SENSITIVITY.md §3-4。

性能（実 GPU）

Apple M5 / Chrome (ANGLE Metal) で測定した結果、1440×900 @2x と 1920×1080 @2x のどちらでも、 静止時・挿抜アニメ中・低負荷モードの全条件で fps 59.9（60 Hz vsync の上限）に達しています。 最大フレーム時間は 19.4 ms 以下で、33 ms を超えるフレーム落ちは 0 件でした。 1 フレームの描画コストは 0.08〜0.10 ms で、16.7 ms の予算の 0.5〜0.6 % です（ポリゴン数 5,460 三角形 / 44 draw call）。

6. 操作方法

挿抜

  • 3D 上でプラグを直接ドラッグ
  • スライダー、数値入力＋「移動」、50% ボタン
  • ← → で微調整（Shift = 0.5 mm、Alt = 0.01 mm）
  • Home / End で完全抜去 / 完全挿入、Space で自動挿入・一時停止、R でリセット
  • ビューポート上で Shift + ホイールでも深度調整（ホイール単独は拡大縮小）
  • 刻みは 0.01 / 0.05 / 0.2 / 1 mm から選択

視点 — ドラッグで回転、ホイールで拡大縮小、右ドラッグで平行移動、「視点を戻す」で既定位置へ。

8. 残る制約

  • 実物の部品との突き合わせをしていません。 現物を持っていないため、 確認しているのは「モデルが自分の定義どおりに動くこと」と「データシート記載値と矛盾しないこと」です。 感度解析も実物の検証ではありません — モデルの内部で、仮定をどう選び直しても結論が 変わらないことを確かめただけです。
  • 図面実測は 2 通りの独立した方法で一致を確認しましたが、どちらも同じ 1 つの図面を読んでいるので、 図面自体の誤りは検出できません。
  • 深さの数字はすべて幅を持ちます（§4）。単一値として引用しないでください。
  • 実物のプラグ外径が公差 φ3.5±0.05 のどこにあるか測っていません。 「第1絶縁帯で橋絡しない」 という中心的な結論は 0.15 mm の段差に乗っていますが、その段差は両端とも幅を持つ量の差で、 最悪の組み合わせでは余裕が 3.1 倍から 2.4 倍に落ちます（UNKNOWNS.md §4-1b）。
  • 接触抵抗の実測値は出しません。 完全接触時のみメーカー公称値（≤30 mΩ）を仕様値として表示し、 不完全接触時は 0〜1 の相対スコアのみを出します（Ω に換算していません）。
  • 挿抜力は有限要素解析ではありません。エネルギー法による近似です。
  • 音響予測は回路接続からの簡易推定であり、特定製品の実際の音を保証しません。音は鳴りません。
  • 4極（TRRS）は 3極版より根拠が弱く、Ring1 / Ring2 の境界と 4極ジャックの内部接点位置は仮定です。
  • 規格本文（JIS C 6560 / JEITA RC-5325A）は入手していません。 いずれも有償規格です。 メーカーが準拠を謳っていることを確認しただけで、規格本文は確認していません。 本アプリに規格由来の数値はありません。
  • 物理的な iPhone / iPad では未検証です。 iOS Safari の確認は iOS 26.4 シミュレータで行いました。 ブラウザエンジンは実機と同じ WebKit ですが、実機固有の要素 (実際の指の接触面積、Safari の ツールバー挙動、実機 GPU の性能、低電力モードなど) は確認できていません。
  • 性能測定は Apple M5 / 60 Hz ディスプレイ 1 台のみです。他の GPU、120 Hz 環境、実際の低性能端末では未測定です。

一次資料どうしの矛盾（要注意）

対応する 2 部品なのに、挿抜力の記載が約 10 倍違います。

9. メーカー CAD について

Lumberg は STEP モデルを登録不要で配布していますが、Legal Notes §5 が 「書面同意なく複製・頒布・再生産・再送信その他の利用は禁止」と定めています。 無料で取得できることは再配布の許諾を意味しません。

11. 納品後に何が変わったか（2026-07-31 〜 08-01）

納品後、公開に向けた監査と感度解析でこの報告書の数字と主張のいくつかが変わりました。 何をどう間違えていたかを含めて記録します。

11-1. 存在しない面取りを削除した（07-31）

導体と絶縁帯の境界に 0.09 mm の面取りを 6 か所置いていました。 図面を 1200 dpi でラスタ化して測ったときの値でしたが、線の太さ（0.302 pt ≒ 0.107 mm）を 面取りと読み違えたものでした。ベクタで見ると各段はちょうど 1 本の垂直線で、 面取りの作図も寸法記載もありません。削除しました。

影響
接触・導通・橋絡の結論変わらず（イベント深度のずれは最大 0.035 mm、橋絡は 6 構成すべてで従来どおり成立）
ポリゴン数6,228 → 5,460（差 768 = 6 点 × 64 分割 × 2 三角形。意図どおりの分だけ減った）
挿抜力モデル壊れた

段が幅ゼロになるとたわみが不連続になり、ランプ項 dδ/dd が発散します。 走査刻みを変えるだけでピークが 17.8 N にも 28.2 N にもなる状態でした。 接触ドームが有限の曲率を持つことを傾きの頭打ちとして表す上限（force.maxRampSlope = 0.48）を 明示的な仮定として置いて直しています。

面取りがあった頃のピーク挿入力 6.97 N は、存在しない面取りの傾きが作っていた値でした。 現在は 5.27 N です。

11-2. 一次資料を読み直した（07-31）

「図面に記載が無い」と書いていたもののうち 3 件は、こちらの読み落としでした。

項目訂正前訂正後
ジャックのナット径5.6 mm（実測由来・注記は図面と正反対のことを書いていた）ø6（図面記載・FACT）
ジャック軸の高さ「何と何の間の寸法か特定できていない」図面が軸中心→本体底面を直接寸法していた（FACT）
歪み止めの外径台帳に無く、φ10 → φ5.8 の円錐として描いていた断面 A-A に Ø7（FACT）。一定径のリブ管に修正

4極プラグの Ring1 / Ring2 境界も同様で、「どの図面にも寸法指定が無い」と書いていたのは 寸法線を先端基準だと読み違えていたためでした。図面のチェーンは肩基準です。 訂正した結果、CTIA プラグを 3極ジャックへ挿したときの帰線の食い違いも解消し、 混挿 6 通りすべてが一般に言われる挙動と一致するようになりました。

pdftotext で拾えないことを「記載が無い」の根拠にしていたのが原因です。

CAD の寸法テキストは輪郭線としてストロークされているので、テキスト抽出には出てきません。

図面は最終的に目で確認する必要があります。

11-3. 感度解析を作った（08-01）— そして作り直した

実物照合ができない以上、「11.76 mm で橋絡する」と単一の数字を出すのは意味が強すぎます。 仮定を成立範囲いっぱいに振り、何が不変で何が動くかを機械的に測りました （SENSITIVITY.md）。

初版には手法上の欠陥が 4 つあり、独立した反証で主張 6 件のうち 3 件が覆りました。 最も重かったのは、看板にしていた「compliance < 0.15 の 729 通りで Tip 橋絡 0 件」が、 水準の取り方の誤りですべて compliance = 0 の一点だったことです。そこは Tip に一切導通できず 完全挿入すら成立しない退化モデルで、証拠として空でした。

初版訂正後
橋絡開始の基準値11.77 mm（走査格子由来）11.760 mm（二分法）
パッド幅のしきい値0.721 mm（0.001 刻みの目盛り）0.720 mm
橋絡深さの幅9.0〜13.1 mm（片振りの合併）6.96〜13.14 mm（同時振り）
Tip 橋絡が起きない根拠「2 つの FACT から出る幾何的帰結」φ3.20 は DERIVED。「公称寸法のモデルでは起きない」

作り直した版でも単調性を仮定した二分法というバグを 1 つ踏みました（橋絡もブレーク接点も 深さに対して単調ではありません）。粗い走査で窓を挟んでから詰める方式に直しています。

この一連の作業で、scripts/ が型検査の対象外（tsconfig.app.json の include が src のみ） だったことも分かりました。未定義の変数を参照したまま npm run typecheck が通ります。 tsconfig.scripts.json を追加して検査対象に入れ、そこで見つかった 3 件を直しました。

さらに同日、解析に 2 つ穴が残っていたので埋めました。

  • 公差を片端しか振っていなかった。 段差 0.150 の両端を同時に振ると、最悪コーナーで 余裕が 3.08 → 2.38 倍まで落ちます。ノギス 1 本で決着するので、 VERIFICATION_PLAN.md に §1-1 として独立させ、 LED 回路を使う決着実験より前に置きました。 そこにあった判定線「0.24 mm を下回ったら前提が崩れる」も実測で取り直しています （実際に崩れるのは 0.090 mm。しかも 0.24 は図面が許す最悪値 0.23 より上にあり、 図面どおりの個体でも誤判定しかねない線でした）。
  • 力のモデルを「対象外」で済ませていた。 校正係数が純粋な倍率であることを確かめたうえで 固定し、物理 8 件を振りました（§5）。

あわせて、振り幅をスクリプトに直書きしていたのを台帳（dimensions.json）へ移しました。 台帳を直したときに解析だけ古い幅で残る状態だったためです。
