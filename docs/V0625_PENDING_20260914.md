## 1. `nanoid` 3.3.16 → 3.3.19

### 何を測ったか

```
更新前   nanoid 3.3.16   npm audit: high 2 / moderate 2 / 計 4 件（nanoid を含む）
更新後   nanoid 3.3.19   npm audit: high 1 / moderate 2 / 計 3 件（**nanoid は消えた**）
経路     trs-jack-3d@0.6.24 → vite@8.1.5 → postcss@8.5.25 → nanoid（推移依存・dev のみ）
方法     npm update nanoid --package-lock-only → npm ci
lockfile の差分  3 行（version / resolved / integrity の 1 か所だけ）
```

advisory が直ったのは 3.3.18 からで、`postcss@8.5.25` が要求する範囲（`^3.3.16`）の中で
いちばん新しいのが **3.3.19** である。`package.json` は触っていない（直接依存にしない）。
`npm audit fix` は回していない——残りの 3 件を巻き込むため。

### ⚠️ この更新だけでは、テストが赤になる

`package-lock.json` は**記録された入力**である。上げた瞬間に
`artifacts/source-input-manifest.json` の記録と食い違う。

```
記録された sha256   08ab42421396b13bc89e58da8723099049e4694b7d492071c950814e30cd9035
実物の sha256       d8e8b78ac087cffeddcb9e96ef6ed1b712d38d8cb657f0c495d01f690ad824d0
consumedBy          5 件（half_plug_topology_profile ×2 / sensitivity ×2 / topology-robustness）
```

**同じ検体で前後を測った**（lockfile の中身だけを入れ替え、他は何も変えていない）。

```
3.3.16   7 ファイル 164 件すべて通る        exit 0
3.3.19   7 ファイル 20 件が落ちる（144 通る） exit 1
落ちた内訳  source-input 検算系だけ（halfPlugProfile / reasonCodeCatalog / reasonCodeReachability /
            sourceInputScope / sourceVerificationResult / sourceVerifierCliResult /
            verifyReleaseSourceInputs）
Test timed out   0 件      ← 機械の負荷ではない
```

**nanoid の中身が何かを壊したのではない。**記録と実物がずれただけである。
`docs/NPM_AUDIT_20260814.md` が「次の版の頭で上げ、その版の staging で `profileId` の変化を実測する」
と書いていたのはこのことで、**閉じるには 5 件の artifact を作り直して記録を取り直す工程**が要る
（重い再生成を含むので、この作業では手を付けていない）。
