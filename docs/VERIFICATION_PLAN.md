# 実物との突き合わせ計画

> この文書の HTML 版（同名 `.html`）は `npm run docs:html` で生成しています。**HTML を直接編集しないでください。**

作成 2026-07-31 ／ 状態: **部品の手配待ち**

このモデルの一番弱いところは、**ジャック内部の接点ばねの寸法をすべて仮定で置いている**ことです
（[UNKNOWNS.md](../UNKNOWNS.md) §3、[ASSUMPTIONS.md](../ASSUMPTIONS.md) A）。
データシートにもメーカー CAD にも書かれていないので、図面からは埋められません。

ただし幸運なことに、**その仮定は電気的に測れます。**
テスターで端子間の導通を見ながらプラグをゆっくり挿していけば、
接点が切り替わる深さが分かります。モデルはその深さを予測しているので、当たり外れが判定できます。

この文書は、その測定をどうやるかを決めたものです。

## 1. 何を測ると何が分かるか

内部で起きていること（接点の状態）はテスターでは見えません。見えるのは端子間の導通だけです。
そこで、モデルの出力を「テスターで見える形」に変換しました（`npm run predict:probe` で再生成できます）。

### 一番おいしい観測点 — ブレーク接点

**ジャックだけあれば測れて、しかも内部接点の位置がそのまま出ます。**
プラグに配線する必要すらありません。テスターの棒を2本のピンに当てるだけです。

#### Ring 側ブレーク接点（ピン2 ↔ ピン4）

| 深さ | すき間 | 変化 |
|---:|---:|---|
| 8.06 mm | 5.94 mm | 閉 → **開** |
| 9.43 mm | 4.57 mm | 開 → **閉** ← ここが山場 |
| 11.23 mm | 2.77 mm | 閉 → **開** |

**「いったん開いて、また閉じて、また開く」** という予測が出ています。
これは意図して作った挙動ではなく、プラグ先端の逆テーパ（先端の円錐の後ろで径が
φ3.02 → φ2.59 へ細くなる）を接点ばねが下ることで、押付が一時的にしきい値を割るためです。

（表の値は走査刻み 0.01mm での出力。刻みを 0.005mm にすると 8.05mm と出るなど、末尾 0.01mm は揺れる。
合否は ±0.3mm で見るので実用上は問題にならない。）

**この「再閉」が起きるかどうかが、この実験の核心です。**
起きれば、プラグ外形の実測と Ring 接点の位置が同時に裏付けられます。
起きなければ、どこかの仮定が間違っているとはっきり分かります。

#### Tip 側ブレーク接点（ピン3 ↔ ピン5）

| 深さ | すき間 | 変化 |
|---:|---:|---|
| 12.01 mm | 1.99 mm | 閉 → **開** |

こちらは1回だけ。素直な観測点です。

### 余力があれば — プラグ導体との導通

プラグの端子に線を出せば、こちらも測れます。半挿しの誤接触がそのまま見えます。

| ピン | 深さ | すき間 | つながる先 |
|---|---:|---:|---|
| ピン1（Sleeve 接点） | 3.93 mm | 10.07 mm | → **プラグ Tip**（帰線が左信号に触れる） |
| 〃 | 6.32 mm | 7.68 mm | → 切れる（絶縁帯を通過） |
| 〃 | 7.03 mm | 6.97 mm | → プラグ Tip |
| 〃 | 8.26 mm | 5.74 mm | → 切れる（第1絶縁帯を通過） |
| 〃 | 8.27 mm | 5.73 mm | → プラグ Ring |
| 〃 | 11.77 mm | 2.23 mm | → **Ring と Sleeve の両方**（橋絡） |
| 〃 | 11.95 mm | 2.05 mm | → **プラグ Sleeve**（ようやく正常） |
| ピン2（Ring 接点） | 8.01 mm | 5.99 mm | → プラグ Tip |
| 〃 | 10.04 mm | 3.96 mm | → 切れる |
| 〃 | 11.11 mm | 2.89 mm | → プラグ Tip |
| 〃 | 12.17 mm | 1.83 mm | → 切れる |
| 〃 | 12.34 mm | 1.66 mm | → **プラグ Ring**（正常） |
| ピン3（Tip 接点） | 11.96 mm | 2.04 mm | → **プラグ Tip**（正常） |

## 1-2. 決着実験 — 橋絡がどこで起きるか

**この 1 つの測定だけで、モデルの修正が正しかったかどうかが決まります。**

### 何が争点か

2026-07-31 の公開前監査で、接触判定に誤りが見つかりました。
接点が届いているかを「たわむ**前**の自由半径」で判定していて、
プラグに押し開かれたあとの位置で見直していなかったのです。

その結果、修正前と修正後で**予測が正面から食い違います**。

| | 第1絶縁帯（Tip↔Ring） | 第2絶縁帯（Ring↔Sleeve） |
|---|---|---|
| **修正前** | 深さ 8.27〜8.44 mm で**橋絡する** | 11.77〜11.94 mm で橋絡する |
| **修正後（現在）** | **一度も橋絡しない** | 11.77〜11.94 mm で橋絡する |

修正の根拠は、プラグ導体の**高さの差**です。Tip は最大 φ3.20（半径 1.600）、
Ring / Sleeve は φ3.50（半径 1.750）。**Tip だけ 0.15 mm 低い。**
接点は Ring に押し上げられた位置にいるので、0.15 mm 下の Tip 面には届かない ―― という理屈です。

### 先に 30 秒でできる事前確認

**部品が届いたら、まずノギスでプラグの直径を 2 箇所測ってください。**

| 測る場所 | 予測 |
|---|---|
| Tip 導体の後端（先端から約 4.5 mm） | **φ3.20** |
| Ring 導体（先端から約 6.5 mm） | **φ3.50** |
| その差 | **0.30 mm** |

**差が 0.24 mm を下回ったら、この実験の前提そのものが崩れます。**
修正の根拠は「Tip が Ring より 0.15 mm 低い（半径で）」なので、
実物にその段差が無ければ、下の導通試験をするまでもなく修正が間違っていたことになります。

### 測り方 — プラグの Tip 線と Ring 線の間を見る

橋絡が起きると、ジャックの帰線接点が 2 つのプラグ導体を橋渡しします。
つまり**プラグ側の 2 本の線どうしが短絡します**。だからプラグ側だけを見れば分かります。

```
   LED + ボタン電池 + 抵抗（直列）
        ├── プラグ Tip 線
        └── プラグ Ring 線     ← この 2 本の間が短絡したら光る
```

**テスターの導通ブザーは勧めません。** 短絡する窓が 0.18 mm しかないので、
ブザーの応答が間に合わず見逃します。LED の直列回路なら瞬時に光ります。

1. プラグに Tip / Ring / Sleeve の 3 本の線を出す
2. LED 回路を Tip 線と Ring 線につなぐ
3. すき間 6.0 mm から 5.3 mm までを **0.2〜0.5 mm/s** でゆっくり通す
4. **一瞬でも光るか**を見る。**3 回以上繰り返す**

### 判定は 2×2 で決まる

対照実験を同時にやります。**プラグの Ring 線と Sleeve 線**の間も同じ回路で見てください
（すき間 2.5 mm → 1.8 mm を同じ速度で通す）。こちらは**修正前も修正後も光る**予測です。

| Ring↔Sleeve（対照） | Tip↔Ring（本命） | 判定 |
|---|---|---|
| **光る** | **光らない** | **修正後のモデルが正しい。** 高さの段差の解釈が裏付けられた |
| **光る** | **光る** | **修正前が正しく、修正が誤り。** 接点は 0.154 mm 以上下の面まで追従している |
| 光らない | — | **測定が成立していない。** 配線・速度・LED 回路を見直す。またはパッド幅が 0.72 mm 以下（本命の陰性は無意味） |
| 光らない | 光る | ありえない。配線ミスを疑う |

対照が光ることが、**「0.18 mm の一瞬の短絡を検出できる装置になっている」ことの証明**です。
これが無いと「Tip↔Ring が光らなかった」に意味がありません。

### なぜこの測り方が強いか

**深さを測る必要がありません。** 見るのは光るか光らないかだけです。

深さで判別しようとすると失敗します。修正前後で予測が食い違う深さの最大差は **0.180 mm** しかなく、
合否基準の ±0.3 mm を下回るからです。**この論点は深さの測定では決着しません。**

もうひとつ、この実験には非対称性があります。
**修正後のモデルは、パッド幅をどれだけ広げても Tip↔Ring 短絡を起こせません。**
だから一度でも光れば、パラメータ調整では逃げられず、修正が無条件に反証されます。

### おまけ — 対照の窓幅からパッド幅が逆算できる

Ring↔Sleeve が光っている間のすき間の幅を測ると、帰線接点のパッド幅が出ます。

```
パッド幅 ≒ 光っている窓の幅 + 0.72
```

いま 0.9 mm と仮定している `jack.contact.sleeve.padWidth` を、ASSUMPTION から上げられます
（予測: 窓幅 0.18 mm）。これは余談ではなく、**本命の陰性結果を解釈するために要ります。**
窓が見えなければパッド幅は 0.72 mm 以下で、そもそも Tip↔Ring 試験が成立しません。

### ブレーク接点では決着しません

§1 の「一番おいしい観測点」（ピン2↔ピン4、ピン3↔ピン5）は、この論点に対して**判別力がゼロ**です。
開閉する深さは修正前後でまったく同じ（8.06 / 9.43 / 11.23 / 12.01 mm）でした。

あちらはプラグ外形と接点の軸位置を試す実験で、橋絡の真偽は試せません。
**この決着実験にはプラグ側への配線が必須**です。プラグ 1532 10 ははんだ付け端子を持つので、
3 本のリード線をはんだ付けするか、市販の 3.5 mm ステレオケーブルを切って各線を確認してください。

## 2. 深さをどう決めるか

**深さそのものを測るのは難しいので、「すき間」を測ります。**

```
   プラグ肩            ジャック前面
      │                    │
      │◀──  すき間  ──▶│
      └────────────────────┴──── 奥
                              深さ = 14.00 − すき間
```

完全に挿し込むとプラグの肩がジャック前面に当たって止まります。この位置が深さ 14.00 mm です
（プラグ肩の外径 φ10（図面記載）がボア φ3.6 より大きいため物理的にそこで止まる）。
つまり**すき間ゼロ＝深さ 14.00 mm** で、自動的に基準が決まります。

すき間は 1.6〜10 mm の範囲なので、ノギスの外側ジョーやデプスバーで素直に測れます。

### 測り方（1チャンネルずつ）

目標の深さに合わせにいくのではなく、**変化した所で止めて測る**ほうが簡単で正確です。

1. ジャックを動かないように固定する（万力・両面テープ・ブレッドボードなど）
2. テスターを導通ブザーにして、ピン2とピン4に当てる（クリップ付きが楽）
3. プラグをごくゆっくり押し込む
4. ブザーが切れた（または鳴った）瞬間に手を止める
5. その状態でプラグ肩とジャック前面のすき間をノギスで測る
6. 深さ = 14.00 − すき間 を記録する
7. 一度完全に抜いて、**3回繰り返す**（ばらつきを見るため）
8. ピン3とピン5でも同じことをする

プラグは指で押すと傾きます。まっすぐ入るよう、指先で軸を支えてください。

## 4. 合否の基準

「だいたい合っていた」で終わらせないために、先に線を引いておきます。

| 予測とのずれ | 判定 | やること |
|---|---|---|
| **0.3 mm 以内** | モデルは実測と整合 | `dimensions.json` の note に実測日と実測値を追記。grade は DERIVED のまま（実測で裏付いたと明記） |
| **0.3〜1.0 mm** | 位置がずれている | 逆算した軸位置へ更新し、grade を ASSUMPTION → DERIVED に上げる |
| **1.0 mm 超**、または再閉が起きない | 構造の仮定が違う | 軸位置だけの問題ではない。パッド幅・自由半径・プラグ外形のどれが効いているか切り分ける |

0.3 mm という線は、**測定側の誤差の見積り**から決めています。
ノギスの読み ±0.02 mm、切り替わり位置の判断 ±0.1 mm、プラグの傾きによる影響 ±0.1 mm 程度を
足し合わせると 0.2 mm 強になるので、その外側に置きました。

### 定性的な合否（数字より重い）

- **Ring ブレーク接点の「再閉」が起きるか** — 起きなければ、プラグ先端の逆テーパの解釈か
  Ring 接点の自由半径が違います。数値のずれより重大です
- **開閉の回数** — 予測は「開・閉・開」の3回。回数が違えば構造の理解が違います
- **ピン1が最初に触れる相手がプラグ Tip か** — 帰線用の接点が左信号に触れるという予測。
  ここが違うと接点の並び順の理解が違います
- **第1絶縁帯で Tip↔Ring が短絡しないか** — §1-2 の決着実験。鳴ってしまったら、
  接触判定の修正そのものが間違っていたことになります。**深さの一致より重い判定です**

## 5. 測った後どうするか

逆算の道具を用意してあります。**測った深さを渡すと、その深さになる接点位置を計算します。**

```bash
npm run fit:contacts -- 8.4 12.3 4.1
```

引数の順は「Ring ブレーク開放 / Tip ブレーク開放 / Sleeve 接点が Tip に触れ始める」の深さ（mm）です。

出力されるもの:

- 逆算した軸位置と、現モデルからのずれ
- **合わせていない残りの切り替わり**が、その軸位置ならどうなるか

最後のが大事です。合わせるのは各接点につき1点だけにしてあります。
全部を合わせにいくと「合って当然」になり、検証したことになりません。
1点で合わせて、残りが当たるかどうかを見る。それがモデルを試すということです。

引数なしで実行すると自己検査になります（モデル自身の予測を入れて元の軸位置を復元できるか）。
**現状の復元誤差は 0.0000 mm** です。道具そのものは正しく動いています。

```bash
npm run fit:contacts
```

### 反映の手順

1. 実測値を `docs/measurements/2026-XX-XX.md` として記録（生データ・3回分・気温も）
2. `npm run fit:contacts -- ...` で逆算
3. 判定表に従って `src/data/dimensions.json` を更新
4. `npm run test` と `npm run artifacts` を回し、予測がどう変わったか差分で確認
5. [UNKNOWNS.md](../UNKNOWNS.md) §3 の該当項目を「解決済み」に移し、実測日と方法を書く
6. [TEST_RESULTS.md](TEST_RESULTS.md) に実測の節を足す

## 6. この実験で分からないこと

正直に書いておきます。

- **接点ばねの形そのもの**（板厚・梁の長さ・曲げ方）は分かりません。分かるのは
  「どの深さで切り替わるか」から逆算した**接触点の軸位置**だけです。
  形を知るには切断するしかありません（だから予備を買う）
- **押付力（N）** は測れません。ばね定数は依然として仮定のままです
- **接触抵抗の絶対値** は、この方法では意味のある精度で出ません。
  導通ブザーが鳴るかどうかしか見ていないためです
- **4極（TRRS）側の仮定** は、この実験では一切検証されません。別部品が必要です
- **接触ドームの追従量そのもの**（0.05 mm と仮定）は測れません。決着実験で分かるのは
  「0.118 mm より小さいかどうか」だけで、その中のどこかは決まりません

つまりこの実験で ASSUMPTION から降ろせるのは「接点の軸位置3つ」と、
間接的に「プラグ外形の解釈」です。37件の仮定のうち片付くのは数件で、
残りは残ります。それでも、**一番効く数件**です。
