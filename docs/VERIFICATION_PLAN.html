メンテナ自身は実測を行いません。電子計測の知見が無く、精度の要る測定を

自分でやると、かえって根拠の弱い数値を「実測値」として台帳に入れてしまうためです。

このプロジェクトが避けたい失敗そのものです。

| ❌ やらないこと | 部品の発注、自分での測定、実測値を待つこと |

ただし幸運なことに、その仮定は電気的に測れます。 テスターで端子間の導通を見ながらプラグをゆっくり挿していけば、 接点が切り替わる深さが分かります。モデルはその深さを予測しているので、当たり外れが判定できます。

この文書は、その測定をどうやるかを決めたものです。

1-1. プラグ 1 個とノギスだけで決まること — 最初にこれをやってください

この計画で一番安く、一番早く、一番効くのがこれです。 ジャックも LED もはんだ付けも要りません。プラグ 1 個とノギスだけ、実測 30 秒です。

何が決まるか

このモデルの中心的な結論は「第1絶縁帯（Tip↔Ring）では橋絡しない」ですが、 その根拠は Tip 導体が Ring より 0.15 mm 低い（半径で）という 1 点だけです。 そしてこの 0.15 mm は、両端とも幅を持つ量の差です。

Tip 後端半径1.600DERIVED図面実測 φ3.20〜3.22 → 半径 +0.01

実物がこの帯のどこにいるかは測っていません（UNKNOWNS.md §4-1b）。 ノギスで直径を 2 箇所測れば、それが 1 つに決まります。

1-2. 決着実験 — 橋絡がどこで起きるか

この 1 つの測定だけで、モデルの修正が正しかったかどうかが決まります。

何が争点か

2026-07-31 の公開前監査で、接触判定に誤りが見つかりました。 接点が届いているかを「たわむ前の自由半径」で判定していて、 プラグに押し開かれたあとの位置で見直していなかったのです。

その結果、修正前と修正後で予測が正面から食い違います。

第1絶縁帯（Tip↔Ring）第2絶縁帯（Ring↔Sleeve）
修正前深さ 8.27〜8.44 mm で橋絡する11.77〜11.94 mm で橋絡する
修正後（現在）一度も橋絡しない11.77〜11.94 mm で橋絡する

修正の根拠は、プラグ導体の高さの差です。Tip は最大 φ3.20（半径 1.600）、 Ring / Sleeve は φ3.50（半径 1.750）。Tip だけ 0.15 mm 低い。 接点は Ring に押し上げられた位置にいるので、0.15 mm 下の Tip 面には届かない ―― という理屈です。

先に §1-1 を済ませてください

この実験の前に、§1-1（すぐ上）のノギス測定を必ず先にやってください。

実物の段差が図面どおり（直径差 0.30 mm 前後）なら、下の導通試験で第1絶縁帯に 橋絡が出ないことが予測どおりの結果です。 しかし実物の段差が薄ければ、橋絡が出るのが正しいことになります。 先に段差を知らずに導通試験だけをすると、どちらの結果も解釈できません。

ノギス測定はプラグ 1 個だけででき、この実験より先に終わります。

測り方 — プラグの Tip 線と Ring 線の間を見る

橋絡が起きると、ジャックの帰線接点が 2 つのプラグ導体を橋渡しします。 つまりプラグ側の 2 本の線どうしが短絡します。だからプラグ側だけを見れば分かります。

   LED + ボタン電池 + 抵抗（直列）
        ├── プラグ Tip 線
        └── プラグ Ring 線     ← この 2 本の間が短絡したら光る

LED の直列回路を勧めます。 ただし理由は「速すぎるから」ではありません。 窓 0.18 mm を 0.2〜0.5 mm/s で通すと、短絡している時間は 0.36〜0.90 秒あります。 導通ブザー（応答は数 ms）でも十分に捉えられる長さです。

LED を勧めるのは次の 2 点です。

  • 接触が不安定なときにそれが見える。 ブザーは鳴る／鳴らないの二値ですが、 LED はちらつきや薄明かりとして中間状態が出ます。判定表の「光らない」を 「接触していない」と読んでよいかの確認になります。
  • ノギスの目盛りと同時に見られる。 音だと、鳴った瞬間のすき間を読むのに 目を離す必要があります。
  1. プラグに Tip / Ring / Sleeve の 3 本の線を出す
  2. LED 回路を Tip 線と Ring 線につなぐ
  3. すき間 6.0 mm から 5.3 mm までを 0.2〜0.5 mm/s でゆっくり通す
  4. 一瞬でも光るかを見る。3 回以上繰り返す

判定は 2×2 で決まる

対照実験を同時にやります。プラグの Ring 線と Sleeve 線の間も同じ回路で見てください （すき間 2.5 mm → 1.8 mm を同じ速度で通す）。こちらは修正前も修正後も光る予測です。

Ring↔Sleeve（対照）Tip↔Ring（本命）判定
光る光らない修正後のモデルが正しい。 高さの段差の解釈が裏付けられた
光る光る修正前が正しく、修正が誤り。 接点は 0.154 mm 以上下の面まで追従している
光らない—測定が成立していない。 配線・速度・LED 回路を見直す。またはパッド幅が 0.72 mm 以下（本命の陰性は無意味）
光らない光るありえない。配線ミスを疑う

対照が光ることが、「0.18 mm の一瞬の短絡を検出できる装置になっている」ことの証明です。 これが無いと「Tip↔Ring が光らなかった」に意味がありません。

なぜこの測り方が強いか

深さを測る必要がありません。 見るのは光るか光らないかだけです。

深さで判別しようとすると失敗します。修正前後で予測が食い違う深さの最大差は 0.180 mm しかなく、 合否基準の ±0.3 mm を下回るからです。この論点は深さの測定では決着しません。

もうひとつ、この実験には非対称性があります。 修正後のモデルは、パッド幅をどれだけ広げても Tip↔Ring 短絡を起こせません。 だから一度でも光れば、パラメータ調整では逃げられず、修正が無条件に反証されます。

おまけ — 対照の窓幅からパッド幅が逆算できる

Ring↔Sleeve が光っている間のすき間の幅を測ると、帰線接点のパッド幅が出ます。

パッド幅 ≒ 光っている窓の幅 + 0.72

いま 0.9 mm と仮定している jack.contact.sleeve.padWidth を、ASSUMPTION から上げられます （予測: 窓幅 0.18 mm）。これは余談ではなく、本命の陰性結果を解釈するために要ります。 窓が見えなければパッド幅は 0.72 mm 以下で、そもそも Tip↔Ring 試験が成立しません。

ブレーク接点では決着しません

§1 の「一番おいしい観測点」（ピン2↔ピン4、ピン3↔ピン5）は、この論点に対して判別力がゼロです。 開閉する深さは修正前後でまったく同じ（8.06 / 9.43 / 11.23 / 12.01 mm）でした。

あちらはプラグ外形と接点の軸位置を試す実験で、橋絡の真偽は試せません。 この決着実験にはプラグ側への配線が必須です。プラグ 1532 10 ははんだ付け端子を持つので、 3 本のリード線をはんだ付けするか、市販の 3.5 mm ステレオケーブルを切って各線を確認してください。

2. 深さをどう決めるか

深さそのものを測るのは難しいので、「すき間」を測ります。

   プラグ肩            ジャック前面
      │                    │
      │◀──  すき間  ──▶│
      └────────────────────┴──── 奥
                              深さ = 14.00 − すき間

完全に挿し込むとプラグの肩がジャック前面に当たって止まります。この位置が深さ 14.00 mm です （プラグ肩の外径 φ10（図面記載）がボア φ3.6 より大きいため物理的にそこで止まる）。 つまりすき間ゼロ＝深さ 14.00 mm で、自動的に基準が決まります。

すき間は 1.6〜10 mm の範囲なので、ノギスの外側ジョーやデプスバーで素直に測れます。

測り方（1チャンネルずつ）

目標の深さに合わせにいくのではなく、変化した所で止めて測るほうが簡単で正確です。

  1. ジャックを動かないように固定する（万力・両面テープ・ブレッドボードなど）
  2. テスターを導通ブザーにして、ピン2とピン4に当てる（クリップ付きが楽）
  3. プラグをごくゆっくり押し込む
  4. ブザーが切れた（または鳴った）瞬間に手を止める
  5. その状態でプラグ肩とジャック前面のすき間をノギスで測る
  6. 深さ = 14.00 − すき間 を記録する
  7. 一度完全に抜いて、3回繰り返す（ばらつきを見るため）
  8. ピン3とピン5でも同じことをする

プラグは指で押すと傾きます。まっすぐ入るよう、指先で軸を支えてください。

2-2. 4極ジャックの接点位置を測る — いま最も効く測定

2026-08-02 追加。 このプロジェクトで最も重い未確認事項は

4極ジャックの接点位置（UNKNOWNS.md §5-2）になりました。

一次図面が 1 つも無く、4 件とも仮定のままです。

しかも**看板の結論（3極プラグを 4極ジャックへ半挿しにすると左右差分が残る）が

そこに丸ごと乗っています。**

内部は見えませんが、電気的には測れます

接点位置そのものはジャックの中なのでノギスでは測れません。 しかし各端子が「最初に導通する深さ」は外から測れて、そこから位置が逆算できます。

モデルの予測は次のとおりです（4極プラグを使う場合）。

端子の役割最初に導通する深さ肩とジャック前面のすき間
MIC1.98 mm12.02 mm
GND5.67 mm8.33 mm
R8.43 mm5.57 mm
L11.86 mm2.14 mm

4 つが 2.7 mm 以上ずつ離れています。ノギスの分解能（0.01 mm）に対して十分な間隔があり、 測り分けられます。

用意するもの

  • 4極ジャック（測りたいもの。スマホ用の 3.5 mm ジャック部品など）
  • 4極プラグ（CTIA 配列のもの。市販の 4極ケーブルを切って使ってよい）
  • テスター（導通ブザー付き）／ デジタルノギス

手順

  1. ジャックの端子番号を、そのジャックのデータシートで確認する。 4極ジャックの端子配列はメーカーごとに違います。推測しないでください。 データシートが無い場合は、完全挿入した状態で各端子とプラグ各導体の導通を測り、 どの端子がどの導体に対応するかを先に確定させます。
  2. プラグの 4 導体それぞれにリード線を出す（切ったケーブルの被覆を剥くのが早い）。
  3. プラグをゆっくり挿しながら、各端子とプラグ導体の導通が最初に成立する位置で止める。
  4. その状態でプラグ肩とジャック前面のすき間をノギスで測る。
  5. 4 端子ぶん繰り返す。各 3 回測ってください（挿入方向のみ。抜去は別途）。

記録

docs/measurements/TEMPLATE.md の測定1・2 と同じ形式で、次を残してください。

端子番号 / 役割 / 対応するプラグ導体 / 最初の導通時のすき間（3 回）/ ノギスの分解能
使ったジャックの型番とロット / 4極プラグの型番

何が決まるか

深さから接点の軸位置を逆算できます（npm run fit:contacts の 4極版は未実装ですが、 すき間 = 14 − 深さ、接点位置 ≒ 深さ − プラグ導体の前端 で手計算できます）。

これが決まると:

  • UNKNOWNS.md §5-2 が ASSUMPTION → 実測になります
  • 看板の結論の深さ 13.30〜13.52 mm が、仮定ではなく実測に基づく値になります
  • topology_search の 4極側の結果が、実在部品の話として読めるようになります

「合わなかった」結果も同じ価値があります。モデルの予測（上の表）は

測る前に公開してあるので、後出しで合わせることはできません。

4. 合否の基準

「だいたい合っていた」で終わらせないために、先に線を引いておきます。

予測とのずれ判定やること
0.3 mm 以内モデルは実測と整合dimensions.json の note に実測日と実測値を追記。grade は DERIVED のまま（実測で裏付いたと明記）
0.3〜1.0 mm位置がずれている逆算した軸位置へ更新し、grade を ASSUMPTION → DERIVED に上げる
1.0 mm 超、または再閉が起きない構造の仮定が違う軸位置だけの問題ではない。パッド幅・自由半径・プラグ外形のどれが効いているか切り分ける

0.3 mm という線は、測定側の誤差の見積りから決めています。 ノギスの読み ±0.02 mm、切り替わり位置の判断 ±0.1 mm、プラグの傾きによる影響 ±0.1 mm 程度を 足し合わせると 0.2 mm 強になるので、その外側に置きました。

定性的な合否（数字より重い）

  • Ring ブレーク接点の「再閉」が起きるか — 起きなければ、プラグ先端の逆テーパの解釈か Ring 接点の自由半径が違います。数値のずれより重大です
  • 開閉の回数 — 予測は「開・閉・開」の3回。回数が違えば構造の理解が違います
  • ピン1が最初に触れる相手がプラグ Tip か — 帰線用の接点が左信号に触れるという予測。 ここが違うと接点の並び順の理解が違います
  • 第1絶縁帯で Tip↔Ring が短絡しないか — §1-2 の決着実験。鳴ってしまったら、 接触判定の修正そのものが間違っていたことになります。深さの一致より重い判定です

5. 測った後どうするか

逆算の道具を用意してあります。測った深さを渡すと、その深さになる接点位置を計算します。

npm run fit:contacts -- 8.4 12.3 4.1

引数の順は「Ring ブレーク開放 / Tip ブレーク開放 / Sleeve 接点が Tip に触れ始める」の深さ（mm）です。

出力されるもの:

  • 逆算した軸位置と、現モデルからのずれ
  • 合わせていない残りの切り替わりが、その軸位置ならどうなるか

最後のが大事です。合わせるのは各接点につき1点だけにしてあります。 全部を合わせにいくと「合って当然」になり、検証したことになりません。 1点で合わせて、残りが当たるかどうかを見る。それがモデルを試すということです。

引数なしで実行すると自己検査になります（モデル自身の予測を入れて元の軸位置を復元できるか）。 現状の復元誤差は 0.0000 mm です。道具そのものは正しく動いています。

npm run fit:contacts

反映の手順

  1. 実測値を docs/measurements/2026-XX-XX.md として記録（生データ・3回分・気温も）
  2. npm run fit:contacts -- ... で逆算
  3. 判定表に従って src/data/dimensions.json を更新
  4. npm run test と npm run artifacts を回し、予測がどう変わったか差分で確認
  5. UNKNOWNS.md §3 の該当項目を「解決済み」に移し、実測日と方法を書く
  6. TEST_RESULTS.md に実測の節を足す

§1-1（ノギス）だけは経路が違います。 逆算は要りません。

  1. plug.bodyRadius と plug.insulatorRadius の value を実測値へ、tolerance を 実測のばらつき（3 回測った幅）へ置き換える
  2. npm run sensitivity を流し直す（15 分）。この 2 つの tolerance が振り幅の正本なので、 公差の箱と最悪コーナーが自動で実測ベースに変わります
  3. SENSITIVITY.md §6-1、UNKNOWNS.md §4-1b、 ASSUMPTIONS.md A-2、REPORT.md §2-3 の数字を差し替える
  4. plug.insulatorRadius の grade を DERIVED → FACT（実測）へ上げ、 SOURCES.md §5 に実測日と方法を追記する

6. この実験で分からないこと

正直に書いておきます。

  • 接点ばねの形そのもの（板厚・梁の長さ・曲げ方）は分かりません。分かるのは 「どの深さで切り替わるか」から逆算した接触点の軸位置だけです。 形を知るには切断するしかありません（だから予備を買う）
  • 押付力（N） は測れません。ばね定数は依然として仮定のままです
  • 接触抵抗の絶対値 は、この方法では意味のある精度で出ません。 導通ブザーが鳴るかどうかしか見ていないためです
  • 4極（TRRS）側の仮定 は、この実験では一切検証されません。別部品が必要です
  • 接触ドームの追従量そのもの（0.05 mm と仮定）は測れません。決着実験で分かるのは 「0.118 mm より小さいかどうか」だけで、その中のどこかは決まりません

つまりこの実験で ASSUMPTION から降ろせるのは「接点の軸位置3つ」と、 間接的に「プラグ外形の解釈」です。37件の仮定のうち片付くのは数件で、 残りは残ります。それでも、一番効く数件です。

  • 生の読みをそのままください。平均や補正はこちらで行います（docs/measurements/TEMPLATE.md）。

  • 器具の分解能と、測った個体のロットが分かれば添えてください。
  • §1-1 だけ、1 回だけでも構いません。
