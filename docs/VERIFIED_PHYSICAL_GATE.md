# `verifiedPhysical` の合格条件（条文 v1）

> この文書の HTML 版（同名 `.html`）は `npm run docs:html` で生成しています。**HTML を直接編集しないでください。**

作成 2026-08-06 ／ 条文 v1 ／ 実装 `scripts/measurementGate.mjs` ／ 台帳 `docs/measurements/measurement-records.v1.json`

## なぜ要るのか

配布 profile の `modelLimitations.verifiedPhysical` は、**2026-08-06 まで生成器のリテラル `false`** でした。
schema の説明はこう書いてあるだけです。

> 実物と突き合わせて検証済みか。未実測の profile では必ず false。**true にできるのは実測記録が伴う場合のみ**

**何を何点測れば足りるのかが、どこにも書いてありませんでした。**
つまり実態は「**誰かがリテラルを書き換えたら `true`**」で、それは検証ではありません。

この条文は、その 1 行を**記録から機械で決まる値**に変えるためのものです。

> **急ぐ話ではありません。**実測は募集していますが必須にしていません（`docs/VERIFICATION_PLAN.md` 冒頭）。
> **記録が 0 件なら `false` のままで、それが正しい状態です。**
> 条文を先に書くのは、**記録が来た日に判断が要らないようにする**ためです。
> 判断が要る形にしておくと、たいてい甘い方へ倒れます。

---

## 第1条（何を主張するか）

`verifiedPhysical: true` は、**その profile の必須観測点がすべて実測で裏付けられた**ことだけを言う。

**「この profile のすべての値が実測である」とは言わない。**
現に TRS profile の `evidenceGrade` は `ASSUMPTION` が 93 件、TRRS は 151 件ある（2026-08-05 実測）。
必須観測点が全部埋まっても、この数は 0 にならない。

**「モデルと実物が一致した」を含む。**単に「突き合わせた」ではない。
実測が予測から離れていたら、**モデルのほうを直してから**でなければ `true` にならない（→ 第4条）。

## 第2条（必須観測点）

profile ごとに、必須観測点を名指しで決める。`scripts/measurementGate.mjs` の `REQUIRED_FOR_PROFILE` が正本。

| profile | 必須観測点 |
|---|---|
| `TRS\|JACK-TRS` | `RING_BREAK_OPEN_DEPTH_MM` ／ `TIP_BREAK_OPEN_DEPTH_MM` |
| `TRS\|JACK-TRRS` | `L_FIRST_CONTACT_SHOULDER_GAP_MM` |

**必須観測点が定義されていない profile は、必ず `false` になる。**
「必須が 0 件だから全部満たしている」で `true` にすると、
**profile を 1 本足しただけで検証済みを名乗れてしまう。**空集合は合格にしない。

> **`TRS|JACK-TRRS` の必須観測点は、別の variant（`TRRS-CTIA|JACK-TRRS`）の量です。**
> 4極ジャックの接点位置を決める測定なので、3極プラグを挿した profile の event 列には現れません。
> 生成器がその variant を別に評価して予測を渡します。**渡されなければ満たせません。**

## 第3条（記録が有効であるための条件）

次を**すべて**満たす記録だけを数える。1 つでも欠ければ、その記録は使わない。

| | 条件 | なぜ |
|---|---|---|
| a | `observation` が条文に定義されている | 定義していない量を根拠にしない |
| b | `variantId` が観測点の定義と一致する | 別の組み合わせで測った値を混ぜない |
| c | **生値が 3 回以上**ある（平均だけの記録は受け取らない） | ばらつきが見えないと、その値の信用度が誰にも分からない |
| d | 測定器の**分解能**が書かれている | c のばらつきが許容内かを判断できない |
| e | **ばらつき（3 回の最大−最小）が許容以内** | → 第5条 |
| f | 測った人・測定日・ジャックとプラグの型番がある | 誰の記録かを追えるようにする |
| g | `retracted: true` でない | 取り下げた記録は消さずに残す。消すと、一度 `true` になっていた事実が追えない |

## 第4条（一致の判定）

有効な記録の**平均**と、**そのとき生成器が計算した現行モデルの予測**の差が、
許容以内であることを求める。

```
|平均(生値) − 現行モデルの予測| ≤ その観測点の許容
```

**予測は artifact から引かない。生成器がその場で計算した値を使う。**
artifact から引くと、モデルを直したのに古い予測と照合し続けることが起きる。

**差が許容を超えたら `false` になる。**そのとき直すのは記録ではなく**モデル**である。
記録のほうを合わせにいったら、この条文は意味を失う。

## 第5条（許容の決め方）

許容は、**その観測点で見分けたい差の 1/5** を基準に置く。

| 観測点 | 見分けたい差 | 許容 |
|---|---:|---:|
| `L_FIRST_CONTACT_SHOULDER_GAP_MM` | **1.45 mm**（本モデル 2.14 mm ↔ 実在部品 PS000001 由来 0.69 mm） | **0.29 mm** |
| `RING_BREAK_OPEN_DEPTH_MM` | 約 1.5 mm | 0.3 mm |
| `TIP_BREAK_OPEN_DEPTH_MM` | 約 1.5 mm | 0.3 mm |

**判定に効かない桁を要求しない。**`L` はデジタルノギスの分解能 0.01 mm の **145 倍**の差を見る測定で、
0.1 mm 単位で読んでも 14.5 倍ある。ここで 0.02 mm の一致を求めると、
**測ってもらったのに弾く**ことになる。

## 第6条（台帳と profile がずれないようにする）

台帳は `inputDigest` に**入れていない**。**理由を書いておく。**

`docs/measurements/measurement-records.v1.json` を共通入力に足すと、
**記録が 1 件も無い今の時点で、全 artifact の ID が動く。**
中身が変わっていないのに ID が変わる状態を自分から作ることになる
（`source-input-scope.v1.json` の `commonInputsNote` が避けている問題と同じ型）。

代わりに、**profile 自身に判定の結果を書き込む**。

```
modelLimitations.verifiedPhysical        判定結果
modelLimitations.physicalVerificationRef 台帳のパスと sha256・条文の版・満たした観測点・欠けている観測点
```

そのうえで `npm run validate:profiles` の semantic 規則 `measurementRecords` が、
**現在の台帳から判定をやり直して、profile に書いてある値と突き合わせる。**
台帳だけ書き換えて profile を作り直さなければ、そこで落ちる。

> **`inputDigest` に入れるほうが素直ではあります。**記録が実際に入って
> `verifiedPhysical` が動くようになったら、そのタイミングで入れ直すのが筋です。
> **いまは入れない理由が「空だから」なので、空でなくなったら理由も消えます。**

## 第7条（この条文の限界）

- **必須観測点の選び方そのものは、この条文では正当化していない。**
  「看板の結論に効く」という判断で選んでいて、**別の選び方もありうる。**
- **1 人が 1 個の部品を 3 回測った記録**で `true` になる。
  個体差・ロット差は見ていない。**複数個体を要求していない。**
- 予測と一致したことは示せるが、**一致した理由がモデルの正しさとは限らない**
  （たまたま合うパラメータ組み合わせが他にもありうる）。
- **`true` になっても、`evidenceGrade` は動かない。**測った値を置く区分が
  `FACT / DERIVED / ASSUMPTION / UNKNOWN` の中に無いためで、これは別途の課題である
  （区分を足すのは `enum` 追加＝`BUMP` で profile v4 になる → `docs/V060_PLAN_20260805.md` §1-2）。

**「起きない」とは書かない。**この条文で言えるのは
**「いま定義した観測点については、記録が無ければ `true` にならない」まで**である。
