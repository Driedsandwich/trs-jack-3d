感度解析 — どの結論が揺れないか

この文書の HTML 版（同名 .html）は npm run docs:html で生成しています。HTML を直接編集しないでください。

作成 2026-08-01 ／ 再現コマンド npm run sensitivity（15 分ほどかかります）／ 生データ artifacts/sensitivity.json

このプロジェクトは実物と突き合わせていません（VERIFICATION_PLAN.md）。 その状態で「11.76 mm で橋絡する」と単一の数字を出すのは、意味が強すぎます。

そこで、仮定として置いたパラメータを成立範囲いっぱいに振り、 何が不変で何が動くかを機械的に測りました。 結論は「仕組みは揺れない、深さの数字は揺れる」です。

## この文書は一度書き直しています

初版（2026-08-01 午前）には手法上の欠陥が 4 つあり、独立した反証ですべて指摘されました。

結論そのものは破れませんでしたが、根拠の強さを実際より強く書いていました。

何がどう間違っていたかは §7 に残します。読み飛ばさないでください。

1. 測り方

走査で測らない

しきい値は二分法で求めています。深さを一定刻みで走査して「どこかで橋絡したか」を見る方法は、 刻みが答えを変えてしまうので使えません。橋絡の窓はしきい値の近くで幾らでも狭くなるからです。

実際、基準構成の橋絡開始は走査刻みでこう動きます。

走査刻み出てくる値
0.02 mm11.78 mm
0.01 mm11.77 mm
0.005 mm11.765 mm
二分法（真値）11.760 mm

初版はこのうち 0.01 mm 刻みの 11.77 を「基準値」として公表していました。

単調でない量に二分法を使わない

ただし二分法だけでも足りません。橋絡もブレーク接点も、深さに対して単調ではありません。 Ring 側ブレーク接点は 8.05 で開く → 9.43 で閉じる → 11.23 で再び開く と動きます。 いきなり二分法をかけると、最初の遷移ではなく最後の遷移を拾ってしまいます。

そこで、粗い走査（0.002 mm）で最初の窓を挟み込んでから、その区間だけを二分法で詰めています。

振り幅は台帳から読む

公差を振る幅（§6-1 の箱）は、dimensions.json から読んでいます。

キー欄値由来
plug.bodyRadiustolerance±0.025図面記載 φ3.5±0.05 の半径換算
plug.insulatorRadiussweepRange1.60〜1.61図面実測 φ3.20〜3.22 の半径換算

解析スクリプトに数値を直書きしていません。 直書きすると、台帳を直したときに 解析だけが古い幅のまま残るためです。実物を測って台帳を更新したら、 npm run sensitivity を流し直すだけで箱も最悪コーナーも追随します。

欄が 2 種類あるのは、tolerance が左右対称の公差しか表せないためです。 絶縁帯の幅は実測が片側にだけ散っている（1.60〜1.61）ので、tolerance: 0.01 と書くと 画面に「1.6 ±0.01」と出て、測っていない下側 1.59 まで測ったことになってしまいます。 非対称な幅は sweepRange に分けました。

2026-08-01 の追加時点では、この 2 つはスクリプト側の直書きでした。

plug.bodyRadius に tolerance 欄が無く（注記の文中に「ø3.5±0.05」とあるだけ）、

plug.insulatorRadius に至っては幅がどこにも構造化されていませんでした。

台帳が持つべき情報を解析側が抱えていたので、台帳へ移しました。

2. 揺れない結論（3極）

2-1. Tip 導体を含む橋絡は起きない

これがこのプロジェクトの中心的な主張です。

接点はパッド内で一番高い面に乗って押し開かれ、そこから compliance だけ低い面までしか届きません。 Tip 面（1.600）に届く条件は 1.600 ≥ 1.750 − compliance、つまり compliance ≥ 0.150。 パッド幅にも接点位置にも依存しません。

確認結果
段差未満の 内側 864 通り（compliance 0.001〜0.1499 × 接点位置 × パッド幅）Tip 橋絡 0 件
Tip 橋絡が始まる compliance（二分法）0.153752 mm
採用値 0.05 との比しきい値の約 1/3.1

0.153752 という値は、段差 0.150 に「導通とみなす最小重なりを Tip 後端の斜面の上で確保する分」が 足されたものです。したがって model.conduction.minOverlap に依存します。

minOverlapTip 橋絡のしきい値
0.0010.150375
0.0050.151876
0.01（採用）0.153752
0.020.157503
0.050.168758

床である 0.150 のほうは minOverlap に依らず一定です。ここが結論の土台です。

ただし土台は FACT だけでできていません。 §6-1 を必ず読んでください。

2-2. 橋絡するのは Ring↔Sleeve だけ

段差未満のどの構成でも、観測された橋絡は RING+SLEEVE のみでした。

2-3. 橋絡の深さを動かすのは帰線接点だけ

Tip 接点・Ring 接点の位置とパッド幅を成立範囲いっぱいに振っても、橋絡の深さは動きません。

ただしこれは幾何の発見というより実装の帰結です。evaluateContact は接点を 1 本ずつ 独立に評価するので、Tip / Ring のパラメータが帰線接点の計算に届く経路がありません。

非自明なのはむしろこちらです: Ring 接点が橋絡できる構成は存在しますが、 そのすべてで完全挿入が壊れます（狙い撃ちで探した 114 構成すべてが結線不成立）。

3. 揺れる数字（3極）

3-1. 橋絡が始まる深さ

帰線接点の 2 パラメータ（軸位置 0.45〜4.55、パッド幅 0.01〜5.00）を同時に振り、 完全挿入が成立する構成だけを集計しました。

2 つ同時に振る（869 構成）6.96〜13.14 mm
片方ずつ振る（OAT）9.01〜13.11 mm

初版は下の行（OAT の合併）を「現実的な幅」として公表していました。 2 つを同時に振ると、下側に 2 mm 広がります。

3-2. Ring 側ブレーク接点が開く深さ

初版は接点位置とパッド幅だけを振っていましたが、この深さを直接決めるのは ブレーク接点のしきい値そのもの（jack.break.ring.openDeflection、ASSUMPTION 0.05）です。

3-3. 橋絡そのものを消せるパラメータ

model.conduction.minOverlap（ASSUMPTION 0.01）は、初版で一度も振っていませんでした。 しきい値の式に自分で書いておきながらです。

橋絡の成立条件は パッド幅 > プラトー間隔 + 2 × minOverlap なので、 (0.9 − 0.7) / 2 = 0.100 でちょうど消えます。採用値との余裕は 10 倍です。

4. 4極（TRRS）

4極ジャックの接点位置は一次図面が無く全面的に仮定です。それでも不変条件が取れます。 3極で効いた論法が、ジャック側の仮定ではなくプラグ側の寸法から出ているためです。

4-1. 同一半径プラトーの間隔は 2 つとも 0.700

4極プラグは半径 1.750 の平坦面を 3 本（Ring1 / Ring2 / Sleeve）持ち、 その間隔は 2 か所、どちらも 0.700 mm です。図面記載の絶縁帯幅 0.7 と一致します。 接点位置とは無関係に決まります。

4-2. Tip を含む橋絡は起きない

根拠は 3極と同一（Tip の最大半径 1.600 が他の 3 本 1.750 より 0.15 mm 低い）で、 やはりパッド幅にも接点位置にも依存しません。§6-1 の限界も同じくかかります。

4-3. 橋絡するかどうかはパッド幅だけで決まる

各接点について、最も橋絡しやすい深さでパッド幅の下限を二分法で求めました。

接点接点位置橋絡し始めるパッド幅
Ring2 接点3.45 / 4.0 / 4.35 / 5.25 / 5.85すべて 0.720
帰線接点0.45 / 1.25 / 2.05 / 2.85すべて 0.720

0.720 は プラトー間隔 0.700 + 導通の最小重なり 0.01 × 2 そのものです。

採用値は狭パッド 0.5（< 0.720 なので橋絡しない）、帰線パッド 0.9（> 0.720 なので橋絡する）。 この大小関係だけで 4極ジャックの橋絡の有無が決まっています。

位置に依存しないのは、成立範囲の内側に限ります。

「パッド中心が絶縁帯の中心に来る深さ」が完全挿入 14 mm を超える位置では、

到達できる最も深い位置で評価するしかなく、しきい値は位置とともに増えます

（Ring2 接点なら位置 6.0 で 1.02、6.5 で 2.02）。

上の表の位置はすべて成立範囲の内側なので、そこでは 0.720 で一定です。

4-4. 各接点がまたげる絶縁帯は決まっている

「完全挿入でパッド全幅が自分の導体に収まる」という制約は、完全挿入が最も深い位置なので、 「パッドは自分の導体の奥端を越えられない」ことを意味します。 一方、挿入の過程では接点は先端から自分の最終位置まですべてを通過します。

したがって各接点がまたげるのは、自分の導体より先端側にある絶縁帯のすべてです。

Tip 0–4.8 │ INS1 │ Ring1 5.5–7.8 │ INSM │ Ring2 8.5–10.8 │ INS2 │ Sleeve 11.5–14.0
            Tip が低い→不可        同じ高さ→可          同じ高さ→可

  Tip 接点   … またげる絶縁帯なし        → 橋絡しない
  Ring1 接点 … INS1 のみ                 → 橋絡しない（Tip が低い）
  Ring2 接点 … INS1, INSM                → INSM で橋絡しうる
  帰線接点   … INS1, INSM, INS2          → INSM と INS2 で橋絡しうる

同時振りで観測された組み合わせはこの表と一致し、 自分の導体より奥の絶縁帯をまたいだ例は 1 件もありませんでした。

4-5. 混挿（3極プラグ × 4極ジャック）

Ring2 接点の軸位置を成立範囲いっぱいに 41 分割して振ると、完全挿入での行き先は 41 通り中 40 通りで 3極プラグの Sleeve（＝帰線が正しくつながる）でした。 範囲のちょうど端 1 点だけが絶縁帯に乗ります。

5. 読み方

README や REPORT に載せている深さの数字は、帰線接点の位置とパッド幅を 現在の仮定値に固定したときの値です。次の幅を持つと読んでください。

事象既定値幅
Ring↔Sleeve 橋絡が始まる11.76 mm6.96〜13.14 mm
Ring 側ブレーク接点が開く8.05 mm8.00〜12.33 mm（0.4 以上では開かない）
挿入ピーク力5.27 N1.5〜11.2 N（校正係数を固定して。§3-4）

一方、次のことは幅を持ちません。

  • 挿入の途中で、帰線接点がプラグの Tip 導体・Ring 導体の上を順に通過する
  • その過程で、Ring↔Sleeve の橋絡が起きる（ただし minOverlap が 0.10 以上なら起きない）
  • Tip↔Ring の橋絡は起きない（公称寸法のモデルでは。§6-1 参照）
  • ブレーク接点が開くのは、正しい結線が完成するより前である

「何が起きるか」はほぼ決まっていて、「何 mm で起きるか」が決まっていない、という状態です。

6. この解析の限界

6-1. FACT を公差の内側で振っていない ← 最も重い

plug.bodyDiameter は図面記載 φ3.5±0.05 です。この公差の内側で振ると、 Tip 橋絡のしきい値は段差 0.150 を割ります。

プラグ外径Tip 橋絡のしきい値
φ3.45（公差下限）0.128752 ← 0.150 を割る
φ3.4750.141252 ← 0.150 を割る
φ3.50（公称）0.153752
φ3.5250.166252
φ3.55（公差上限）0.178752

つまり 公差の下半分では、compliance を採用値より大きく取れば Tip 橋絡が実際に起きます。

さらに、段差 0.150 は plug.bodyRadius（1.75）− Tip 後端半径（1.60）ですが、 後者の plug.insulatorRadius は DERIVED であって FACT ではありません （出典は図面実測で、注記自身が「図面実測 φ3.20〜3.22」と幅を認めています）。

**初版はここを「図面記載の φ3.20 と φ3.50 という 2 つの FACT から出る幾何的な帰結」と

書いていました。撤回します。** φ3.20 は DERIVED です。

正確には 「公称寸法のモデルでは Tip 橋絡は起きない」であって、

「実物の 3.5 mm プラグでは起きない」ではありません。

採用値 0.05 では最悪コーナーでも Tip 橋絡は起きません。 ただし compliance の採用範囲の上端 0.10（UNKNOWNS.md §3-6）と比べると、 最悪コーナーでの余裕は 1.19 倍しかありません。 公称寸法での 3.08 倍とは、まったく違う強さの主張になります。

では、どこまで薄ければ本当に崩れるのか

上の箱は「図面が許す範囲」ですが、結論が実際に崩れる線はその外側にあります。 段差を薄くしていって、採用値で Tip 橋絡が始まる点を二分法で探しました。

compliance破綻する段差（半径）直径差に直すと
0.05（採用値）0.04500.090 mm
0.10（採用範囲の上端）0.09560.191 mm

公称の直径差は 0.30 mm、図面が許す最悪でも 0.23 mm なので、 破綻線 0.090 mm までは 2.5 倍以上の隔たりがあります。

実物のプラグ外径を測っていないので、どの行にいるのか分かりません。 ノギス 1 本・30 秒で決まるので、 VERIFICATION_PLAN.md §1-1 として独立させ、 LED 回路を使う決着実験（§1-2）より前に置きました （→ UNKNOWNS.md §4-1b）。

6-2. その他

  • 走査で窓を挟み込む段は 0.002 mm 刻みです。これより狭い窓は取りこぼします。
  • 4極は CTIA プラグ × 4極ジャックを主対象にしました。OMTP は形状が完全に同一で 機能割当だけが違うので、幾何の結論はそのまま当てはまります。
  • 力のモデル（force.*）は §3-4 で振りました。ただし振ったのは 8 件で、 calibrationScale は固定しています（純粋な倍率なので同時に振っても情報が増えないため）。 同時振りは 2 水準の全組み合わせなので、内側に非単調な山があれば取りこぼします。
  • jack.contact.*.freeRadius は DERIVED なので振っていません。橋絡の結論には効きませんが、 イベントの深さには効きます。
  • これは実物の検証ではありません。 モデルの内部で、仮定をどう選び直しても 結論が変わらないことを確かめただけです。実物との照合は依然として VERIFICATION_PLAN.md の手順が必要です。

7. 初版の何が間違っていたか

独立した 8 体の検証で、初版の主張 6 件のうち 3 件が反証されました。記録として残します。

#初版の記述何が問題だったか
1「compliance < 0.15 の 729 通りで Tip 橋絡 0 件」同時振りの水準が {0, 0.15, 0.30} だったため、この 729 通りはすべて compliance = 0 の一点。しかも compliance = 0 では Tip 導体に一切導通できず（Tip はプラトーを持たず全域が斜面）、完全挿入すら成立しない退化モデルだった。証拠が空だった。
2「橋絡し始めるパッド幅は 0.721」0.001 刻みの走査で探していたため、真値 0.720 が 1 目盛ぶん過大に出ていた。pad = 0.7205 は「0.721 未満」なのに橋絡する。
3「接点をどこに置いても同じ値」理想深さが完全挿入 14 mm を超える位置では成り立たない。しかもコードは到達できない深さ（14.05〜16.15 mm）で黙って値を返していた。
4「橋絡の深さの幅は 9.0〜13.1 mm」片方ずつ振った結果（OAT）の合併だった。2 つ同時に振ると 6.96〜13.14 mm。
