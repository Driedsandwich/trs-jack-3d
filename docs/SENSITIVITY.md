# 感度解析 — どの結論が揺れないか

> この文書の HTML 版（同名 `.html`）は `npm run docs:html` で生成しています。**HTML を直接編集しないでください。**

作成 2026-08-01 ／ 再現コマンド `npm run sensitivity` ／ 生データ `artifacts/sensitivity.json`

このプロジェクトは**実物と突き合わせていません**（[VERIFICATION_PLAN.md](VERIFICATION_PLAN.md)）。
その状態で「11.77 mm で橋絡する」と単一の数字を出すのは、意味が強すぎます。

そこで、仮定として置いた 7 個のパラメータを**成立範囲いっぱいに振り**、
何が不変で何が動くかを機械的に測りました。
**結論は「仕組みは揺れない、深さの数字は揺れる」です。**

---

## 1. 何を振ったか

| パラメータ | 現在値 | 振った範囲 | 範囲の根拠 |
|---|---:|---|---|
| `jack.contact.tip.axialCenter` | 11.4 | 9.475〜13.400 | 完全挿入でパッド全幅が Tip 導体（0〜4.8）に収まり、かつ端子3（13.4）より前 |
| `jack.contact.ring.axialCenter` | 7.1 | 5.975〜8.225 | 同上、Ring 導体（5.5〜8.3）と端子2（8.9） |
| `jack.contact.sleeve.axialCenter` | 3.2 | 0.450〜4.550 | 同上、Sleeve 導体（9.0〜14.0）と端子1（5.6） |
| `jack.contact.tip.padWidth` | 0.55 | 0.010〜4.800 | 下限＝導通とみなす最小重なり、上限＝Tip 導体の幅 |
| `jack.contact.ring.padWidth` | 0.55 | 0.010〜2.800 | 同上、Ring 導体の幅 |
| `jack.contact.sleeve.padWidth` | 0.90 | 0.010〜5.000 | 同上、Sleeve 導体の幅 |
| `model.contact.complianceMm` | 0.05 | 0.000〜0.300 | **あえて壊れるまで振った**（下記） |

**範囲は勝手に決めていません。** すべて図面の FACT 値（導体境界・端子位置・嵌合長 14.0）と、
「完全挿入で正しく結線されねばならない」という条件から導いています。
導出は [`scripts/sensitivity.ts`](../scripts/sensitivity.ts) の `deriveRanges` にあります。

> **compliance だけは扱いを変えました。** この値の上限を「Tip と Ring の半径差 0.15 mm」に
> すると、「Tip 導体を含む橋絡は起きない」という結論がその上限の**言い換え**になり、
> 検証になりません（循環します）。そこで段差の 2 倍まで振って、
> **どこで壊れるかを実測**しました。

やり方は 2 通りです。

- **一つずつ振る（OAT）** … 各パラメータを 41 段階、他は既定値。7 × 41 = 287 通り
- **同時に振る** … 7 個すべてを 3 水準で総当たり。3⁷ = **2,187 通り**

同時振りをやるのは、OAT だと「一つずつなら平気だが、組み合わせると壊れる」を見逃すためです。
乱数は使っていないので、何度実行しても同じ結果になります。

## 2. 揺れない結論

### 2-1. Tip 導体を含む橋絡は起きない

**これがこのプロジェクトの中心的な主張で、感度解析でも揺れませんでした。**

| 確認 | 結果 |
|---|---|
| OAT（compliance 以外の 6 パラメータ、246 通り） | Tip 橋絡 **0 件** |
| 同時振りのうち compliance < 0.15 mm（**729 通り**） | Tip 橋絡 **0 件** |
| Tip 橋絡が始まる compliance | **0.15375 mm** |

そして 0.15375 という値には意味があります。**Tip 導体の最大半径 1.600 と
Ring / Sleeve の 1.750 の差、ちょうど 0.150 mm の直上**です。

これは偶然ではなく、計算式からそのまま出ます。接点はパッド内で一番高い面
（Ring の 1.750）に押し上げられ、そこから `compliance` だけ低い面までしか届きません。
Tip 面（1.600）に届く条件は `1.600 ≥ 1.750 − compliance`、つまり `compliance ≥ 0.150`。
**パッド幅にも接点位置にも一切依存しません。**

> つまり「第1絶縁帯で橋絡しない」は、**仮定を選んだ結果ではなく、
> 図面記載の φ3.20 と φ3.50 という 2 つの FACT から出る幾何的な帰結**です。
> 採用している compliance 0.05 は、しきい値 0.154 の **1/3** です。

### 2-2. 橋絡するのは Ring↔Sleeve だけ

完全挿入が成立する全構成で、観測された橋絡は **`RING+SLEEVE` のみ**でした
（compliance を 0.15 以上に上げた構成を除く）。

### 2-3. Tip 接点・Ring 接点は橋絡に関与しない

`tip.axialCenter` / `ring.axialCenter` / `tip.padWidth` / `ring.padWidth` の
**4 つをどう振っても、橋絡の深さは 11.77 mm から動きません**（幅 0.00）。

橋絡を起こしているのは帰線（Sleeve）接点だけなので、当然ではありますが、
**「橋絡の数字は帰線接点の仮定だけに依存する」**と言い切れることには意味があります。
不確かさの発生源が 2 つに絞れます。

## 3. 揺れる数字

**橋絡の深さを動かすのは、帰線接点の 2 つのパラメータだけです。**

| パラメータ | 最初の橋絡 | 帰線接点が Tip に触れる | 全部が正常につながる |
|---|---|---|---|
| `sleeve.axialCenter` 0.45〜4.55 | **9.02〜13.12**（幅 4.10） | 1.18〜5.28（幅 4.10） | 12.34〜13.30 |
| `sleeve.padWidth` 0.01〜5.00 | **9.71〜11.84**（幅 2.13） | 1.88〜4.32（幅 2.44） | 12.34〜14.00 |
| `ring.axialCenter` 5.98〜8.23 | 11.77（不変） | 3.93（不変） | 11.96〜13.46 |
| `tip.axialCenter` 9.48〜13.40 | 11.77（不変） | 3.93（不変） | 12.34〜13.76 |
| `ring.padWidth` 0.01〜2.80 | 11.77（不変） | 3.93（不変） | 11.96〜12.58 |
| `tip.padWidth` 0.01〜4.80 | 11.77（不変） | 3.93（不変） | 12.34（不変） |
| `compliance` 0.00〜0.30 | 8.27〜11.77 ※ | 3.93〜4.05 | 12.34〜12.43 |

※ compliance の 8.27 は、0.15 を超えて**偽の Tip 橋絡**が復活した構成の値です。
0.15 未満に限れば 11.77 で不変。

### Ring 側ブレーク接点が開く深さ

`ring.axialCenter` で **6.93〜9.18**（幅 2.25）、`ring.padWidth` で 6.93〜8.29（幅 1.36）動きます。
既定値では 8.06 mm ですが、**この数字は仮定依存です。**

## 4. 読み方

README や REPORT に載せている深さの数字は、**帰線接点の位置とパッド幅を
現在の仮定値に固定したときの値**です。それらは一次資料に無い仮定なので、
数字は次の幅を持つと読んでください。

| 事象 | 既定値 | 現実的な幅 |
|---|---:|---|
| 帰線接点がプラグ Tip に触れ始める | 3.93 mm | **1.2〜5.3 mm** |
| Ring 側ブレーク接点が開く | 8.06 mm | **6.9〜9.2 mm** |
| Ring↔Sleeve 橋絡が始まる | 11.77 mm | **9.0〜13.1 mm** |
| 全接点が正しくつながる | 12.34 mm | **11.96〜14.00 mm** |

一方で、**次のことは幅を持ちません。**

- 挿入の途中で、帰線接点がプラグの Tip 導体・Ring 導体の上を順に通過する
- その過程で、Ring↔Sleeve の橋絡（短絡）が必ず 1 回起きる
- **Tip↔Ring の橋絡は起きない**
- ブレーク接点が開くのは、正しい結線が完成するより前である

**「何が起きるか」は決まっていて、「何 mm で起きるか」が決まっていない**、という状態です。

## 5. この解析の限界

- **3極（TRS）× 3極ジャックだけ**を対象にしました。4極側は接点位置が全面的に仮定なので、
  同じことをやっても「仮定を振ったら仮定の分だけ動いた」以上のことは言えません。
- 同時振りは各パラメータ **3 水準**です。範囲の端と中央しか見ていないので、
  範囲の内側に狭い異常領域があれば見逃します。OAT は 41 段階なので、
  単独パラメータについてはもっと細かく見ています。
- 同時振りの走査刻みは 0.02 mm です。**これより狭い橋絡窓は取りこぼします**
  （既定構成の橋絡窓は 0.17 mm なので、8 点以上に当たります）。
- 2,187 通りのうち完全挿入が成立したのは **308 通り**でした。
  パッド幅を導体幅いっぱいまで広げるなど、端の組み合わせでは結線が壊れるためです。
  上の「揺れる幅」は、**結線が成立する構成だけ**を対象に集計しています。
- **これは実物の検証ではありません。** モデルの内部で、仮定をどう選び直しても
  結論が変わらないことを確かめただけです。実物との照合は依然として
  [VERIFICATION_PLAN.md](VERIFICATION_PLAN.md) の手順が必要です。
